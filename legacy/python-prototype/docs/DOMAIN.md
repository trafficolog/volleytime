# Предметная область

Глоссарий, сущности, их состояния и переходы.

## Глоссарий

- **Игрок** (player) — участник группы, который записывается на тренировки.
- **Админ** (admin) — организатор: создаёт тренировки, ведёт кассу, подтверждает платежи.
- **Тренировка** (training) — событие в зале на конкретную дату и время.
- **Слот** (slot) — место в тренировке. Три типа: `main`, `rotation`, `waitlist`.
- **Запись** (booking) — заявка игрока на тренировку.
- **Абонемент** (subscription) — предоплаченный пакет на N сессий с сроком действия.
- **Платёж** (payment) — финансовая транзакция: разовая оплата записи или покупка абонемента.
- **Касса** (ledger) — журнал доходов и расходов группы.

## Состояния и переходы

### Training

```
   ┌───────────┐
   │  planned  │  ← создана, но регистрация ещё не открыта
   └─────┬─────┘
         │ open_registration
         ▼
   ┌───────────┐
   │   open    │  ← идёт запись
   └─────┬─────┘
         │ booking_window_closed (за N часов до начала)
         ▼
   ┌───────────┐
   │  closed   │  ← запись закрыта, ждём начала
   └─────┬─────┘
         │ training_ended
         ▼
   ┌───────────┐
   │ finished  │  ← прошла, можно отметить посещаемость
   └───────────┘

  В любой момент из open/closed → cancelled (с массовым refund)
```

### Booking

```
                      ┌─────────────────┐
   создание ────────► │ pending_payment │  ← бронь без оплаты
                      └────────┬────────┘
                               │
       payment_succeeded ──────┼─── payment_timeout / user_cancel
                               │              │
                               ▼              ▼
                      ┌────────────┐   ┌──────────┐
                      │ confirmed  │   │cancelled │
                      └─────┬──────┘   └──────────┘
                            │
            training_ended  │
                ┌───────────┼────────────┐
                ▼                        ▼
        ┌───────────┐            ┌──────────┐
        │ attended  │            │ no_show  │
        └───────────┘            └──────────┘
```

### Subscription

```
   ┌──────────┐
   │  active  │
   └────┬─────┘
        │
        ├── used == total ─────► ┌──────────┐
        │                        │ depleted │
        │                        └──────────┘
        ├── now > expires_at ──► ┌──────────┐
        │                        │ expired  │
        │                        └──────────┘
        └── refund_requested ──► ┌──────────┐
                                 │ refunded │
                                 └──────────┘
```

### Payment

```
   ┌──────────┐
   │ pending  │
   └────┬─────┘
        ├── webhook(succeeded) / admin_confirm ─► succeeded
        ├── webhook(failed) / timeout ─────────► failed
        └── refund ────────────────────────────► refunded
```

## Бизнес-правила

### Запись

1. Игрок не может записаться на одну тренировку дважды (уникальный индекс).
2. Запись закрывается за `BOOKING_CLOSES_HOURS_BEFORE` часов до начала (по умолчанию 2).
3. Распределение мест по приоритету: `main` (12) → `rotation` (2) → `waitlist` (∞).
4. При отмене кого-то из main/rotation → первый из waitlist автоматически продвигается (Фаза 4 — с TTL подтверждения).

### Абонемент

1. Срок действия абонемента — индивидуальный для плана (см. таблицу ниже).
2. Списание сессии происходит в момент **подтверждения** записи.
3. Если запись отменяется в срок «бесплатной отмены» (за 24 ч и более) → возврат сессии в абонемент.
4. При нескольких активных абонементах списание идёт с самого ближайшего к истечению (FIFO по `expires_at`).

#### Планы абонементов (по умолчанию)

| Код | Сессий | Цена | За тренировку | Срок |
|-----|--------|------|---------------|------|
| `4x` | 4 | 56 BYN | 14 BYN | 35 дней |
| `8x` | 8 | 104 BYN | 13 BYN | 60 дней |
| `12x` | 12 | 144 BYN | 12 BYN | 90 дней |

Базовая разовая цена: 15 BYN. То есть скидка от 1 до 3 BYN за тренировку.

### Оплата

1. Все суммы в `BYN`, хранятся как `Decimal(10, 2)`.
2. Разовая оплата идёт за конкретную тренировку. Абонемент идёт сам по себе.
3. Возврат при отмене тренировки админом — полный.
4. Возврат при отмене игроком: за 24 ч и более — возврат полный, менее — без возврата.

### Касса

1. Каждое успешное поступление → автоматическая запись в `LedgerEntry` с типом `income`.
2. Расходы вводятся админом вручную (категории: `rent` / `balls` / `refund` / `other`) с прикреплением фото чека.
3. Баланс на дату = сумма income − сумма expense за всё время до этой даты.

## Ценовая модель (под текущий кейс)

Решение пользователя: **все 14 мест по одной цене**.

В модели заложены два поля (`price_main`, `price_rotation`) на случай, если правила изменятся. При создании тренировки они заполняются одинаковыми значениями.

Пример экономики на одну тренировку:
- Цена с человека: 15 BYN
- Аренда зала: 100 BYN
- Полная заполняемость (14 чел): 14 × 15 = 210 BYN
- В кассу после аренды: 210 − 100 = 110 BYN
