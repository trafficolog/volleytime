# Сессия 2026-05-25: подробное описание Phase 3 и Phase 4

## Цели

Оператор попросил расписать Phase 3 (bePaid) и Phase 4 (scheduler) полностью, чтобы можно было продолжить разработку в IDE без возвращения к чату для уточнений.

## Контекст

После Phase 2 wrap-up Phase 3 и 4 существовали только как болванки (frontmatter + "TODO: описать"). Не хватало:
- предусловий и DoD на уровне фаз
- описаний эпиков (что они делают, что не делают)
- содержательных карточек задач (цель, контекст, deliverables, критерии, подсказки)

## Ход работы

### Шаг 1. Расширенные phase-карточки

`docs/phases/3-bepaid-integration.md`:
- Подробные предусловия (Трек A, подключение bePaid, инфраструктура)
- Чёткие DoD (cargo, ЕРИП, идемпотентность, refund, security)
- Технические заметки: архитектура, сервис, webhook, безопасность, тестовая среда

`docs/phases/4-reminders-and-automation.md`:
- Прозрачное «можно параллельно с Phase 3»
- Стек: APScheduler 3.10.4, AsyncIOScheduler, SQLAlchemyJobStore
- Принципы: идемпотентность, привязка к сущности, catchup, misfire
- Что не делаем в этой фазе (Phase 5-плюс)

### Шаг 2. Эпики

Для каждого эпика — Цель, Контекст, DoD, таблица задач, «Не делать»:

**Phase 3:**
- 3.1 Сервис bePaid
- 3.2 Приём и обработка webhook
- 3.3 UX оплаты
- 3.4 Безопасность
- 3.5 Тесты Phase 3

**Phase 4:**
- 4.1 APScheduler infrastructure
- 4.2 Напоминания
- 4.3 Автоматические переходы статусов
- 4.4 Тесты Phase 4

### Шаг 3. Подробные задачи

Все 23 задачи (15 Phase 3 + 8 Phase 4) получили:
- frontmatter с `roles`, `depends_on`, `estimated_hours`, `tags`
- Цель (одно-два предложения)
- Контекст (что есть, на что опираемся)
- Deliverables (конкретные артефакты)
- Критерии приёмки (измеримые)
- Подсказки (gotchas, references)
- «Не делать» (защита от scope creep)

Особое внимание уделил:
- **Task 3.1.1 (BePaidClient)** — конкретный API endpoint, retry-стратегия, redaction.
- **Task 3.2.2 (Idempotency)** — 4 граничных случая: дубль, разные uid для одного payment, неизвестный tracking_id, amount mismatch.
- **Task 3.4.3 (Log redaction)** — список запрещённых ключей, регекспы PAN, тест-кейсы.
- **Task 4.1.2 (Register jobs on training create)** — job_id schema, привязка к сущности, обработка отмены.
- **Task 4.3.2 (Waitlist promotion with TTL)** — изменение существующей логики `BookingService.promote_from_waitlist`.
- **Task 4.4.1 (Tests scheduler jobs)** — конкретные 7 тест-кейсов, freezegun caveats.

### Шаг 4. Регенерация status-файлов

`current-state.md`, `drift-report.md`, `phases.md`, `epics.md`, `tasks.md` — пересобраны из обновлённых frontmatter. Drift report теперь корректно показывает все 46 todo-задач с группировкой по фазам.
