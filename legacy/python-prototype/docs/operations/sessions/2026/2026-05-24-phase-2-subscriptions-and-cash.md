# Сессия 2026-05-24: Phase 2 — абонементы и ручная оплата

## Цели

После завершения Phase 1 — собрать рабочий бот без bePaid, чтобы можно было запустить в группе уже сейчас.

## Контекст

Phase 1 закрыта. Параллельно с этой сессией — оператор готовит обращение в МНС (Трек A).

## Ход работы

### Шаг 1. Сервисы

- `services/subscription.py`: планы 4x/8x/12x с ценами, FIFO-выбор для списания, атомарное consume через WHERE-условие.
- `services/ledger.py`: income, expense, balance на дату, история.
- `services/payments.py`: координатор — confirm активирует подписку или подтверждает бронь и пишет в кассу.
- `services/notifier.py`: обёртка для отправки сообщений по telegram_id (для уведомлений админам).

### Шаг 2. Расширение клавиатур

- payment_method_choice (с абонемента / наличными)
- subscription_plans, subscription_payment_method
- admin_menu расширен: «Ожидают оплаты», «Касса», «Добавить расход»
- payment_confirm_actions для админа

### Шаг 3. Хендлеры

- `handlers/player/subscriptions.py`: меню «Мои», «Купить», выбор плана, оплата cash.
- `handlers/player/my_bookings.py`: «Мои записи» с фильтром «будущие».
- `handlers/player/trainings.py` — переписан под выбор способа оплаты.
- `handlers/admin/payments.py`: список pending, view, confirm, reject.
- `handlers/admin/ledger.py`: касса + FSM ввода расхода.

### Шаг 4. NotifierMiddleware

Добавлен middleware, который кладёт `Notifier(bot)` в data → доступен во всех хендлерах.
