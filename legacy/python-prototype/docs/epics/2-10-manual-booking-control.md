# Epic 2.10: Ручное управление записями

**Цель.** Админ может управлять любой Booking: записать игрока сам (за него), снять чужую запись, переместить из waitlist в основной состав, перенести на другую тренировку.

## Контекст

Реальные сценарии:
- «Петя написал в группе, что хочет на тренировку, но не может зайти в бот».
- «Маша записалась случайно дважды через разные устройства» (хотя unique-индекс не даст, но бывают edge cases).
- «У нас сегодня внезапно освободилось место и я хочу взять конкретного из waitlist».
- «Я перенёс игроков с отменённой тренировки на следующую».

## Definition of Done

- В карточке игрока (Epic 2.8) — кнопка «➕ Записать на тренировку»: показывает список ближайших → admin выбирает → бот создаёт Booking, применяя обычную логику slot/payment
- В карточке тренировки (Epic 2.9) — кнопка «➕ Добавить игрока»: показывает список зарегистрированных пользователей с поиском
- В карточке Booking (новая кнопка через клик по имени в составе) — кнопки «🚫 Снять запись», «↗️ Переместить в main/rotation», «📅 Перенести на другую тренировку»
- При ручной записи: вопрос «Игрок будет оплачивать наличными или у него есть абонемент?» (как обычный flow)
- При снятии чужой брони админом — обязательное поле «причина» (свободный текст), пишется в AdminLog
- При переносе из waitlist — обходит TTL (Phase 4) и сразу `confirmed`
- При переносе между тренировками — копируется payment_id если был, либо создаётся новый pending
