# Epic 2.13: CRUD планов абонементов

**Цель.** Перенести планы абонементов из захардкоженных констант в БД, добавить UI для управления: создать, изменить цену/срок/количество сессий, деактивировать.

## Контекст

Сейчас планы (`SubscriptionPlan` в `services/subscription.py`) — это Python-константы. Чтобы поднять цену с 1 июня — нужно править код и делать деплой. Это блокирует Phase 6 (CI/CD) и сильно неудобно.

Решение: новая таблица `subscription_plans` в БД. При запуске бота первый раз — заполняется дефолтными планами (миграция). Дальше — управление через UI.

Существующие купленные абонементы при изменении цены **не пересчитываются** — у них своя зафиксированная цена в `Subscription.price`.

## Definition of Done

- Новая модель `SubscriptionPlan` в `src/db/models.py` с полями: code, title, total_sessions, price, valid_days, is_active, created_at, updated_at
- При первом запуске бота — заполняется тремя дефолтными планами (4x/8x/12x) из существующих констант
- `SubscriptionService` использует БД-планы вместо констант
- В admin_menu — кнопка «🎫 Планы абонементов»
- Список планов с пометкой active/inactive
- Создание нового плана: FSM «код → название → сессий → цена → срок»
- Редактирование: «изменить цену», «изменить срок», «изменить название»
- Деактивация: план остаётся в БД (купленные абонементы продолжают работать), но не показывается пользователям при покупке
- Защита: нельзя удалить или деактивировать план, у которого есть активные подписки (только когда все истекут/исчерпают)
- Все операции в AdminLog
