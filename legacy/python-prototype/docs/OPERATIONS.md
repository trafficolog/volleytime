# Эксплуатация

Что делать после того, как бот работает в проде.

## Регулярные операции

### Ежедневно (автоматически)
- Бэкап БД (cron).
- Ротация логов (`logrotate`).

### Еженедельно (ручная проверка)
- Открыть Sentry: были ли необработанные ошибки?
- Открыть UptimeRobot: были ли даунтаймы?
- Сверить остаток в кассе с фактическим балансом карты.

### Ежемесячно
- Скачать CSV-экспорт кассы за месяц (для НПД-декларации).
- Проверить актуальность зависимостей: `pip list --outdated`.
- Очистить старые бэкапы (> 90 дней).

## Подача декларации НПД

Если выбран режим самозанятости:
- Налог считается автоматически приложением «НПД».
- Каждое поступление надо вручную ввести в приложение.
- Альтернатива: интеграция с банком, если они её поддерживают.

В Фазе 5 будет добавлена кнопка «Экспорт для НПД» в админ-меню.

## Восстановление после сбоя

### Сбой бота
```bash
docker-compose ps
docker-compose logs --tail=200 bot
docker-compose restart bot
```

### Сбой БД
```bash
docker-compose logs postgres
df -h  # проверить диск
# Восстановление:
gunzip < /backups/volley-LATEST.sql.gz | docker exec -i pg psql -U volley volley
```

### Скомпрометирован SECRET_KEY bePaid
1. Зайти в кабинет bePaid, выпустить новый ключ.
2. Обновить `.env` на сервере.
3. `docker-compose restart bot`.

## Мониторинг

| Метрика | Норма | Тревога |
|---------|-------|---------|
| Uptime бота | > 99% / месяц | < 95% |
| Время ответа webhook'а bePaid | < 500 мс | > 2 сек |
| Свободное место на диске | > 20% | < 10% |
| Размер БД | < 100 МБ | > 1 ГБ |
| Ошибок в Sentry / день | 0–5 | > 20 |

### Healthcheck

`GET /health` возвращает:
- `200 OK` если БД доступна и schema актуальна;
- `500` иначе.

## Поддержка пользователей

### Типичные обращения

1. **«Я оплатил, но не вижу записи».**
   - Проверить `Payment` по `user_id` за последние сутки.
   - Если `pending` — webhook bePaid не дошёл. Проверить логи.
   - Если `succeeded`, но Booking в `pending_payment` — баг. Подтвердить вручную.

2. **«У меня списали с абонемента, хотя я не записывался».**
   - Открыть историю `Booking`. Найти запись со ссылкой на subscription.
   - Если ошибка — отменить запись, вернуть сессию.

3. **«Хочу вернуть деньги за абонемент».**
   - По оферте: возврат пропорционально неиспользованным сессиям.
   - Через bePaid: POST `/transactions/{uid}/refunds`.
   - В кассу: `LedgerEntry(type=expense, category=refund)`.

## Юридические аспекты

### Персональные данные

Бот хранит: Telegram ID, имя, username, иногда телефон. Это **персональные данные** по закону РБ.

- Оферта должна явно описывать сбор данных.
- Пользователь может запросить удаление (`/delete_me` в Фазе 5).
- Не передавать третьим лицам.

### Хранение чеков
По НК РБ — 5 лет. Удобно: ежемесячный архив CSV + PDF чеков в Google Drive.

### Налоговая проверка

Что покажете:
1. Регистрацию НПД / ИП.
2. Реестр поступлений (выгрузка из бота).
3. Подтверждённую оплату налога.
4. Расходные документы.

## Безопасность

### Что не должно попасть в Git
- `.env`
- `bepaid_public_key.pem`
- `*.db`, `*.sqlite`
- Любые секреты в комментариях

### Ротация секретов
- BOT_TOKEN: при подозрении на утечку — у BotFather `/revoke`.
- BEPAID_SECRET_KEY: раз в год.

### SSH-доступ
- Только по ключу.
- fail2ban.
- Регулярные `apt update && apt upgrade`.
