# Phase 4: Напоминания и автоматизация

**Цель.** Бот сам уведомляет игроков, закрывает записи, продвигает waitlist. Минимум ручных действий админа.

## Контекст

После запуска в реальной группе (CP-2) обычно выявляется, что много операций требуют ручного «пинка»: напомнить за день, переместить из waitlist, закрыть запись за пару часов до начала. Эта фаза автоматизирует всё это через APScheduler.

**Можно делать параллельно с Phase 3.** Фаза не зависит от bePaid: напоминания работают одинаково и для cash-, и для card-платежей.

## Предусловия

- ✅ Phase 1 завершена
- ✅ Phase 2 завершена
- 🔵 Phase 3 не обязательна (но в задаче 4.3.1 учитываем существующие методы платежа из Phase 2 + Phase 3)

## Definition of Done

- Все участники с `BookingStatus.confirmed` получают напоминание за 24 ч до тренировки
- Все участники получают напоминание за 2 ч + админ уведомлён о закрытии записи
- Если игрок не оплатил за 15 мин — `Booking.status → cancelled`, слот освобождается, первый из waitlist получает уведомление
- Из waitlist первый получает уведомление о свободном месте с TTL 30 мин на подтверждение
- Прошедшие тренировки автоматически переходят в `finished` через 30 минут после окончания
- Задачи планировщика **переживают рестарт бота** (persistent jobstore)
- При отмене тренировки админом — все связанные задачи отменяются (не приходят «фантомные» напоминания)

## Технические заметки

### Стек

- **APScheduler 3.10.4** (уже в requirements.txt)
- **AsyncIOScheduler** — работает в том же event loop, что и aiogram
- **SQLAlchemyJobStore** — задачи хранятся в той же БД, что и доменные сущности

### Принципы

1. **Идемпотентность.** Каждая задача может выполниться повторно без побочных эффектов. Например, «отправить напоминание за 24 ч» проверяет в БД, что напоминание ещё не было отправлено (флаг или таблица истории).
2. **Привязка к сущности.** ID задачи строится по схеме `reminder_24h_training_<id>` → можно найти, отменить, заменить.
3. **Регистрация при создании / отмена при отмене.** Когда админ создаёт тренировку, регистрируются все её задачи. При отмене тренировки — все задачи снимаются.
4. **Catchup window.** Если бот был выключен в момент срабатывания — задача всё равно выполняется при следующем запуске (в пределах разумного окна, например 1 час). Иначе пропускается.
5. **Misfire handling.** Использовать `misfire_grace_time` для устойчивости.

### Время и таймзоны

Все задачи работают в `Europe/Minsk`. `AsyncIOScheduler(timezone=settings.tz)`.

### Архитектура

```
src/scheduler/
├── __init__.py
├── scheduler.py        # AsyncIOScheduler instance + setup
└── jobs.py             # функции-задачи (вызываются по расписанию)

src/bot/main.py:
  - стартует scheduler в lifespan
  - регистрация существующих задач при старте (для durability)
```

### Что не делаем в этой фазе

- **Не делаем сложные правила.** Например, «напомнить тем, кто часто не приходит, отдельным сообщением» — это Phase 5.
- **Не делаем динамические настройки** (типа «настроить за сколько часов напоминать» через бот). Захардкожено в config.
- **Не делаем кронообразный планировщик** для аналитики (типа «каждый понедельник прислать отчёт») — тоже Phase 5.
