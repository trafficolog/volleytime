# Task 2.10.1: Запись игрока админом «за него»

## Цель

Админ может записать другого игрока на тренировку, минуя обычный flow «игрок сам жмёт». Используется когда игрок написал в личку, не имеет доступа к боту, или просто «новый и я записал».

## Контекст

Точка входа — два места:
1. Карточка игрока (Task 2.8.2) → кнопка «➕ Записать на тренировку» → выбор тренировки
2. Карточка тренировки (admin/manage.py) → кнопка «➕ Добавить игрока» → выбор игрока

Логика записи — та же, что у player flow (propose_slot, оплата), но управляется админом.

## Что должно быть сделано

- Кнопка «➕ Записать на тренировку» в карточке игрока:
  - Открывает список ближайших 7 тренировок со статусом `open` или `planned`
  - Клик на тренировку → передача в общий хендлер
- Кнопка «➕ Добавить игрока» в карточке тренировки:
  - Открывает список игроков (по аналогии с 2.8.1) с поиском, фильтр «не записан на эту тренировку»
  - Клик на игрока → передача в общий хендлер
- Общий хендлер `admin:booking:create:<user_id>:<training_id>`:
  - Проверка: игрок ещё не записан, тренировка не отменена/прошла
  - `BookingService.propose_slot(training_id, user_id)` для расчёта slot_type
  - Показать админу: «Записать @user на TRAINING на слот main/rotation/waitlist?»
  - Если main/rotation — вопрос про оплату: inline-клавиатура «🎫 С абонемента (если есть)», «💵 Наличные (pending)», «✅ Засчитать оплаченным (без записи в кассу)»
  - Если waitlist — просто создание `Booking` в `confirmed` (waitlist не требует оплаты до promotion)
- При выборе «С абонемента»:
  - Найти активный subscription игрока → consume_session
  - Booking → confirmed
- При выборе «Наличные»:
  - Создать Payment в pending, Booking в pending_payment
  - Уведомить игрока: «Вас записал админ на TRAINING, оплата N BYN наличными на тренировке»
- При выборе «Засчитать оплаченным»:
  - Создать Payment с status=succeeded, method=cash, без записи в кассу (это «компенсация»/«подарок» от админа)
  - Опционально — пометка в Payment.description "manual_admin_booking by <admin_id>"
  - Booking → confirmed
- AdminLog обязательно (action="manual_booking_create", details={user_id, training_id, slot, payment_method})
- Уведомление игроку: «Вас записал админ @<adminname> на тренировку DD.MM.YYYY HH:MM в <venue>. Слот: ...»

## Критерии приёмки

- Из карточки игрока запись работает
- Из карточки тренировки запись работает
- При попытке записать дважды — отказ (unique constraint)
- При попытке записать на отменённую — отказ
- При отсутствии активного абонемента — кнопка «С абонемента» не показывается
- Уведомление игроку доставлено
- AdminLog содержит все детали

## Подсказки

- Переиспользуем `BookingService.create_booking` — не дублируем логику.
- При показе «не записан на эту тренировку» в списке игроков — нужен EXISTS-запрос, индекс на (user_id, training_id) уже есть.

## Не делать

- Не создавать новых пользователей через «запиши за него» — только существующих.
- Не обходить лимиты слотов (если все заняты — в waitlist, а не «впихнуть»).
- Не давать обходить unique-constraint (даже если кажется удобным).
