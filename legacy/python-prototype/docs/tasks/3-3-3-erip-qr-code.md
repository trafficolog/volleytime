# Task 3.3.3: QR-код для ЕРИП

## Цель

Для оплат через ЕРИП дополнительно к ссылке на hosted page отправлять пользователю изображение QR-кода с кодом услуги, чтобы можно было оплатить из мобильного банк-клиента сразу.

## Контекст

ЕРИП интегрирован с банковскими приложениями: сканируешь QR → банк-клиент сам открывает экран оплаты с предзаполненным кодом. Это быстрее, чем переход на hosted page.

Эта задача **опциональная**: hosted page bePaid сам показывает QR-код. Дублирование в Telegram удобно, но не обязательно.

## Что должно быть сделано

- Библиотека `qrcode[pil]` в requirements.txt
- Хелпер `generate_erip_qr(payment_code: str, amount: int) -> BytesIO`: генерирует PNG-изображение QR-кода со ссылкой / кодом ЕРИП
- Формат содержимого QR — узнать у bePaid из их доки (обычно строка вида `erip:code=XXXX;amount=YYYY` или ссылка на hosted page с pre-filled параметрами)
- В хендлере `booking:pay:bepaid:erip:*` (3.3.2) добавить вторым сообщением `bot.send_photo` с этим QR
- Caption под QR: «Отсканируйте в мобильном банке. Код услуги: XXX. К оплате: 15.00 BYN»

## Критерии приёмки

- При выборе ЕРИП пользователь получает два сообщения: ссылку и QR-код
- Если bePaid не поддерживает наш способ генерации QR — отложить задачу в Phase 5

## Подсказки

- В реальной интеграции bePaid возвращает в `create_checkout` response код ЕРИП — нужно сохранить и использовать.
- Можно сделать без QR: просто текстовая инструкция «откройте банк → ЕРИП → найдите услугу [код]».

## Не делать

- Не реализовываем свой парсер QR из изображения.
- Не делаем динамические QR с обновлением — статичный достаточно.
- Если этот таск тормозит Phase 3 — пометить как cancelled, перенести в Phase 5.
