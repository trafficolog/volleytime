# Task 2.10.3: Перемещение между слотами и тренировками

## Цель

В миникарточке Booking (Task 2.10.2) кнопки «↗️ Переместить в main/rotation» и «📅 Перенести на другую тренировку». Полезно, когда место освободилось и нужен конкретный игрок из waitlist, или перенесли тренировку и нужно переместить участников.

## Контекст

Перенос между слотами в рамках тренировки — простая операция, изменение `slot_type` + проверка лимита.

Перенос между тренировками — сложнее: текущий Booking отменяется, новый создаётся с тем же payment_id/subscription_id (если был), на новой тренировке.

## Что должно быть сделано

### Перемещение между слотами

- Кнопки в миникарточке Booking:
  - Если slot=main: «↘️ В ротацию», «↘️ В waitlist»
  - Если slot=rotation: «↖️ В main», «↘️ В waitlist»
  - Если slot=waitlist: «↖️ В main», «↖️ В ротацию» (с обходом TTL подтверждения)
- При нажатии:
  - Проверка лимита целевого слота (если перевод в main и main заполнен — отказ)
  - `Booking.slot_type = new_slot`
  - Если новый slot = waitlist, а старый был main/rotation — попытаться promote_from_waitlist
  - Уведомление игроку: «Ваш статус на TRAINING изменён: main → rotation»
  - AdminLog

### Перенос на другую тренировку

- Кнопка «📅 Перенести на другую тренировку» → выбор тренировки (с фильтром по доступным датам)
- При выборе:
  - Подтверждение «Перенести Booking #X с TRAINING_A на TRAINING_B? Старая бронь будет отменена, на новой создан слот.»
  - Применить: отмена старого + создание нового с тем же `payment_id`/`subscription_id`
  - Если на новой тренировке используется абонемент — НЕ списываем сессию повторно (она уже списана)
  - Если cash — payment остаётся тем же
  - Уведомление: «Ваша запись перенесена с DATE_A на DATE_B»
  - AdminLog

## Критерии приёмки

- Перемещение main → rotation в рамках тренировки работает
- Попытка переместить в заполненный main — отказ
- Промоут из waitlist в main с подтверждением админа обходит TTL (Phase 4)
- Перенос на другую тренировку: на старой статус cancelled, на новой confirmed
- Subscription session не списывается повторно
- Все операции в AdminLog

## Подсказки

- При переносе: проще создать transactional helper `BookingService.transfer_booking(booking_id, new_training_id)`.
- Защита: нельзя переместить на cancelled/finished тренировку. Нельзя на тренировку, где игрок уже записан (unique constraint).

## Не делать

- Не дублировать платёж при переносе.
- Не создавать новый Payment если на новой тренировке другая цена — это редкий edge case, оставляем pending для админа разбираться вручную.
- Не делать «массовый перенос» в этой задаче.
