# Task 2.11.3: Отмена абонемента с возвратом

## Цель

В карточке абонемента кнопка «🚫 Отменить абонемент»: переводит status в `refunded`, опционально создаёт expense в кассу с категорией refund на сумму неиспользованных сессий (пропорционально) или на полную сумму.

## Контекст

Сценарии: «Хочу вернуть деньги за неиспользованные», «По договору 14-дневный return-period».

## Что должно быть сделано

- Кнопка «🚫 Отменить абонемент» → подтверждение
- FSM `RefundSubscription`:
  1. `waiting_amount_mode`:
     - «🔄 Возврат пропорционально (за N неиспользованных сессий)» — рассчитать
     - «💯 Возврат полной суммы» — `subscription.price`
     - «🆓 Без возврата (списать)» — только статус, без ledger
     - «✏️ Ввести сумму вручную»
  2. (если ввод вручную) `waiting_amount` — Decimal
  3. `waiting_reason` — свободный текст
- Применение:
  - Если выбран любой возврат с amount > 0 — `LedgerEntry(expense, category=refund, amount=<sum>)`
  - `Payment.status = refunded` (если был)
  - `Subscription.status = refunded`
  - Если все сессии не использованы — `Subscription.total_sessions = used_sessions` (чтобы счётчик «осталось» был 0)
  - Уведомление игроку: «Ваш абонемент отменён. {reason}. Возврат: N BYN — обратитесь к организатору.»
  - AdminLog (action="subscription_refunded", details={amount, reason, mode})

## Критерии приёмки

- Расчёт пропорционального возврата корректный: если использовано 3 из 8 за 104 BYN → возврат `104 * 5/8 = 65 BYN`
- При выборе «без возврата» в кассу ничего не пишется
- Subscription.status становится refunded и недоступен для consume
- Уведомление игроку доставлено
- AdminLog заполнен

## Подсказки

- Округление: `Decimal(price) * Decimal(remaining) / Decimal(total)`, округление до копеек (`.quantize(Decimal("0.01"), ROUND_HALF_UP)`).
- Если есть существующие confirmed-брони с этим subscription_id и тренировки ещё не прошли — предупреждение: «На этом абонементе N активных бронирований. После возврата они останутся, но сессий не будет. Снять брони? [Да] [Нет]»

## Не делать

- Не делать частичный возврат с продолжением использования (либо вернули — либо нет).
- Не вызывать bePaid refund API в этой задаче (это будет в Phase 3, Task 3.1.2). Здесь только cash-возвраты через ledger.
- Не возвращать сессии в абонемент после refund (он закрыт).
