# Task 2.9.1: Редактирование полей тренировки

## Цель

В карточке тренировки (admin/manage.py) добавить кнопку «✏️ Редактировать». Открывается экран со списком полей и кнопками для изменения каждого. Уведомляем участников при изменении даты/места.

## Контекст

Текущий flow Phase 1: FSM создания тренировки за 5 шагов. После сохранения — никаких правок. Phase 2.5 это закрывает.

## Что должно быть сделано

- Кнопка «✏️ Редактировать» в `cb_training_view` (admin/manage.py), видна только если `training.status not in (finished, cancelled)`
- Экран `admin:training:edit:<id>` со списком полей:
  ```
  ✏️ Редактирование тренировки

  📅 Дата и время: 30.05.2026 19:00 → [✏️]
  🕒 Длительность: 2 часа → [✏️]
  📍 Место: Спортшкола №1 → [✏️]
  💰 Цена main: 15.00 BYN → [✏️]
  💰 Цена ротация: 15.00 BYN → [✏️]
  👥 Лимит main: 12 → [✏️] (см. 2.9.4)
  👥 Лимит ротация: 2 → [✏️]
  📝 Заметки: — → [✏️]

  « Назад в карточку
  ```
- Каждая кнопка `[✏️]` запускает соответствующий FSM:
  - `EditTraining.waiting_datetime` — формат: `DD.MM.YYYY HH:MM` или `завтра 19:00`
  - `EditTraining.waiting_duration_hours` — число, например `2` или `2.5`
  - `EditTraining.waiting_venue` — строка
  - `EditTraining.waiting_price_main` — Decimal
  - `EditTraining.waiting_notes` — строка или `/skip` чтобы очистить
- Валидация:
  - Дата не в прошлом
  - Цена ≥ 0
  - Лимит main ≥ 1, лимит rotation ≥ 0
  - Если новых лимитов меньше, чем уже занятых слотов — отказать с пояснением (см. 2.9.4)
- После каждой правки:
  - Запись в `AdminLog` (action="training_edited", details={field, old, new})
  - Возврат в экран редактирования с обновлёнными значениями
- При изменении `starts_at` или `venue` — уведомление всем участникам (confirmed + pending) с новой информацией
- При изменении цены — текст в notification: «новая цена X BYN. Уже совершённые оплаты не пересчитываются.»

## Критерии приёмки

- Кнопка «Редактировать» не видна для отменённых/завершённых тренировок
- Все 8 полей можно изменить независимо
- Уведомление при смене даты/места доходит до всех confirmed
- При попытке изменить лимит main с 12 на 8, когда уже 10 main-бронирований — отказ с подсказкой
- Все правки в AdminLog

## Подсказки

- Парсер даты: `dateutil.parser.parse(value, dayfirst=True)` или явный `strptime`. Если в требованиях разрешить «завтра 19:00» — простой словарь маппинга «сегодня/завтра/послезавтра» + время.
- `ends_at = starts_at + duration_hours` — пересчитать при изменении любого из них.
- Не пересчитываем `ends_at` независимо: только через duration.

## Не делать

- Не делать «массовую правку нескольких тренировок» — отдельные операции.
- Не делать undo последних N изменений — AdminLog даёт читать историю, но не восстанавливать.
