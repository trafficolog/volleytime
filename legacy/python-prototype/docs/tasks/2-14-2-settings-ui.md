# Task 2.14.2: UI просмотра и редактирования настроек

## Цель

В admin_menu кнопка «⚙️ Настройки». Список настроек по группам, клик → редактирование.

## Контекст

Все 9 настроек из Task 2.14.1 должны быть редактируемы через бот.

## Что должно быть сделано

- В `admin_menu` кнопка «⚙️ Настройки» → `admin:settings:list`
- Хендлер `admin:settings:list`:
  - Все настройки сгруппированы по `group_name`:
    ```
    ⚙️ Настройки

    📌 Цены
    • Базовая цена тренировки: 15.00 BYN [✏️]

    📌 Лимиты
    • Лимит основной состав: 12 [✏️]
    • Лимит ротация: 2 [✏️]

    📌 Тайминги
    • Окно записи (часов до): 2 [✏️]
    • TTL pending-платежа (мин): 15 [✏️]
    • Возврат при отмене (часов до): 24 [✏️]
    • TTL подтверждения waitlist (мин): 30 [✏️]

    📌 Уведомления
    • Напоминание за 24 ч: ✅ вкл [🔁 переключить]
    • Напоминание за 2 ч: ✅ вкл [🔁 переключить]

    « Назад
    ```
- Каждое значение — кнопка `admin:settings:edit:<key>`
- Для bool — toggle при нажатии (без FSM): прямо в обработчике инвертируем и сохраняем
- Для остальных — FSM `EditSetting.waiting_value`:
  - Бот: «Введите новое значение для {description} (текущее: {value}):»
  - Валидация по `value_type`:
    - int: `int(text)`, диапазон сансибельный (например, 0-1000)
    - decimal: `Decimal(text)`, ≥ 0
  - При ошибке — сообщение и повторный ввод
- Применение: `await settings_service.set(key, parsed_value, admin_id)` → возврат в список

## Критерии приёмки

- Все 9 настроек видны и редактируемы
- Bool-настройки переключаются одним кликом
- Числовые — через FSM
- Невалидное значение отклоняется с понятной подсказкой
- После изменения возврат в общий список с обновлённым значением
- AdminLog ведётся (внутри SettingsService.set)

## Подсказки

- Группировка по `group_name` — query с GROUP BY или просто сортировка и группировка в Python.
- При редактировании float — поддержать как точку, так и запятую (`text.replace(",", ".")`).

## Не делать

- Не валидировать кросс-настройки (типа `pending_payment_ttl > 0`) — диапазон для каждой проверяется отдельно.
- Не показывать историю изменений в первой итерации — AdminLog даёт это отдельно.
