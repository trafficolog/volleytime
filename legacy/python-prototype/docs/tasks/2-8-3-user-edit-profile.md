# Task 2.8.3: Редактирование профиля (ФИО, телефон)

## Цель

Из карточки игрока (Task 2.8.2) админ может изменить его ФИО и телефон. Например, если игрок указал короткое имя в Telegram, а в группе известен как «Пётр Петров».

## Контекст

`username` Telegram админ не редактирует (его меняет сам пользователь в TG). А `full_name` и `phone` — на нашей стороне.

## Что должно быть сделано

- Кнопка «✏️ Изменить ФИО» в карточке → запуск FSM `EditUserName.waiting_value`
- Бот: «Введите новое ФИО для игрока @petrov (сейчас: «Пётр Петров»):»
- При получении сообщения: валидация (длина 2-255 символов), сохранение через `UserRepository`
- Запись в `AdminLog`: action="user_renamed", entity_type="user", entity_id=user.id, details={"old": "...", "new": "..."}
- Возврат в карточку с обновлённым ФИО
- Аналогично «✏️ Изменить телефон» (FSM `EditUserPhone.waiting_value`), валидация формата (`re.match(r"^\+?[\d\s\-\(\)]{7,20}$", value)`)
- Опция «❌ Очистить телефон» — устанавливает в `None`

## Критерии приёмки

- Изменение ФИО сохраняется в БД
- Изменение телефона сохраняется
- Невалидный телефон отвергается с подсказкой по формату
- В AdminLog есть запись с старым и новым значением
- После сохранения карточка обновляется

## Подсказки

- FSM-классы в стиле существующих (см. `admin/ledger.py` для `AddExpense`).
- Текст «сейчас: ...» помогает админу понять, что менять.
- Не нужна отдельная кнопка «отмена» — `/cancel` или просто игнор.

## Не делать

- Не разрешать редактировать чужой `username` или `telegram_id` (это поломает поиск).
- Не уведомлять игрока, когда админ изменил его ФИО — это административная корректировка.
