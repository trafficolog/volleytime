# Task 2.8.2: Карточка игрока с историей

## Цель

При клике на игрока в списке (Task 2.8.1) — открывается его карточка: основная информация, агрегированная статистика, кнопки для перехода во вкладки «История записей», «Абонементы», «Платежи», «Кассовые операции с участием».

## Контекст

Это основной экран работы с конкретным игроком. Через неё подключаются все остальные задачи Epic 2.8 (редактирование, блокировка, повышение) и Epic 2.10–2.11 (ручные записи и абонементы).

## Что должно быть сделано

- Хендлер `admin:user:view:<user_id>`:
  - Загрузить User
  - Подсчитать агрегаты через одно-два SQL запроса:
    - `bookings_total = COUNT(Booking) WHERE user_id = X`
    - `bookings_attended = COUNT WHERE status=attended`
    - `bookings_no_show = COUNT WHERE status=no_show`
    - `subscriptions_active = COUNT WHERE status=active AND user_id=X`
    - `total_spent = SUM(amount) WHERE user_id=X AND status=succeeded`
  - Сформировать карточку:
    ```
    👤 Пётр Петров @petrov

    ID: 12345678 · Тел: +375 29 123-45-67
    Регистрация: 12.03.2026
    Роль: player · Статус: ✅ активен

    📊 Статистика
    Записей всего: 24 · Посетил: 18 · Не пришёл: 2
    Активных абонементов: 1 · Потратил всего: 480 BYN

    ✏️ Изменить ФИО · ✏️ Изменить телефон
    🚫 Заблокировать · 👑 Сделать админом

    📋 История записей (24)
    🎫 Абонементы (3)
    💰 Платежи (15)
    ```
- Вкладки реализованы как отдельные хендлеры:
  - `admin:user:bookings:<user_id>` — список бронирований игрока по странице 10, сортировка по `created_at DESC`, видны: дата тренировки, slot_type, status (с иконкой)
  - `admin:user:subscriptions:<user_id>` — список абонементов, видны: код плана, сессий/срок, status
  - `admin:user:payments:<user_id>` — список платежей: amount, kind, method, status, дата
- Каждый элемент в этих списках кликабелен → переход в его карточку (для booking: переход в карточку тренировки; для subscription: переход в карточку абонемента — Epic 2.11; для payment: переход в карточку платежа — частично уже есть в `admin/payments.py`)
- Кнопка «« К списку игроков» возвращает в Task 2.8.1

## Критерии приёмки

- Карточка открывается за < 200 мс на in-memory SQLite
- Все агрегаты корректны (написать SQL-тест)
- Вкладка «История записей» показывает данные с пагинацией
- Все ссылки на другие сущности (тренировка по booking, абонемент) работают
- Если у игрока нет данных в какой-то вкладке — пустое сообщение «У игрока пока нет записей»

## Подсказки

- Агрегаты можно посчитать одним запросом через `func.count(case())` (SQLAlchemy), это эффективнее чем 5 отдельных.
- В карточке не дублируем кнопки «➕ Записать на тренировку» и «🎫 Создать абонемент» — это будут отдельные кнопки из Epic 2.10 и 2.11.

## Не делать

- Не делать визуализацию (графики посещаемости). Это Phase 5.
- Не открывать полную историю в самой карточке — она перегружается. Только агрегаты.
- Не показывать чувствительные данные (содержимое чата, переписку) — у нас их и нет.
