# Task 2.11.2: Продление срока и модификация сессий абонемента

## Цель

В карточке игрока во вкладке «Абонементы» (Task 2.8.2) — клик на конкретный абонемент открывает его карточку с кнопками для модификации.

## Контекст

Сценарии:
- «У меня заканчивается срок, продлите на неделю — я болел».
- «Случайно списали сессию из-за бага» (это вообще должно бы делать `restore_session`, но иногда нужна ручная корректировка).
- «Хочу подарить ещё одну сессию игроку».

## Что должно быть сделано

- Хендлер `admin:subscription:view:<sub_id>`:
  - Карточка:
    ```
    🎫 Абонемент #15
    Игрок: Пётр Петров
    План: 8x (8 сессий, 104 BYN, 60 дней)

    Использовано: 3 / 8
    Срок действия: до 30.06.2026 (осталось 28 дней)
    Статус: active

    📅 Продлить срок
    ➕ Добавить сессию · ➖ Убрать сессию
    🚫 Отменить абонемент (см. 2.11.3)
    « К игроку
    ```
- Кнопка «📅 Продлить срок» → FSM `ExtendSubscription.waiting_days`:
  - «На сколько дней продлить?»
  - Валидация: 1-365
  - `subscription.expires_at += timedelta(days=N)`
  - AdminLog (action="subscription_extended", details={days, old_expires, new_expires})
  - Уведомление игроку: «Срок действия вашего абонемента продлён на N дней до DD.MM»
- Кнопка «➕ Добавить сессию»:
  - `subscription.total_sessions += 1`
  - Если статус был `depleted` — вернуть в `active`
  - AdminLog
  - Уведомление: «На ваш абонемент добавлена 1 сессия. Осталось: X из Y»
- Кнопка «➖ Убрать сессию»:
  - Защита: `total_sessions - 1 >= used_sessions` — иначе отказ «нельзя убрать больше, чем доступно»
  - `subscription.total_sessions -= 1`
  - Если новый `total == used` — статус → `depleted`
  - AdminLog + уведомление

## Критерии приёмки

- Продление срока работает, новая дата корректная
- Добавление сессии работает, depleted → active
- Убавление сессии нельзя сделать ниже used
- Все операции в AdminLog
- Игрок получает уведомления

## Подсказки

- Уведомление формирование: текст шаблона в `bot/texts.py`.
- Защита от race condition при `used_sessions == total_sessions` — операции с total можно делать через явный SQL UPDATE.

## Не делать

- Не делать «продление с обнулением used» — это другая операция (новая покупка).
- Не давать продлевать просроченный (`expired`) абонемент через эту задачу — отдельный flow «реактивация» в Phase 5.
- Не позволять менять `price` уже купленного абонемента — это финансовый артефакт.
