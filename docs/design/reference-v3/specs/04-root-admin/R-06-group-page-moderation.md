# R-06 · Модерация страниц групп

| Интерфейс | Фаза | Сложность | Модель | Ревью |
|---|---|---|---|---|
| Root Admin | Ф4 · SEO-страницы групп · 24.1.3 | L | контракт Opus, UI Sonnet | Opus |

## Цель

Root Admin находит любую страницу группы в стране за пару действий и может скрыть её или закрыть от поиска. Организатор видит причину и может её исправить.

## Макет

- 4b Root Admin → Страницы групп → вкладка «Каталог городов»
- 4b Root Admin → Страницы групп → вкладка «Жалобы»
- 4b Root Admin → Страницы групп → ··· у страницы → Скрыть / Принудительный noindex / Вернуть / История
- 5 Public Pages → режим «Страница группы» → «Пожаловаться»
- 4 Кабинет организатора → Страница группы → Tweaks «Модерация»: нет / скрыта / noindex
- Скриншоты: `screenshots-2026-11-24/4b-root-admin/13…21-R06-*`, `5-public/04…06-R06-*`, `4-cabinet/28…29-R06-*`

## Объём

**Каталог городов**
- Города из каталога 24.1.2: все районные центры страны (≈120), сгруппированы по Минску и шести областям
- Поиск сразу по городам и группам, фильтры «Со страницами · Внимание · Все», сворачиваемые области, режим «Вся страна»
- Таблица страниц: группа, адрес `volleytime.by/{город}/{группа}`, статус, жалобы, последнее решение
- Статусы: «в поиске», «noindex · владелец», «noindex · root», «скрыта · 404»
- «Внимание» = скрыта, noindex от root или есть открытые жалобы

**Два разных действия**
- «Скрыть»: страница отдаёт тот же 404, что неопубликованная, пропадает из sitemap, каталога города и выдачи
- «Принудительный noindex»: страница открывается по ссылке, но получает `noindex` и `X-Robots-Tag`, её нет в sitemap и каталоге. Действует, даже если владелец включил индексацию, а переключатель в кабинете при этом заблокирован
- Оба действия требуют причину из списка и необязательную заметку. В диалоге показано, что изменится, и как будет выглядеть сообщение в боте
- Причины: цены не совпадают с записью; оплата в обход записи; вводящие в заблуждение обещания; чужие или неподходящие фото; группа не проводит игры (нет событий больше 60 дней); спам или контакты в заголовках
- «Вернуть»: снимает решение root, индексация снова по настройке владельца
- «История»: все решения и жалобы по странице с автором и временем

**Жалобы на страницы**
- Публичная кнопка «Пожаловаться» на `/{город}/{группа}`: причина из списка и текст до 500 символов
- Причины для посетителя: цены не совпадают с записью; группа не существует или не играет; чужие фото или текст; обман или мошенничество; другое
- Лимит: не больше 3 жалоб в сутки с устройства, сверх лимита ответ «принято» без записи; счётчик отсечённых виден root
- Вкладка «Жалобы»: счётчики «Новые · Решено за 30 дней · Отсечено лимитом», фильтр «Новые · Решённые · Все», действия «Скрыть страницу», «noindex», «Отклонить»

**Права команды платформы**
- «Скрыть», «Принудительный noindex» и «Вернуть» — Owner, Admin и Moderator ([R-15](R-15-platform-team-roles.md))
- Support разбирает жалобы на страницы: видит их и может отклонить; чтобы скрыть страницу, передаёт жалобу модератору

**Организатор**
- Баннер в разделе кабинета «Страница группы»: что сделала администрация, причина, когда, что исправить; кнопки «Запросить проверку» и «Ответить модератору»
- То же сообщение уходит в бот владельцу и организаторам группы (P-09)

## Данные и API

Модель данных меняется, поэтому первым шагом Opus пишет миграцию и контракт, затем Sonnet делает экраны.

- `group_page_moderation`: `pageId`, `state` (none · noindex · hidden), `reason`, `note`, `byUserId`, `at`. Хранится рядом со страницей группы, одна текущая запись на страницу
- `group_page_complaint`: новая таблица. `pageId`, `reason`, `text`, `deviceHash`, `ip`, `status` (new · done · rejected), `resolution`, `resolvedBy`, `createdAt`
- Каждое решение пишет `page.moderation.hide / noindex / restore` в журнал аудита R-07
- GET /admin/pages?city=&q=&scope=attention|with-pages|all
- POST /admin/pages/{id}/moderation {state, reason, note}
- GET /admin/pages/{id}/history
- POST /public/pages/{id}/complaints — без авторизации, с лимитом
- GET/PATCH /admin/page-complaints
- POST /groups/{id}/page/review-request — «Запросить проверку»

## Состояния экрана

- Город без страниц групп
- Поиск без результатов
- Страница скрыта: 404 на публичном адресе, баннер в кабинете
- Принудительный noindex: страница открывается, переключатель индексации в кабинете заблокирован
- Жалоба отправлена, жалоба отсечена лимитом (посетитель видит тот же ответ)

## Критерии приёмки

- [ ] Скрытая страница отдаёт тот же 404, что и неопубликованная, без признаков модерации в ответе
- [ ] Принудительный noindex перекрывает `seoIndex = true` владельца в HTML, заголовке, sitemap и каталоге
- [ ] «Вернуть» восстанавливает индексацию по настройке владельца, а не всегда «в поиске»
- [ ] Организатор видит причину в кабинете и получает сообщение в бот
- [ ] Четвёртая жалоба за сутки с одного устройства не попадает в таблицу
- [ ] Каждое решение есть в журнале аудита с автором и причиной
- [ ] Поиск по каталогу из 120 городов отвечает быстрее 300 мс
- [ ] Support не может скрыть страницу или выставить noindex — проверка на стороне API

## Правки после ревью

- Прежняя очередь премодерации (новые и изменённые страницы, «Опубликовать») убрана. Страница публикуется сразу, root реагирует постфактум: на жалобы и через каталог.
- Отдельный макет 4c удалён, экраны встроены в 4b, 5 и 4.
- Адрес страницы: `volleytime.by/{город}/{группа}`, например `volleytime.by/minsk/vt-minsk`.
- Сложность выросла с M до L: новая таблица жалоб и миграция состояния модерации.
- Реализовано в репозитории задачей [24.1.3](../../../../tasks/24-1-3-group-page-moderation.md) (`v0.5.0`, контракт #343, UI #344). Маршруты API — по карточке задачи. Адрес `/{город}/{группа}` принят владельцем ([D-26](../../../../operations/decisions/2026-10-12-reference-v3-decisions.md#d-26)), в коде пока `/g/<slug>`. «Запросить проверку» и «Ответить модератору» — бэклог ([D-30](../../../../operations/decisions/2026-10-12-reference-v3-decisions.md#d-30)). Права ролей Moderator и Support — после R-15 ([D-28](../../../../operations/decisions/2026-10-12-reference-v3-decisions.md#d-28)).
