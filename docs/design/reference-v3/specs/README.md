## Сложность и модель

| Уровень | Что это | Модель |
|---|---|---|
| S | Вёрстка по готовому макету, тексты, переименования | Haiku |
| M | Компоненты с состоянием, формы, CRUD, известный API | Sonnet |
| L | Несколько экранов и сущностей, новые эндпоинты | Sonnet, ревью — Opus |
| XL | Архитектура, деньги, фоновые задачи, алгоритмы, доступ, LLM, SEO-рендер | Opus + тесты |

- Деньги и баланс (цена, сбор суммой, возвраты, списания, выплаты) — Opus и тесты на граничные случаи.
- Проверка доступа (initData, роли, приглашения) — Opus.
- Если L-задача меняет модель данных, сначала Opus пишет схему и контракт, потом Sonnet — UI.
- Haiku не трогает бизнес-логику.

Решения после четвёртого прохода (нарисованы в макетах):
- W-13: город выбирается поиском по всем ≈120 районным центрам каталога 24.1.2.
- W-01, P-18: у организатора в кабинете нет «Команды» и «Опасной зоны».

Решения владельца 2026-11-24 (сверка с репозиторием, PR #348):
- Адрес страницы группы — `volleytime.by/{город}/{группа}`, например `/minsk/vt-minsk`; в коде сейчас `/g/<slug>`, нужна задача на смену адресов с 301.
- Организатор видит баланс событий и историю, пополняет только владелец — как в коде. Прежнее «организатор не видит баланс» было ошибкой переноса матрицы из «Ревью платформы».
- Роли команды платформы расширены до шести — [R-15](04-root-admin/R-15-platform-team-roles.md), задача 29.3.1.
- Фаза 29 поглощает карточки проекта 27.10.3 и 10.2.1–10.2.2.
- «Запросить проверку» и «Ответить модератору» (R-06) — бэклог, через обращение в поддержку после 29.3.
