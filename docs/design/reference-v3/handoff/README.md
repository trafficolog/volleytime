# Handoff: VolleyTime — платформа записи на волейбольные тренировки

## Обзор
VolleyTime — Telegram-first SaaS для любительских волейбольных групп. Игроки записываются на тренировки в Telegram Mini App. Организатор ведёт состав, оплаты, абонементы, сборы и кассу в Mini App и в веб-кабинете. Владелец платформы управляет организациями, credits и тарифами в Root Admin.

Пакет покрывает все точки входа:
- **Лендинг** volleytime.by
- **Telegram-бот** (сообщения, клавиатуры)
- **Mini App** — роли «игрок» и «организатор»
- **Веб-кабинет организатора**
- **Root Admin** платформы
- **Публичная страница события**
- **Авторизация** (веб и Mini App)
- **Бренд-система**

## О файлах дизайна
Файлы в пакете — **дизайн-референсы, сделанные на HTML**: прототипы с целевым внешним видом и поведением. Это не продакшен-код для копирования.

Задача — **воспроизвести эти экраны в целевом стеке** его собственными средствами. По исходной архитектуре проекта это **Nuxt 4 (Vue 3) + Drizzle/PostgreSQL + grammY + better-auth + Telegram WebApp SDK**.

Прототипы собраны на React + Babel в браузере. Это только инструмент прототипирования, в проект его не переносить. Компоненты нужно заново сделать как Vue-компоненты, стили — как токены и утилиты проекта (CSS variables, UnoCSS или Tailwind — что принято в кодовой базе).

## Точность
**High-fidelity.** Цвета, типографика, отступы, радиусы, тени, тексты и состояния финальные. Воспроизводить нужно попиксельно. Все значения — в разделе «Дизайн-токены» и в `styles.css`.

Моковые данные (имена, суммы, даты) — фикстуры. Их заменяют реальными данными из API.

## Дизайн-язык: Bento Bold
- **Поверхности без обводок.** Карточки отделяются тоном фона и тенью. Обводка 1px используется только у полей в фокусе и изредка как тонкий разделитель.
- **Бенто-сетка.** На главных экранах сетка плиток разной ширины. В каждой плитке одна крупная цифра и короткая подпись.
- **Акцентная карточка («hero»).** Одна на экран. Фон `--vt-blue-ink`, белый текст, оранжевый декоративный круг в углу, тень `--vt-shadow-accent`.
- **Типографика.** Заголовки H1/H2 и все числа набраны Oswald 700 в ВЕРХНЕМ регистре, `letter-spacing: 0`. Текст и H3/H4 — Golos Text. Отрицательного трекинга у Oswald нет нигде.
- **Плавающий док.** Таб-бар Mini App — тёмная капсула с тенью, отступ от краёв 12px.
- **Иконки.** Stroke 1.6–1.8, скруглённые концы. Эмодзи не используются нигде, кроме текста сообщений Telegram-бота.

## Доменная логика (реализовать один раз и переиспользовать)
Лежит в `atoms.jsx`. Во всех экранах должна вызываться **одна и та же функция**: раньше список и карточка расходились, когда одно и то же считали в двух местах.

- **`meterTint(pct)`** — цвет заполненности: `≥100` rose · `>70` amber · иначе grass. Используется для шкал, сегментов, пилюль и календаря.
- **`buildRoster(headCount, {isSplit})`** — состав события. Игрок может занять **несколько мест** одной записью (`seatsOf`, лимит в настройках группы, по умолчанию 3). Места упаковываются до заполнения вместимости. Строка одна, мест несколько, чип `+N`. Счётчики «мест занято» и «игроков» — разные величины.
- **`pendingOf(...)`** — число «ждут оплаты». Бейдж в списке берётся отсюда, а не из литерала.
- **Модель оплаты события** (`priceMode`):
  - `fixed` — цена за место известна сразу, абонемент применим.
  - `split` — задаётся общая сумма к сбору. **Пока запись открыта**, цена с места показывается как прогноз `≈ total / seats` с пометкой «уточнится». **При закрытии записи** сумма фиксируется, игрокам приходит точная цифра, знак ≈ исчезает. **Абонементы в `split` недоступны.**
- **Лист ожидания** — при полном составе вместо записи «Встать в лист ожидания · без оплаты». При освобождении места первый получает уведомление и **30 минут** на подтверждение (срок сгорания стережёт планировщик на сервере). На закрытом событии секция скрыта.
- **Опциональные модули группы** (настройки → «Записи и оплата»): абонементы включаются тумблером. Если выключены, раздел пропадает из навигации, KPI, состава и выбора оплаты, а уже купленные абонементы доживают срок. Лимит мест на игрока. Способ оплаты по умолчанию.
- **Политика отмены** — глобально на уровне группы (разрешена ли, крайний срок), а не у каждого события.
- **Credits** — 1 credit = 1 опубликованное событие. Списывается при создании, возвращается при отмене до открытия записи. Demo-квота новой группы — 5.
- **Касса (ledger)** — подтверждённые взносы попадают автоматически с категорией (`training_fee / subscription / contribution / rent / balls / refund / …`), расходы вносятся вручную.

### Статусная модель (обязательно соблюдать)
Три оси, которые **никогда не смешиваются в одном чипе** (`atoms.jsx`: `participationOf`, `eventStateOf`, `MyChip`, `StateChip`, `SeatsMini`):
1. **Моё участие** — чип **словом**, фирменный синий, только у игрока: `.vt-chip--mine` «Иду» (галочка), `.vt-chip--queue` «В очереди · N-й». Не записан — чипа нет. «Иду» остаётся синим и после закрытия записи.
2. **Событие** — нейтральный серый `.vt-chip--state` словом: «Запись закрыта» / «Прошла» / «Отменена». В строке списка — в мета-строке под названием, а не в правой колонке.
3. **Места** — только **цифра + шкала**, цвет живёт на шкале (`meterTint`), текст нейтральный; полный состав — «мест нет». На синем hero — `meterTintOnDark`.
Оплата — отдельная ось: amber = нужно действие («ждёт оплаты», «нужно распределить»), grass = в порядке. Очередь и прогноз цены у организатора — серые (информация, не тревога). Согласование числа: «1 ждёт / 2 ждут».

### Расписание на месяц (`screens-schedule.jsx`)
`ScheduleMonth role="player|org"` — переключение месяцев, вид «Календарь / Список по неделям», у игрока фильтр «Мои». В сетке точка = тренировка: залитая синяя — «вы идёте», контурная — просто тренировка. Тап по дню → список его тренировок. Вход — кнопка «Смотреть все» на главных игрока и организатора.

### Серии тренировок (`RecurrenceBlock`)
Одно действие вместо десятков: повтор (один раз / каждую неделю / раз в 2 недели) × дни недели (мультивыбор) × срок (месяц / квартал / полгода / год). Предпросмотр: количество, диапазон дат (год указывается при переходе через год), правило словами, даты чипами, конфликт зала → дата создаётся черновиком. Credits: 1 на тренировку; при нехватке публикуются первые N, остальные — черновики до пополнения. Серию правят целиком или по дате; отмена будущих дат возвращает credits. Используется и в Mini App, и в кабинете.

### Группы (переключатель)
В Mini App сущность везде называется **«группа»** («Группы», «Создать группу», «Вступить по ссылке»); «организация» — только в кабинете и админке. Текущая группа — залитый круг `--vt-flame` с белой галочкой (`role="radio"`). Слева — логотип группы (`OrgLogo`); без логотипа — монограмма из 2 букв Oswald на тоновой плитке, цвет стабилен по хэшу названия.

### Текст внутри flex-контейнеров
`.vt-chip` и строки с иконкой — `inline-flex` с `gap`: текст из нескольких JSX-узлов разваливается на отдельные flex-элементы («Сб 6 . 06»). Подпись собирать одной шаблонной строкой или оборачивать текст в один `<span>`.

## Экраны

### 0. Лендинг — `0 Лендинг.html` + `landing-fx.js`
Адаптивный, `max-width 1240`, отступ 28px (18px на мобильном).
1. Липкая шапка с размытием (логотип, 4 якорные ссылки — скрываются ≤1000px, «Войти», «Создать группу»).
2. Первый экран: грид 1.05fr / 1fr (одна колонка ≤1080px). H1 «Игра без чата и таблиц», последняя строка оранжевая. Справа блок blue-ink с двумя повёрнутыми телефонами (−4° и +5°) и всплывающими уведомлениями.
3. Бегущая строка на оранжевом (Oswald 30px, точки-разделители).
4. «Было / стало»: переписка в чате против карточки события.
5. Бенто 4 колонки: запись и лист ожидания (2 колонки, hero), делёж суммы, несколько мест, касса (2 колонки, raised), абонементы, напоминания (ink).
6. «Запуск за вечер» — 3 шага, номера 01–03 Oswald 96px.
7. Организатору / игроку.
8. Тарифы на credits: 10 → 50 Br, 30 → 120 Br («Популярный», hero), 100 → 350 Br.
9. Вопросы — `details/summary`, иконка «+» поворачивается на 45°.
10. Финальный CTA, подвал.

**Интерактив (`landing-fx.js`)** — перенести как Vue-композиблы:
- **Частицы на canvas** в hero и финальном CTA. Плотность — площадь / 8200 (от 24 до 110 точек), DPR не выше 2. Связи между точками ближе 110px. Курсор притягивает точки в радиусе 160px и отталкивает ближе 40px, линии к курсору оранжевые. Пауза вне экрана (IntersectionObserver), пересчёт при ресайзе (ResizeObserver).
- **Параллакс слоёв hero** за курсором с плавностью 0.08 плюс смещение при скролле.
- **Появление при скролле** `.rv`: `translateY(28px)` → 0, 700–800 мс `cubic-bezier(.2,.7,.2,1)`, шаг 80 мс внутри группы.
- **Отсчёт цифр** 1100 мс, ease-out cubic. **Шкала мест** заполняется по ячейке каждые 60 мс.
- **Живые уведомления** в hero: смена каждые 3.6 и 4.5 с.
- **Бегущая строка** ускоряется со скоростью скролла и разворачивается при прокрутке вверх.
- **Блик** за курсором на бенто-плитках, **магнитные** оранжевые CTA, **полоса прогресса** чтения, подсветка текущего раздела в меню.
- Эффекты за курсором только при `(pointer: fine)`. С `reduced-motion` всё статично.

### 1. Бренд-система — `1 Brand and System.html` (+ `brand.jsx`)
Живой каталог: айдентика, типографика, компоненты, формы и контролы (с выпадающим списком), доменные паттерны. Использовать как визуальный эталон атомов.

### 2. Telegram-бот — `2 Telegram Bot.html` (+ `screens-bot.jsx`)
Сверено с реальными ограничениями Bot API — **не рисовать невозможного**:
- В inline-кнопках **только текст** (эмодзи можно), иконок нет. Кнопка `web_app` выглядит как обычная.
- В теле сообщения только `b / i / u / s / a / code / pre / blockquote / tg-spoiler`. Ни цвета, ни подложек, ни колонок. Статусы передаются эмодзи-кружками 🟢🟡🔴, счёт словами («занято 12 из 14»).
- Нажатие inline-кнопки → `answerCallbackQuery` (тост) + `editMessageText` (правка на месте). **Реплики от пользователя не появляется.**
- Меню — **reply-клавиатура** над полем ввода: она отправляет текст от пользователя.
- Живых таймеров нет, только абсолютный дедлайн («подтверди до 08:44»).
- Экраны: deeplink-онбординг `/start org_…`, лента уведомлений (24 ч / 2 ч, оплата, итог, место из листа ожидания), меню + расписание + помощь.

### 3. Mini App — `3 Mini App.html` (прототип с навигацией, переключатель ролей сверху)
Фрейм 390×820. Навигация — стек (`app-nav.jsx`: `push / back / reset`, sheet, popover, toast, alert).

**Игрок:** Главная (бенто, hero ближайшей записи, расписание) · Событие (fixed / split / лист ожидания / закрыто) · Запись (выбор числа мест, способ оплаты, ветка листа ожидания) · Мои записи · Абонементы · Покупка абонемента · Сборы → сбор → взнос · Уведомления · Профиль · Онбординг по приглашению · пустые и офлайн-состояния (`canBook`, `OFFLINE_REASON`).

**Организатор:** Главная (бенто: касса-hero, credits, «ждут подтверждения», события, быстрые действия) · Состав события (вкладки Состав / Платежи / Шеринг; для split — прогноз и «Закрыть запись и распределить») · Ожидают подтверждения · Касса · Создание тренировки (тип оплаты fixed / split) · Игроки (Активные / Заявки / Все) · Отчёт за месяц · Сборы → управление → создание · Уведомления · Создание организации.

Таб-бар игрока: Главная / Абонементы* / Сборы / Профиль. Таб-бар организатора: События / Игроки / Касса / Сборы / Меню. (*скрывается, если абонементы выключены.)

### 4. Кабинет организатора — `4 Кабинет организатора.html` (1440×900)
Сайдбар 240px + топбар (заголовок в одну строку без переноса, поиск ⌘K, колокольчик, аватар). Разделы: Обзор · События (список и календарь; несколько событий в дне — стопкой до 2, дальше «+N ещё» → лист выбора) · Создание события · Карточка события (для split — прогноз и распределение) · Игроки · Абонементы* · Касса + форма поступления / расхода · Сборы · Отчёты + экспорт · Credits & биллинг · Уведомления · Настройки (Профиль, Расписание по умолчанию, Записи и оплата, Залы, Способы оплаты, Уведомления, Telegram-бот, Опасная зона).

### 4b. Root Admin — `4b Root Admin.html`

### 6. Авторизация — `6 Авторизация.html` (+ `screens-auth.jsx`)
**Веб (7):** выбор способа (Telegram / email) · ввод 6-значного кода (10 мин, повтор через 60 с) · неверный код (осталось N попыток) · проверка · выбор организации · «Нет доступа — вы игрок» → Mini App · организация заблокирована (тикет).
**Mini App (4):** проверка initData · ошибка `AUTH_INITDATA_INVALID` · вошли, но групп нет · доступ к группе закрыт.
В Mini App **экрана логина нет**: личность берётся из подписанного `initData`. Email-код — резерв только для веба, без пароля.

### 9. Гипотезы для игроков — `9 Гипотезы для игроков.html` + `9.1…9.8`

## Состояние (кратко)
- Сессия: user, текущая организация, роль (`owner / organizer / player / guest`), тема.
- Настройки группы: `subscriptionsEnabled`, `maxSeatsPerPlayer` (3), `defaultPriceMode`, политика отмены (`allowed`, `cutoff`), способы оплаты.
- Событие: `priceMode`, `price` | `total`, `capacity`, `status (open / full / closed / past / cancelled)`, `closeBefore`, роспись мест (`bookings[] { userId, seats, payStatus, method }`), лист ожидания (очередь + TTL предложения).
- Уведомления: лента, `unread`.
- Серверные задачи: напоминания 24 ч / 2 ч, TTL листа ожидания, распределение split при закрытии записи, идемпотентность записи (`unique userId + eventId`) и webhook-списаний credits.

## Ассеты
- `assets/logo/` — знак «Галочка-подача»: `vt-mark-*` (цвет, на синем, ч/б, инверсия, на оранжевом), `vt-app-*` (иконки приложения), `vt-favicon.svg` (сам переключается в тёмной теме), `vt-apple-touch-icon.svg`. Полный комплект с логотипами и правилами — `8 Логотип — комплект.html`.
- Шрифты — Google Fonts: Oswald 500–700, Golos Text 400–700 (оба с кириллицей).
- Иконки — собственный stroke-набор в `atoms.jsx` (компонент `Icon`, SVG paths). Перенести в SVG-спрайт или компоненты. Стилистически совместим с Lucide.
