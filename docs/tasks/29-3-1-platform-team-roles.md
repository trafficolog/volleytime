# Task 29.3.1: Роли команды платформы

## Цель

Root Admin разросся: поддержка, модерация, жалобы, деньги, настройки. Вместо одного флага «root» у каждого члена команды платформы — роль, которая открывает только его разделы. Так поддержку и модерацию можно отдать людям без доступа к деньгам и настройкам.

- Analyst не видит персональных данных: контакты, Telegram, email пользователей скрыты в ответах API
- Owner на платформе — не меньше одного; последнего Owner нельзя понизить или удалить
- Смена роли действует со следующего запроса и пишется в аудит (кто, кому, было → стало)
- Разделы без доступа скрыты из меню; прямой адрес отдаёт «Нет доступа к разделу»
- В макете на страницах показаны действия Owner; у ролей с «просмотр» кнопки изменений скрыты

**Данные и API** (по спецификации; точные маршруты и имена — в контракте)

Модель данных меняется, поэтому первым шагом Opus пишет миграцию и контракт.

- `platform_staff(user_id, role, invited_by, created_at)` вместо флага `users.is_root_admin`; миграция переносит текущих root в `owner`
- Политики `requirePlatformRole(...roles)` на каждом маршруте `/api/platform/**` по матрице; тест, что каждый маршрут описан, как `idor.integration.test` для групп
- GET/POST/PATCH/DELETE `/api/platform/staff` — только Owner
- Аудит: `platform.staff.invited|role_changed|removed`

## Критерии приёмки

- ✅ Каждый маршрут `/api/platform/**` проверяет роль по матрице; маршрут без описания валит тест

- ✅ Последнего Owner нельзя понизить или удалить

- ✅ IDOR- и ролевые тесты на каждый новый эндпоинт
- ✅ Пять gates CODING_STANDARDS на tested revision; ревью `claude-opus-5-5` (обязательны тесты граничных случаев) без Critical/Important

## Решения реализации

- **Поиск Analyst без контактов** (владелец, 2026-11-25, ревью PR #354): в списке организаций (`GET /api/platform/organizations?q=`) Analyst не находит группу по email и Telegram владельца — иначе поиск был бы оракулом существования контакта. Поиск по названию, slug, городу и имени владельца остаётся. Другие маршруты со свободным поиском по контактам (пользователи, аудит) Analyst недоступны. Тест — `platform-roles.integration.test.ts`.
- **Принятые отклонения** (владелец, 2026-11-25):
  - `GET /api/platform/staff/me` доступен любому члену команды (политика `self`), а не только Owner.
  - Аудит: Finance видит только записи баланса и тарифов, Moderator и Support — пользователей и страниц групп; Owner и Admin — весь журнал; Analyst журнал не видит.
  - Аналитика функций (`feature-analytics`) входит в политику `overview` и доступна всем ролям.
  - RED шага контракта не зафиксирован отдельным коммитом; в раунде исправлений 1 RED поиска Analyst проверен локально до исправления.
- **UI «Команда & роли» (шаг 2, Sonnet):** по референсу в списке ролей Owner предлагают только действующему Owner (смена роли другого человека и приглашение Owner не назначают); список — таблицей `vt-team-table` кабинета, а не тремя карточками в ряд; матрица прав выводится из `PLATFORM_POLICIES`, тест сверяет её с матрицей карточки. Меню Root Admin и вкладки настроек строятся по `policies` из `GET /api/platform/staff/me`; пока роль грузится, меню пусто, при ошибке запроса показывается полное меню (доступ проверяет сервер). «Аналитика функций» остаётся в меню у всех ролей (политика `overview`).
- **Кнопки изменений по роли (шаг 3, Sonnet, #360):** composable `usePlatformCan()` (`can(policy)` поверх `usePlatformStaffMe()`, общий ключ `root-staff-me`, отдельного запроса нет) скрывает кнопки изменений на страницах `/root/**` по `PLATFORM_POLICIES`: страницы групп (скрыть, noindex, вернуть — `groupPagesModerate`), жалобы на страницы (меры — `groupPageComplaintsResolve`, отклонить — `groupPageComplaintsReject`), заявки на баланс, выдача баланса, безлимит организации (`balanceManage`), тарифы и пакеты (`plansManage`), создание организации (`organizationsManage`), блокировка пользователя (`usersManage`). Пока роль грузится и при ошибке `staff/me` кнопки изменений скрыты; доступ по-прежнему проверяет сервер. Настройки доступны только Owner и Admin (оба с правом изменения). Пункты «Изменить роль» и «Удалить из команды» у единственного Owner недоступны с пояснением. «Вход в организацию» (R-09) и страницы подписок с изменениями ещё не существуют: когда появятся, они берут `can('organizationEnter')` и `can('subscriptionsManage')`.
