# Task 29.3.1: Роли команды платформы

## Цель

Root Admin разросся: поддержка, модерация, жалобы, деньги, настройки. Вместо одного флага «root» у каждого члена команды платформы — роль, которая открывает только его разделы. Так поддержку и модерацию можно отдать людям без доступа к деньгам и настройкам.

## Контекст

- Спецификация референса: [R-15 · Роли команды платформы](../design/reference-v3/specs/04-root-admin/R-15-platform-team-roles.md); обновление референса — [отчёт 2026-11-24](../design/2026-11-24-reference-v3-update.md).
- Макет: 4b Root Admin → Настройки → Команда & роли: список команды, «Изменить роль», матрица прав; 4b Root Admin → Tweaks «Кто вошёл · R-15»: меню глазами каждой роли; Скриншоты: `screenshots-2026-11-24/4b-root-admin/24-nastroyki-komanda.png`, `33…36-R15-*`.
- **Как есть (main `69a5595`):** root — один флаг `users.is_root_admin` (`apps/web/server/utils/root-admin.ts`), `requireRootAdmin` на всех `/api/platform/**`; ролей команды нет.
- **Дельта до референса:** всё, что в «Что должно быть сделано»; работающее не переписывается.

- Analyst не видит персональных данных: контакты, Telegram, email пользователей скрыты в ответах API
- Owner на платформе — не меньше одного; последнего Owner нельзя понизить или удалить
- Смена роли действует со следующего запроса и пишется в аудит (кто, кому, было → стало)
- Разделы без доступа скрыты из меню; прямой адрес отдаёт «Нет доступа к разделу»
- В макете на страницах показаны действия Owner; у ролей с «просмотр» кнопки изменений скрыты

**Данные и API** (по спецификации; точные маршруты и имена — в контракте)

Модель данных меняется, поэтому первым шагом Opus пишет миграцию и контракт.

- `platform_staff(user_id, role, invited_by, created_at)` вместо флага `users.is_root_admin`; миграция переносит текущих root в `owner`
- Политики `requirePlatformRole(...roles)` на каждом маршруте `/api/platform/**` по матрице; тест, что каждый маршрут описан, как `idor.integration.test` для групп
- GET/POST/PATCH/DELETE `/api/platform/staff` — только Owner
- Аудит: `platform.staff.invited|role_changed|removed`

## Критерии приёмки

- ✅ Каждый маршрут `/api/platform/**` проверяет роль по матрице; маршрут без описания валит тест
- ✅ Support не может скрыть страницу группы, выставить noindex и выдать баланс — и в интерфейсе, и в API (403)
- ✅ Analyst не получает контактов пользователей ни в одном ответе
- ✅ Последнего Owner нельзя понизить или удалить
- ✅ Текущие root после миграции работают как Owner без повторного входа
- ✅ IDOR- и ролевые тесты на каждый новый эндпоинт
- ✅ Пять gates CODING_STANDARDS на tested revision; ревью `claude-opus-5-5` (обязательны тесты граничных случаев) без Critical/Important
