# Task 30.3.1: Передать место и запись с напарником

## Цель

Игрок сам находит замену, пары записываются вместе.

## Контекст

- Спецификация референса: [M-29 · Передать место и запись с напарником](../design/reference-v3/specs/02-mini-app/M-29-seat-transfer-partner.md); обновление референса — [отчёт 2026-11-24](../design/2026-11-24-reference-v3-update.md).
- Макет: 3 Mini App → Событие (записан) → ··· → Передать место; 3 Mini App → Событие (не записан) → ··· → Записаться с напарником.
- **Как есть (main `69a5595`):** передачи места другому игроку и записи с напарником нет; есть передача владения группой (другая сущность).
- **Дельта до референса:** всё, что в «Что должно быть сделано»; работающее не переписывается.
- Модель: реализация `claude-sonnet-5-5`, ревью `claude-opus-5-5` (обязательны тесты граничных случаев); маршрутизация — [ORCHESTRATION](../ORCHESTRATION.md).

## Что должно быть сделано

**Объём** (по спецификации)

- Передача: кому (@username или из группы), ссылка на 2 ч, место переходит после подтверждения; деньги возвращаются или зачитываются, когда новый игрок оплатит
- Напарник: запись создаётся только для двоих сразу; таймер 2 ч; при нехватке мест не создаётся

## Критерии приёмки

- ✅ Передача не задевает лист ожидания
- ✅ Отмена передачи возвращает место
- ✅ IDOR- и ролевые тесты на каждый новый эндпоинт
- ✅ Пять gates CODING_STANDARDS на tested revision; ревью `claude-opus-5-5` (обязательны тесты граничных случаев) без Critical/Important
