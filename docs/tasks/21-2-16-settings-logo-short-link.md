# Task 21.2.16: Логотип и короткая ссылка группы (`W-11`)

## Цель

Организатор загружает логотип группы и задаёт короткий адрес `volleytime.by/<имя>`; логотип показывается в приложении, адрес используют публичные страницы.

## Контекст

- Решение владельца 2026-10-15 (ревью PR #138, 20.5.7): часть макета W-11, которой нужна новая серверная работа, выделена из [20.5.7](20-5-7-settings.md) отдельной задачей v0.3.0; в v0.2.0 она не входит.
- Спецификация референса: [W-11 · Настройки](../design/reference-v3/specs/03-organizer-web/W-11-settings.md); макет: 4 Кабинет организатора → Настройки → Профиль, `4-cabinet/17-screen.png`; исходник — `WebSettings` в `handoff/screens-web.jsx`.
- **Как есть (main `35a43fd`):** В модели группы нет логотипа ([20.4.3](20-4-3-group-switcher.md) рисует монограммы), короткой ссылки нет; публичная страница группы — [24.1.2](24-1-2-group-page-render.md) (v0.5.0).
- **Дельта до референса:** Профиль: «Загрузить логотип» (PNG или SVG, до 1 МБ, квадратный) и «Короткая ссылка» с префиксом `volleytime.by/`. Задача только хранит и проверяет логотип и адрес; публичную страницу по адресу строит 24.1.2 в v0.5.0 и будет читать значения отсюда. Конфликта сроков нет: в v0.3.0 логотип показывается в шапке и шторке групп, адрес пока только сохраняется.
- Модель: реализация `claude-sonnet-5-5`, ревью `claude-opus-5-5` (ревью Opus: загрузка файлов и уникальные адреса); маршрутизация — [ORCHESTRATION](../ORCHESTRATION.md).

## Что должно быть сделано

1. Хранение файла логотипа: тип по содержимому (не по расширению), лимит 1 МБ, квадрат; SVG очищается от скриптов и внешних ссылок или конвертируется; если в проекте нет хранилища файлов — остановиться и вернуть задачу оркестратору.
2. Короткая ссылка: формат (строчные латинские буквы, цифры, дефис), уникальность по платформе, зарезервированные слова, смена с проверкой занятости; миграция forward-compatible.
3. API профиля группы: загрузка и удаление логотипа, чтение и смена адреса; права owner/organizer.
4. Подраздел «Профиль»: загрузка логотипа с предпросмотром, поле адреса с проверкой занятости; монограммы в шапке и шторке групп ([20.4.3](20-4-3-group-switcher.md)) заменяются логотипом, если он есть.
5. Сверить экраны с референсом через харнесс [19.0.2](19-0-2-visual-reference-harness.md) и приложить отчёт к PR.

## Критерии приёмки

- ✅ Файл неподходящего типа, размера или с исполняемым содержимым отклоняется; SVG не выполняет скрипты
- ✅ Адрес уникален, зарезервированные и занятые адреса отклоняются понятной ошибкой; гонка двух групп на один адрес даёт одну победившую
- ✅ Логотип виден в шапке и шторке групп; без логотипа остаётся монограмма
- ✅ IDOR-тесты на загрузку и смену адреса (чужая группа, роль без прав)
- ✅ Тесты: валидация файла, очистка SVG, уникальность адреса, компонентные на загрузку
- ✅ Отчёт визуальной сверки по экранам из `reference.screens` без открытых расхождений Critical/Important
- ✅ Пять gates CODING_STANDARDS на tested revision; ревью `claude-opus-5-5` без Critical/Important
