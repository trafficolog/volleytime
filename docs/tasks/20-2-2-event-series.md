# Task 20.2.2: Серии событий (`P-06`)

## Цель

Массовое создание событий по правилу повтора.

## Контекст

- Спецификация референса: [P-06 · Серии событий](../design/reference-v3/specs/01-platform/P-06-event-series.md); макет: 4 Кабинет → Создание события → Повтор; 3 Mini App → организатор → создание.
- **Как есть (main `e68acf2`):** Не реализовано: события создаются по одному.
- **Дельта до референса:** Правило повтора (handoff `RecurrenceBlock`: один раз / каждую неделю / раз в 2 недели × дни × срок), предпросмотр, исключения, правка «только это / это и последующие», конфликт зала → черновик, списание баланса за каждое событие по D-04.
- Решения владельца (2026-10-12): [D-04](../operations/decisions/2026-10-12-reference-v3-decisions.md#d-04) — серия создаётся атомарно целиком; баланс списывается за опубликованные, даты сверх баланса — черновики; предпросмотр показывает число публикуемых.
- Модель: реализация `claude-opus-5-5`, ревью `claude-opus-5-5` (ревью Opus + тесты граничных случаев и гонок); маршрутизация — [ORCHESTRATION](../ORCHESTRATION.md).

## Что должно быть сделано

1. Правило: дни недели, период (месяц, квартал, год, до даты, N раз)
2. Исключения (праздники, отменённые даты)
3. Предпросмотр дат перед созданием
4. Правка «только это» / «это и последующие»; отмена «это и последующие» одной командой — дата и все последующие, возврат баланса по D-09/D-13 и платежи по R0.7/20.1.2 для каждого события, детерминированный порядок блокировок `(series_date, id)` ([решение владельца 2026-10-15, D-04 (B)](../operations/decisions/2026-10-12-reference-v3-decisions.md#d-04))
5. Списание баланса за каждое опубликованное событие серии (D-04): серия создаётся целиком, даты сверх баланса — черновики; предпросмотр показывает, сколько будет опубликовано
6. Данные и API: POST /series; GET /series/{id}/preview; PATCH /series/{id}?scope=following. Пути по [ADR](../architecture/ADR-v3-domain.md#серии-и-черновики-2022-d-04): `POST …/series/preview` (без записи; число публикуемых, черновиков и баланс после — контракт 21.1.7), `POST …/series`, `GET …/series/{id}`, `PATCH …/series/{id}?scope=single|following&from=…`, `POST …/series/{id}/cancel`.
7. ~~Сверить экраны с референсом через харнесс [19.0.2](19-0-2-visual-reference-harness.md) и приложить отчёт к PR.~~ — перенесено решением владельца 2026-10-15 в 20.5.5 (`4-cabinet/05-screen.png`) и 21.1.2 (`3-miniapp-organizer/05-screen.png`) ([D-04, уточнение (A)](../operations/decisions/2026-10-12-reference-v3-decisions.md#d-04)).

## Критерии приёмки

- ✅ Создание серии из 52 событий выполняется одной операцией
- ✅ Серия создаётся атомарно целиком: при нехватке баланса опубликованы первые N дат, остальные — черновики; при сбое не создаётся ничего
- ✅ Отмена «это и последующие» одной командой: атомарно, повтор безопасен, возврат баланса по D-09/D-13 за каждое событие; гонка отмены и записи на более позднюю дату не оставляет активных записей на отменённых событиях
- ~~✅ Отчёт визуальной сверки по экранам из `reference.screens` без открытых расхождений Critical/Important~~ — перенесено решением владельца 2026-10-15 в 20.5.5 и 21.1.2
- ✅ Пять gates CODING_STANDARDS на tested revision; ревью `claude-opus-5-5` без Critical/Important
- ✅ RED→GREEN тесты на граничные случаи, деньги/доступ и конкурентность приложены к PR

## Примечания реализации

- **Перенесено решением владельца 2026-10-15 ([D-04, уточнение](../operations/decisions/2026-10-12-reference-v3-decisions.md#d-04)):** визуальная сверка (п. 7, критерий отчёта) — в [20.5.5](20-5-5-event-create.md) и [21.1.2](21-1-2-org-event-create.md); проверка отката — [20.7.1](20-7-1-release-v0-2-0-qa.md), п. 8.
- **Флага нет:** даты серии — обычные события, прежний runtime работает с ними без изменений (ADR, правило совместимости 4). Откат миграции 0027 отказывает, пока есть строки `event_series`.
- **Решения координатора 2026-10-15** (записаны в ADR): конфликт зала — тот же `venue_id`, пересечение `[starts_at, ends_at)` с неотменённым событием группы, включая более ранние даты серии; без зала — нет конфликта. Предпросмотр — `POST …/series/preview` с `balanceAfter`.
- **Вне карточки:** массовая публикация черновиков после пополнения баланса — по одному через `PATCH …/events/{id}` (списание при публикации); пакетной публикации серии нет.
