# Task 22.1.6: Экспорт журнала платформы в JSON и глобальный поиск шапки Root Admin

## Цель

Дать root выгрузку журнала платформы в JSON по текущим фильтрам и рабочий глобальный поиск в шапке Root Admin, как в макете.

## Контекст

- Решение владельца 2026-11-19 ([D-17](../operations/decisions/2026-10-12-reference-v3-decisions.md#d-17)): экспорт и поиск шапки выделены из [22.1.2](22-1-2-audit-log.md) в отдельную карточку бэклога; релиз не назначен.
- Макеты: [4b-root-admin/11-screen.png](../design/reference-v3/screenshots/4b-root-admin/11-screen.png) (кнопка «Экспорт JSON»), [4b-root-admin/01-screen.png](../design/reference-v3/screenshots/4b-root-admin/01-screen.png) (поиск в шапке); спецификация [R-07](../design/reference-v3/specs/04-root-admin/R-07-audit-log.md).
- **Как есть:** страница `/root/audit` и `GET /api/platform/audit` (22.1.2) отдают журнал постранично с редактированием секретов в `old/new` (`redactAuditValue`); экспорта нет, поле поиска шапки не подключено.
- **Секреты:** экспорт обязан использовать то же скрытие секретов, что и экран, без обходных путей; IP и user-agent не выгружаются.
- Задача касается доступа root и выгрузки данных: ревью `claude-opus-5-5` с тестами (правило 2 [ORCHESTRATION](../ORCHESTRATION.md)).

## Что должно быть сделано

1. Определить в карточке до кода: формат файла JSON (поля записи, метаданные: период, фильтры, число записей, время выгрузки), предел числа записей и поведение при превышении, имя файла.
2. Серверный маршрут экспорта только для root (`requireRootAdmin`, 401/403 `forbidden.root_only`, `no-store`), с теми же фильтрами, что у списка; пропуск записей идёт через то же скрытие секретов, что и список, а не через отдельную копию правил. Расширение правил скрытия из follow-ups 22.1.2 применяется и к экспорту.
3. Кнопка «Экспорт JSON» на `/root/audit`: скачивает файл по текущим фильтрам.
4. Глобальный поиск шапки Root Admin: определить область (организации, пользователи, записи журнала) и ссылаться только на уже существующие разделы Root Admin; результаты видит только root, пустой и короткий запрос не обращаются к серверу.
5. Тесты: скрытие секретов в экспорте (токены, пароли, коды, ссылки, ключ `__proto__`); фильтры совпадают со списком; предел записей; доступ (401, 403); поиск не отдаёт данные не-root.
6. Сверить экраны с референсом вручную (десктоп 1440x900 и мобильный 375x812, отчёт в теле PR) по [D-16](../operations/decisions/2026-10-12-reference-v3-decisions.md#d-16).

## Критерии приёмки

- ✅ Файл экспорта не содержит секретов, IP и user-agent; тест сравнивает вывод экспорта с выводом списка
- ✅ Экспорт и поиск недоступны не-root; журнал остаётся только на чтение
- ✅ Отчёт визуальной сверки по экранам 4b-root-admin/11 и 01 без открытых расхождений Critical/Important
- ✅ Пять gates CODING_STANDARDS на tested revision; ревью `claude-opus-5-5` без Critical/Important
