# Task 24.2.1: Адреса страниц групп /{город}/{группа}

## Цель

Страница группы открывается по адресу `volleytime.by/{город}/{группа}`, старые адреса ведут на новые без потери индексации.

## Контекст

- Спецификация референса: [R-06 · Страница группы · рендер](../design/reference-v3/specs/03-organizer-web/W-14-group-page-render.md); обновление референса — [отчёт 2026-11-24](../design/2026-11-24-reference-v3-update.md).
- **Как есть (main `69a5595`):** страница группы — `/g/<slug>`, каталог — `/volleyball/<город>`, короткая ссылка `/<имя>` (302), sitemap и canonical — по этим адресам (24.1.2, `v0.5.0`).
- **Дельта до референса:** всё, что в «Что должно быть сделано»; работающее не переписывается.
- Решения владельца: [D-26](../operations/decisions/2026-10-12-reference-v3-decisions.md#d-26).
- Модель: реализация `claude-opus-5-5`, ревью `claude-opus-5-5` (обязательны тесты граничных случаев); маршрутизация — [ORCHESTRATION](../ORCHESTRATION.md).

## Что должно быть сделано

**Шаги (правило 3 [ORCHESTRATION](../ORCHESTRATION.md#маршрутизация-моделей)):** контракт — `claude-opus-5-5`: история адресов, маршруты и редиректы, проверки slug; затем правки кабинета (выбор города) — `claude-sonnet-5-5`.

**Объём** (по спецификации)

- Маршрут `/{город}/{группа}`: город — slug районного центра из каталога (W-13), группа — slug группы
- 301 с `/g/<slug>` на новый адрес; короткая ссылка `/<имя>` ведёт на новый адрес
- Смена города или slug группы владельцем — 301 со старого адреса (история адресов)
- Каталог города, sitemap, canonical, OG, ссылки в боте и кабинете — на новые адреса
- Скрытая root страница (24.1.3) отдаёт 404 и по новому, и по старому адресу
- Конфликт slug города с зарезервированными путями (`/app`, `/m`, `/e`, `/api`, `/help`) — проверка при выборе

## Критерии приёмки

- ✅ Старый адрес отвечает 301 на новый, новый — 200; скрытая страница — 404 по обоим
- ✅ В sitemap только новые адреса
- ✅ Смена slug не ломает старые ссылки
- ✅ IDOR- и ролевые тесты на каждый новый эндпоинт
- ✅ Пять gates CODING_STANDARDS на tested revision; ревью `claude-opus-5-5` (обязательны тесты граничных случаев) без Critical/Important

## Решения реализации

Владелец, 2026-11-25 — четыре отклонения приняты как есть:

1. Группа без города или с городом вне справочника остаётся на `/g/<slug>` (200); каталог такого города — на `/volleyball/<город>`.
2. Город — `datalist` вместо выпадающего списка W-13; мобильные настройки не меняются; API принимает город свободным текстом.
3. Slug меняется только через API, поля в UI нет.
4. Существующие короткие ссылки, совпавшие со slug города, продолжают работать и перекрывают каталог `/<город>`; новые такие ссылки запрещены (раунд 1 ревью).

## Короткие ссылки, совпавшие со slug города

Новая короткая ссылка не может совпасть со slug города справочника (тот же `ShortLinkReservedError`, что для зарезервированных слов; при создании и изменении). Ссылки, заданные до 24.2.1, не удаляются и не переименовываются: middleware `short-link` отвечает на `/<город>` 302 раньше каталога, пока такая ссылка существует. Найти их (список slug — `GROUP_PAGE_CITY_SLUGS` из `@volley-time/shared`):

```sql
SELECT id, name, slug, short_link
FROM organizations
WHERE short_link = ANY (ARRAY['minsk', 'brest', 'pinsk' /* … все GROUP_PAGE_CITY_SLUGS */]);
```

Решение владельца 2026-11-25 (п. 4 выше): найденные ссылки оставить как есть.
