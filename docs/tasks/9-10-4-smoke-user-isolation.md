# Task 9.10.4: Smoke не оставляет обычного пользователя в боевой базе

## Цель

Проверка входа после деплоя не засоряет данные группы.

## Контекст

Smoke логинится настоящим Telegram id и создаёт пользователя при каждом деплое.

## Что должно быть сделано

1. Пометка технического аккаунта: `users.is_smoke` (или `name = 'Smoke check'` + фиксированный id в `SMOKE_TG_ID`), исключение из списков участников не требуется — он никуда не вступает.
2. Smoke после проверки делает `POST /api/internal/smoke/cleanup` (внутренний секрет): удаляет сессии smoke-пользователя.
3. Документировать в runbook: какой id используется и как его найти.

## Критерии приёмки

- ✅ После smoke в БД нет новых сессий smoke-аккаунта
- ✅ Аккаунт помечен и описан в runbook

## Подсказки

- Полное удаление пользователя невозможно из-за RESTRICT на платежах — достаточно пометки и очистки сессий.

## Не делать

- ❌ Не удалять пользователей боевой базы скриптом
