# Task 28.1.7: Граф в ролях агентов

## Цель

Каждая роль (оркестратор, исполнитель, ревьюер, визуальный QA) использует граф там, где он экономит чтение и находит влияние изменения, и не опирается на него там, где он слеп.

## Контекст

- Правило обновления — [28.1.5](28-1-5-graphify-agent-workflow.md), раздел [ORCHESTRATION](../ORCHESTRATION.md#граф-знаний-graphify). Действующий граф — в worktree `.claude/worktrees/graphify`; исполнитель и ревьюер работают в своих worktree и о графе из шаблонов промптов и `.claude/agents/` раньше не узнавали.
- Сильные и слабые стороны — [базовая линия 28.1.3](../guides/graphify.md#базовая-линия-2813-2026-11-20): граф надёжен на уровне файлов и экспортируемых функций (импортёры, путь «эндпоинт → сервис → таблица»); методы объектов-сервисов (`bookingService.cancel`) узлами не являются, «кто вызывает метод» — только поиском по коду.
- Проверено 2026-11-22 на 0.9.103: `query`, `affected`, `explain`, `path` принимают `--graph <путь>`; запрос из worktree задачи к общему графу работает. `affected <файл>` на `--depth 1` останавливается на barrel `index.ts` (`re_exports`); `--depth 2` с фильтром тестов даёт реальных вызывающих (26 строк для `ledger/service.ts`), `--depth 3` — около 300 строк шума. Агенты запускают команды в bash: нужна bash-форма пути к графу.
- Решение владельца — дополнение [D-22](../operations/decisions/2026-10-12-reference-v3-decisions.md#d-22) от 2026-11-22.

## Что должно быть сделано

1. Правила по ролям в ORCHESTRATION: оркестратор строит карту влияния карточки и передаёт её исполнителю, сравнивает карты при параллельном запуске, обновляет граф после закрытия; исполнитель ориентируется по карте и графу, затем читает файлы, в PR — раздел «Влияние»; ревьюер ищет графом вызывающих вне diff и проверяет их по коду; визуальный QA — по желанию, поиск других экранов с изменённым компонентом.
2. Шаблоны промптов исполнителя и ревьюера и определения `.claude/agents/` ссылаются на эти правила.
3. Guide: путь к общему графу из любого worktree, глубина для barrel-модулей, ограничения.
4. Без графа (не установлен, нет `.built-sha`) работа не блокируется: роль отмечает это и работает поиском.
