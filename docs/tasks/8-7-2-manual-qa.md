# Task 8.7.2: Manual QA чеклист + прогон в Telegram

## Цель

Чеклист полного MVP-сценария (игрок + организатор). Прогон в реальном Telegram на iOS и Android. Проверка MVP-критерия: неделя тренировок только через Mini App.

## Контекст

Telegram-specific вещи (initData реально приходит, MainButton рендерится на iOS/Android, web_app deeplinks открываются, haptics работают) нельзя проверить автотестами — только вручную в реальном клиенте. Это гейт перед Phase 9 (deploy).

## Что должно быть сделано

1. **QA чеклист — Организатор (создаёт и ведёт):**

   ```
   [ ] /start в боте → приветствие + кнопка Mini App
   [ ] Открытие Mini App → авто-логин (без формы)
   [ ] Создание организации
   [ ] Создание площадки (venue)
   [ ] Создание subscription plan (платный + бесплатный)
   [ ] Создание события (с venue, capacity, price, deadline)
   [ ] MainButton «Создать событие» работает
   [ ] Поделиться событием: /start event_<id> в боте → preview + открытие
   [ ] Просмотр записей события
   [ ] Подтверждение pending оплаты → игрок получает уведомление
   [ ] Отметка посещаемости (attended/no_show) + bulk сохранение
   [ ] Касса: баланс, история, добавление расхода
   [ ] Отмена события → участники получают уведомление, mass refund
   ```

2. **QA чеклист — Игрок:**

   ```
   [ ] Переход по invite-ссылке (org_) → присоединение
   [ ] Открытие Mini App → авто-логин
   [ ] Просмотр списка событий (индикаторы мест)
   [ ] Покупка абонемента (платный → pending, бесплатный → active)
   [ ] Запись на событие с абонемента (MainButton «Записаться»)
   [ ] Запись с оплатой на месте (pending_payment)
   [ ] Запись на заполненное → лист ожидания (orange кнопка)
   [ ] Получение уведомления о подтверждении записи
   [ ] Waitlist promotion: отмена другим → я попадаю в состав → уведомление
   [ ] Мои записи (upcoming/past)
   [ ] Отмена записи (до дедлайна) → восстановление сессии
   [ ] Отмена после дедлайна → блокируется
   [ ] Мои абонементы (остаток, срок)
   ```

3. **Платформы:**

   ```
   [ ] iOS Telegram: авто-логин, MainButton, BackButton, haptics, тема
   [ ] Android Telegram: то же
   [ ] Desktop Telegram: базовая работа (MainButton может отличаться)
   [ ] Браузер (вне Telegram): email fallback логин, in-page кнопки
   [ ] Light тема: читаемость
   [ ] Dark тема: читаемость
   ```

4. **Telegram-specific проверки:**

   ```
   [ ] initData приходит и валидируется (реальный клиент)
   [ ] MainButton рендерится нативно, loading-прогресс работает
   [ ] BackButton навигация назад
   [ ] web_app deeplinks открывают правильный экран
   [ ] Уведомления приходят (bot шлёт, не в спам)
   [ ] Кнопки в уведомлениях открывают нужный экран
   [ ] Haptic feedback ощущается (запись, успех, ошибка)
   [ ] Offline баннер при потере сети
   ```

5. **MVP-критерий (главный):**

   ```
   [ ] Соло-разработчик провёл неделю тренировок СВОЕЙ группы
       только через Mini App, без Python-прототипа/Excel:
       - создал события на неделю
       - игроки записались
       - вёл состав, отмечал посещаемость
       - принимал оплаты, вёл кассу
       - всё работало без критичных багов
   ```

6. **Результат:** документ с найденными проблемами (severity: blocker/major/minor), решение по каждой (fix сейчас / backlog / Phase 9-10).

## Критерии приёмки

- ✅ Чеклист организатора пройден
- ✅ Чеклист игрока пройден
- ✅ iOS + Android Telegram проверены
- ✅ Light + dark темы читаемы
- ✅ Браузерный fallback работает
- ✅ Telegram-specific (initData, MainButton, deeplinks, уведомления, haptics) работает в реальном клиенте
- ✅ MVP-критерий: неделя тренировок только через Mini App — выполнимо
- ✅ Найденные проблемы задокументированы с severity и решением
- ✅ Нет blocker-проблем (или исправлены)

## Подсказки

- **Manual QA незаменим для Telegram** — initData, MainButton, web_app кнопки, haptics работают только в реальном клиенте. Эмулятор/браузер не покрывает.
- **MVP-критерий — реальный прогон.** Лучший тест — провести настоящую неделю тренировок. Это и QA, и Трек B (UX-валидация) одновременно.
- **iOS vs Android отличия** — MainButton, safe areas, клавиатура могут вести себя по-разному. Проверить оба.
- **Severity-триаж** — не все баги блокируют MVP. Blocker (нельзя пользоваться) → fix. Minor (косметика) → backlog.

## Не делать

- ❌ Не делать E2E автоматизацию (Phase 9) — manual для MVP
- ❌ Не блокировать на minor-багах
- ❌ Не пропускать реальный прогам (MVP-критерий)
- ❌ Не тестировать только в браузере (Telegram-specific пропустишь)
