# Task 21.4.13: Цена за час в залах (DEF-23)

## Цель

Хранить и показывать цену за час зала («15 Br/ч» макета) в «Настройки → Залы».

## Контекст

- DEF-23, Important: [бэклог 21.4.1](../operations/reviews/2026-11-11-defects-v0-2-v0-3.md), [отчёт 21.2.13](../operations/qa/2026-11-05-21-2-13-settings-venues-visual.md). Решение владельца 2026-11-05: функция v0.3.1; решение 2026-11-16 ([журнал](../operations/decisions/2026-10-12-reference-v3-decisions.md)) перенесло её в `v0.4.0`, `v0.3.1` схемных задач не содержит.
- Нужна миграция (колонка в `venues`), поэтому по ORCHESTRATION («Параллельность», правило 3) схему и контракт сначала задаёт `claude-opus-5-5` (ADR), затем API и форма. Не входит в 21.4.2.

## Что должно быть сделано

1. ADR: тип и единица хранения цены (минорные единицы, валюта группы), nullable, обратная совместимость.
2. Миграция `venues`, схема Zod, API создания/правки зала, список залов.
3. Форма и список «Настройки → Залы»: поле и подпись «N BYN/ч».
4. Тесты: RED→GREEN, граничные значения (0, максимум, пусто), доступ (IDOR) на изменённые эндпоинты.

## Критерии приёмки

- ✅ Цена за час сохраняется и отображается; пустая допустима
- ✅ Миграция forward-compatible, применима к данным production
- ✅ Тесты доступа на каждый затронутый эндпоинт; пять gates CODING_STANDARDS

## Не делать

- ❌ Не менять другие поля залов и не трогать расчёт цены события
- ❌ Не запускать параллельно с другой схемной задачей
