# Task 8.10.1: Mini App игрока v2

## Цель

Привести MVP-потоки игрока к `3 Mini App.html` / `screens-player.jsx`.

## Контекст

Структура home, события, выбора записи/оплаты, абонементов и профиля в [v2](../design/2026-09-23-reference-v2.md) частично отличается от текущих Vue-экранов. [Утверждённый дизайн реализации](../superpowers/specs/2026-09-24-player-miniapp-v2-design.md) и [план](../superpowers/plans/2026-09-24-player-miniapp-v2.md) фиксируют маршруты и границу между MVP и макетными данными до написания кода.

## Карта экранов MVP к очищенному референсу

| Секция `screens-player.jsx`                         | Рабочий маршрут / поле API                                                                     | Применяемая композиция и исключения макета                                                                                                                                                                                      |
| --------------------------------------------------- | ---------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| PlayerHome: группа, главный hero, расписание        | `/m/orgs/[orgId]`; `organizations/[orgId]`, `dashboard.upcoming`, `myBookings`, `subscription` | Реальная группа и ближайшее опубликованное событие, затем остальные события и явная ссылка «Все события». Не переносить вымышленное приветствие, 96% посещаемости, несуществующий notification badge или fallback-событие.      |

Исключить split-price, уровень игрока, несколько мест, карты/календарь без реализации.                                                      |

При выключении — только чтение действующего остатка и истории; без остатка пункт tab bar скрыт, прямая авторизованная ссылка остаётся. Нет передачи абонемента или онлайн-оплаты.        |

Нет вымышленного организатора и автопринятия без ответа API.                                     |

Список событий `/m/orgs/[orgId]/events` остаётся отдельным достижимым маршрутом из Home, а навигация игрока — Главная, Записи, условные Абонементы, Профиль. Организаторскую панель вкладок меняет задача 8.10.2, не эта.

## Что должно быть сделано

1. Сопоставить реальные маршруты игрока с home, event, booking, subscriptions, profile/onboarding; зафиксировать визуальные различия по секциям.
2. Обновить композицию экранов, карточки, состояния empty/loading/error, навигацию и CTA по v2, сохраняя реальные данные и серверные разрешения.
3. TDD для записи, ожидания, отмены, оплаты и переходов; visual smoke на 320/390 px, светлую и Telegram-тёмную тему.
4. Следовать настройке абонементов группы из 5.13.21: при отключении оставлять просмотр действующего остатка без покупки/нового списания, а без действующего остатка скрывать раздел из навигации.

## Критерии приёмки

- MVP-потоки игрока доступны без тупиков и визуально соответствуют v2 по структуре и состояниям.
- Данные и статусы берутся из API, не из прототипных моков.
- Смена группы немедленно пересчитывает видимость абонементов по данным именно выбранной организации.
- Пять gates зелёные и Telegram Mini App QA отмечен отдельно от репозиторных тестов.

## QA-дефект, обнаруженный 2026-09-24

- В локальном браузере после записи на платное событие кнопка «Отменить запись» не выполняла действие: SDK Telegram присутствует, но вне Telegram `initData` пуст, а вызов `showConfirm` отклоняется с `WebAppMethodUnsupported` (клиентская версия 6.0). До завершения 8.10.1 требуется подтверждение через браузерный диалог вне Telegram и совместимый fallback в старых Telegram-клиентах, с RED → GREEN тестом и повторным browser smoke отмены.
