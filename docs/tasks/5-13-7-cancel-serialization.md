# Task 5.13.7: Параллельные отмены: advisory lock события и SKIP LOCKED при промоушене

## Цель

Одна освободившаяся позиция — один продвинутый игрок.

## Контекст

4 из 5 прогонов: один игрок получил 2 pending-платежа, второй остался в листе при свободном месте.

## Что должно быть сделано

1. `cancel`: `pg_advisory_xact_lock(eventId)` до чтения брони; повторная проверка статуса после лока.
2. `promoteFromWaitlist`: подсчёт мест и выбор следующего после лока; выбор `FOR UPDATE SKIP LOCKED`.
3. Конкурентный тест: N занятых мест, N параллельных отмен, N+1 в листе → продвинуты ровно N разных игроков, у каждого ≤1 pending-платёж.

## Критерии приёмки

- ✅ Тест гонки стабилен на 5 прогонах

## Подсказки

- Тот же ключ лока, что в `book` — запись и отмена сериализуются вместе.

- ❌ Не использовать SERIALIZABLE для всей БД
