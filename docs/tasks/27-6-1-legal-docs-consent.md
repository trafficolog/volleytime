# Task 27.6.1: Политика конфиденциальности, соглашение и согласие при первом входе

## Цель

У пользователя есть доступ к правовым документам, а платформа хранит факт и версию его согласия.

## Контекст

- Замечание `PD-01`, `PROD-11` [аудита 2026-11-10](../operations/reviews/2026-11-10-project-audit.md); фаза [27](../phases/27-audit-hardening.md).
- **Как есть:** в коде нет страниц политики и соглашения, согласия и его хранения.
- Хранятся: Telegram ID и username, email, имя, история записей и платежей, уровни.
- `docs/PLATFORM_VISION.md` («Решения», п. 3 и 6): география РБ и РФ, юрисдикция не выбрана. От AQ-2 зависят требования (локализация данных, форма согласия).
- Тексты документов предоставляет владелец (или юрист); агент делает страницы, хранение и экран согласия.
- Открытые решения владельца: AQ-2 ([фаза 27, «Открытые вопросы»](../phases/27-audit-hardening.md#открытые-вопросы-владельца)). Карточка с открытым решением не стартует.
- Модель: реализация `claude-sonnet-5-5`, ревью `claude-opus-5-5` (юридические тексты утверждает владелец); маршрутизация — [ORCHESTRATION](../ORCHESTRATION.md).

## Что должно быть сделано

1. Подготовить для AQ-2 перечень обрабатываемых данных и целей (по схеме БД) — основа для текста политики.
2. Публичные страницы `/privacy` и `/terms` (SSR, ссылки в подвале лендинга, на экране входа и в профиле).
3. Хранение согласия: версия документа, время, способ входа; миграция — по правилам (схема — `claude-opus-5-5`).
4. Экран согласия при первом входе и при смене версии; без согласия — только просмотр документов.
5. Тесты: без согласия API возвращает понятную ошибку; смена версии запрашивает повторное согласие.

## Критерии приёмки

- ✅ Документы доступны без входа
- ✅ Согласие с версией хранится и запрашивается при смене (тесты)
- ✅ Тексты утверждены владельцем
- ✅ Пять gates CODING_STANDARDS на tested revision; ревью `claude-opus-5-5` без Critical/Important; итог принят владельцем
