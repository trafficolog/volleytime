# Task 5.13.21: Включение абонементов на уровне организации

## Цель

Дать владельцу возможность временно отключить новые продажи и использование абонементов в группе, сохранив купленные остатки и историю. [Согласованный дизайн](../superpowers/specs/2026-09-24-organization-subscriptions-toggle-design.md).

## Контекст

Сейчас у организации нет признака доступности абонементов: покупка и запись с них разрешены на любом платном событии. Простое скрытие интерфейса не защищает прямые API-запросы и может скрыть оплаченный остаток. В референсе v2 есть общий переключатель группы; отдельного переключателя события в MVP не будет.

## Что должно быть сделано

1. Добавить миграцию и поле `subscriptionsEnabled` у организации с `NOT NULL DEFAULT true`, расширить валидацию PATCH и аудит изменения; сохранить owner-only право на запись.
2. При `false` предметно отклонять сервером создание новых планов, покупку абонемента и новую запись с методом `subscription`. Не менять cash/transfer/free и существующие подтверждённые записи или очередь, оформленную до переключения.
3. Добавить переключатель и пояснение в текущие настройки группы. В текущем Mini App скрывать предложения покупки и способ оплаты абонементом. Пункт «Абонементы» оставлять только при наличии действующего остатка, показывая его без покупки; при отсутствии остатка скрывать. Прямая ссылка на собственные данные остаётся читаемой.
4. При повторном включении снова разрешить покупки и использование действующих неистёкших остатков без изменения их срока, количества и истории. Состояние брать из API текущей организации; ошибка загрузки не должна открывать запрещённые действия.
5. TDD: сервисные, API и UI-тесты на оба значения, owner-only право, остаток/без остатка, подтверждение ранее оформленной pending-покупки, прямой URL, смену группы, уже оформленные записи, очередь, отмену и повторное включение.

## Критерии приёмки

- После миграции существующие организации продолжают работать с абонементами; переключение сохраняется и аудируется. Владелец может менять настройку, другие роли не могут.
- При отключении новые покупка/план/запись с абонементом отвергаются в core/API независимо от UI; cash, transfer и free не ломаются.
- Купленные абонементы, остатки, pending и история не удаляются. Действующий остаток виден игроку без возможности новой покупки или выбора его при новой записи; без действующего остатка пункт меню скрыт. Прямая авторизованная ссылка остаётся доступной для истории.
- Ранее оформленные подтверждённые записи и очередь сохраняют условия; отмена корректно возвращает сессию. При повторном включении действующий неистёкший остаток снова доступен.
- Пять gates (`format:check`, `lint`, `typecheck`, `test`, `build`) зелёные. Визуальный smoke 320/390 px и Telegram QA фиксируются отдельно; tests не выдаются за production-проверку.

- Не считать скрытие кнопки достаточной серверной защитой.
