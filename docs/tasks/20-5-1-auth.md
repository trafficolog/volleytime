7. Кнопка Telegram Login Widget (D-05). Бэкенд готов в 19.3.1: `POST /api/auth/sign-in/telegram-widget`, выключен флагом `TELEGRAM_LOGIN_WIDGET_ENABLED` (404, пока выключен).
   - Подключать **только через JS-колбэк Telegram.Login.auth** (не `data-auth-url` и не `data-onauth` — eval запрещён CSP): своя кнопка вызывает `Telegram.Login.auth({ bot_id, request_access: false }, cb)` из `telegram-widget.js`, `cb` отправляет данные на эндпоинт. `data-auth-url` не использовать — подписанные данные попадут в URL, логи и историю браузера; `data-onauth` не использовать — скрипт Telegram превращает строку в функцию через eval, а CSP в Caddyfile без `'unsafe-eval'` (и добавлять его нельзя). `bot_id` — числовой публичный префикс токена бота, отдаётся `GET /api/auth/login-options` только при включённом флаге.
   - По желанию: отклонять повторно использованный `hash` виджета в пределах срока жизни (защита от повтора).
   - Перед включением флага в production (действия владельца): BotFather `/setdomain` для production-домена; прокинуть `TELEGRAM_LOGIN_WIDGET_ENABLED` и `TELEGRAM_LOGIN_WIDGET_MAX_AGE_SECONDS` в `docker-compose.prod.yml` и deploy workflow (флаг проведён 2026-10-26: `render-production-env.mjs` + одна строка `vars.*` в `deploy.yml`, Compose не меняется, значение выключено; `…_MAX_AGE_SECONDS` не проводится, действует умолчание 3600); выкатка через **Promote to production**. Порядок — раздел «Включение в production» карточки 19.3.1.
