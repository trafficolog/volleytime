# Task 21.2.12: Расписание по умолчанию: шаблоны слотов (`W-11`)

## Цель

Организатор хранит регулярные слоты группы (день недели, время, формат, зал) и создаёт по ним события и серии в один шаг.

## Контекст

- Решение владельца 2026-10-15 (ревью PR #138, 20.5.7): часть макета W-11, которой нужна новая серверная работа, выделена из [20.5.7](20-5-7-settings.md) отдельной задачей v0.3.0; в v0.2.0 она не входит.
- Спецификация референса: [W-11 · Настройки](../design/reference-v3/specs/03-organizer-web/W-11-settings.md); макет: 4 Кабинет организатора → Настройки → Расписание по умолчанию, `4-cabinet/18-screen.png`; исходник — `WebSettings` в `handoff/screens-web.jsx`.
- **Как есть (main `35a43fd`):** Шаблонов расписания нет: каждое событие и серия создаются вручную (серии — [20.2.2](20-2-2-event-series.md), форма — [20.5.5](20-5-5-event-create.md)).
- **Дельта до референса:** Список слотов с добавлением, изменением и удалением; слот подставляется в форму создания события и серии. Решение карточки: шаблоны только заполняют форму создания, события автоматически не появляются — автосоздание впрок списывает баланс событий (D-04) и вынесено в backlog.
- Модель: реализация `claude-sonnet-5-5`, ревью `claude-opus-5-5` (ревью Opus: tenant safety настроек группы); маршрутизация — [ORCHESTRATION](../ORCHESTRATION.md).

## Что должно быть сделано

1. Модель и API шаблонов слота группы (день недели, время, название или формат, зал, число мест); права owner/organizer; миграция forward-compatible.
2. Подраздел «Расписание по умолчанию»: список слотов, добавить, изменить, удалить слот, «Сохранить».
3. В форме создания события и серии ([20.5.5](20-5-5-event-create.md)) выбор слота подставляет поля; дальнейшее создание идёт существующим контрактом [20.2.2](20-2-2-event-series.md) со списанием по D-04.
4. Сверить экраны с референсом через харнесс [19.0.2](19-0-2-visual-reference-harness.md) и приложить отчёт к PR.

## Критерии приёмки

- ✅ Слот подставляет в форму день, время, зал и места; созданное событие совпадает со слотом
- ✅ Шаблон не создаёт события сам и не списывает баланс
- ✅ Tenant safety: слоты видны и меняются только в своей группе; тест на чужую группу
- ✅ Тесты: CRUD слотов, граничные значения времени и мест, компонентные на список и подстановку
- ✅ Отчёт визуальной сверки по экранам из `reference.screens` без открытых расхождений Critical/Important
- ✅ Пять gates CODING_STANDARDS на tested revision; ревью `claude-opus-5-5` без Critical/Important
