## Follow-ups

Не входят в критерии приёмки 22.1.4 и берутся отдельными задачами.

- **Решения владельца 2026-11-19 (чат).** Пользователь №4 в production — технический smoke-аккаунт; он включается обратно шагом prepare при каждом деплое («re-enable on each deploy»), это заменяет прежнее «оставить заблокированным» (сказано до того, как стало известно, что №4 — smoke-аккаунт). Если root заблокирует smoke-аккаунт вручную, следующий деплой его включит; вывести аккаунт из обращения можно только снятием `SMOKE_TG_ID`.
- **Release gate v0.4.0.** До Promote выполнить read-only проверку production: нет ли других пользователей с `is_active = false`, которых никто не блокировал намеренно (до 22.1.4 флаг ничего не запрещал, а бот его читал), например `SELECT id, name, telegram_username, created_at FROM users WHERE NOT is_active`. Каждого найденного либо включить по решению владельца, либо подтвердить как намеренно заблокированного. Проверку и результат записать в evidence выпуска.
- P2: поиск в списке пользователей использует `ILIKE '%…%'` по имени, email и Telegram без индексов, а счётчики и сводка считаются коррелированными подзапросами. На тысячах пользователей перенести на триграммные индексы (`pg_trgm`) и агрегаты через join.
- P2: в журнале платформы 22.1.2 нет категории «Пользователи» для фильтра; записи `user.blocked` и `user.unblocked` видны только без фильтра по разделу.
- P2 (hardening, замечание ревьюера): `/api/internal/smoke/prepare` и `/api/internal/smoke/cleanup` принимают `telegramUserId` из тела запроса и защищены только внутренним секретом и проверками аккаунта (не root, без членств, имя «Smoke check»). Привязать оба шага к серверной переменной `SMOKE_TG_ID` (тело запроса не выбирает аккаунт), чтобы утечка секрета не позволяла включить или почистить чужой аккаунт с таким именем.
- Negligible: UPDATE шага prepare повторяет условия «не root» и имя, но не условие «нет членств» из предшествующей выборки, поэтому между проверкой и UPDATE теоретически возможна гонка (аккаунт успевает вступить в группу). Добавить условие `NOT EXISTS` членства в UPDATE вместе с привязкой к `SMOKE_TG_ID`.
- Вне scope (решения владельца ожидаются): экспорт CSV, «Связаться в Telegram», причина блокировки (поле и показ пользователю).
