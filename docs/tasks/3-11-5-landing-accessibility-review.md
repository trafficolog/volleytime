# Task 3.11.5: Доступность лендинга после review

## Дефекты

1. Акцентный `#ff6b1f` используется как текст и focus-outline на светлых поверхностях: контраст с белым около 2,85:1, с `--vt-bone` около 2,59:1. Это ниже порога 4,5:1 для обычного текста и 3:1 для крупного текста/индикатора фокуса. Тот же контраст имеет белый мелкий текст на оранжевой плашке демо-интерфейса. Декоративные оранжевые поверхности можно сохранить, но смысловой текст и фокус должны быть различимы.
2. На узких экранах CSS `order` переносит «Войти» и «Создать группу» перед ссылками разделов визуально, тогда как последовательность Tab остаётся по DOM: сначала разделы, затем действия.
3. При `prefers-reduced-motion: reduce` и coarse pointer наведение всё ещё сдвигает CTA на 2 px: правило сокращает длительность, но не отменяет transform.
4. При 320 px `overflow-x: clip` скрывает выход двух заголовков за правый край: измерение `Range.getClientRects()` дало правые границы 350 и 391 px при viewport 320 px, хотя `documentElement.scrollWidth` остаётся 320 px.

## Критерии приёмки

- Смысловой акцентный текст на светлом и сером фоне проходит 4,5:1; крупный акцентный текст не ниже 3:1. Focus-индикатор различим на светлых и тёмных секциях без потери видимости.
- Визуальный порядок мобильной навигации совпадает с Tab-порядком; все пять ссылок доступны и CTA не обрезан на 320/390/768 px.
- При reduced motion и coarse pointer hover CTA не вызывает пространственного сдвига; обычная мышь без reduced motion сохраняет эффект макета.
- Заголовки и смысловой текст на 320/390/768 px не обрезаются; проверять прямоугольники строк, а не один лишь `scrollWidth`.
- Для каждого исправления есть RED → GREEN проверка реального поведения; затем пять стандартных gates и browser QA. Изменения 3.11.4 не попадают в `prod` до общего R0.6 gate.

## Журнал

- 2026-09-25: независимое review ветки 3.11.4 выявило перечисленные дефекты. Перед исправлением создана отдельная SDD-карточка и ветка `trafficolog/fix/3.11.5-landing-accessibility` от landing-ветки.
- RED: локальный Edge на 320 px показал цвет hero `rgb(255, 107, 31)` на белом (2,85:1), порядок DOM `разделы → вход → CTA`, но визуально `вход/CTA → разделы`; при reduced motion hover-transform CTA был `translateY(-2px)`. `Range.getClientRects()` нашёл строки заголовков с правыми границами 350/391 px при ширине 320 px. Новый unit-тест контраста упал 2/2 с измеренным 2,85:1 для hero и белого текста на оранжевой демо-плашке.
- GREEN: смысловой акцент стал `#a43d0b` (6,46:1 на белом; 5,88:1 на bone), демо-плашка получила тёмный текст (6,35:1), focus-outline на светлом фоне стал тёмным, на финальном/тёмном блоке — белым. Убрана перестановка `order`; при reduced motion/coarse pointer hover-transform отключён. На 320 px визуальный порядок теперь совпадает с DOM, `scrollWidth=320`; обычный hover сохраняет сдвиг 2 px, reduced motion даёт `transform:none`. После изменения размера заголовков `Range.getClientRects()` не нашёл обрезки на 320/390/768 px; `scrollWidth` равен ширине viewport. Unit-тест контраста прошёл 2/2.
- Дополнительная проверка собранного Nuxt-приложения: мобильный Edge (`412 px`, `matchMedia('(pointer: coarse)')=true`) после hover показывает `transform:none`, `scrollWidth=412`. Две ошибки консоли — тайм-ауты внешних `telegram.org/js/telegram-web-app.js` и Google Fonts в тестовой сети; это не подтверждает доступность внешних ресурсов в production.
- Локальные gates 2026-09-25: `pnpm format:check` — pass; `pnpm lint` — pass, 0 ошибок и 22 существующих предупреждения вне задачи; `pnpm typecheck` — 6/6; `pnpm test` — 85 файлов / 451 тест; `pnpm build` — 2/2; `git diff --check` — pass. GitHub CI и общая ручная QA R0.6 этим не заменяются.
