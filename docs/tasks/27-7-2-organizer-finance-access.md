# Task 27.7.2: Организатор без доступа к кассе и экспорту

## Цель

Владелец может дать организатору ведение событий без доступа к деньгам группы.

## Контекст

- Замечание `ROLE-02` [аудита 2026-11-10](../operations/reviews/2026-11-10-project-audit.md); фаза [27](../phases/27-audit-hardening.md).
- **Как есть:** `canManageContent` объединяет события, оплаты и кассу; организатор равен владельцу во всём, кроме настроек и ролей.
- Варианты AQ-6: отдельный флаг доступа к финансам у организатора; новая роль; оставить как есть.
- Открытые решения владельца: AQ-6 ([фаза 27, «Открытые вопросы»](../phases/27-audit-hardening.md#открытые-вопросы-владельца)). Карточка с открытым решением не стартует.
- Модель: реализация `claude-opus-5-5`, ревью `claude-opus-5-5` (безопасность, доступ или деньги; обязательны тесты граничных случаев); маршрутизация — [ORCHESTRATION](../ORCHESTRATION.md).

## Что должно быть сделано

1. Разделить `canManageContent` на события и финансы; перечень маршрутов каждой группы в PR.
2. Реализовать по AQ-6 (флаг или роль), включение — владельцем в карточке участника.
3. Экраны кабинета и Mini App скрывают разделы денег без доступа; API отвечает 403.
4. Ролевые тесты на каждый финансовый маршрут; деньги в отчётах и обзоре не утекают через сводные ответы.

## Критерии приёмки

- ✅ Организатор без доступа к финансам получает 403 на всех финансовых маршрутах и сводках (тесты)
- ✅ Существующие организаторы сохраняют текущие права
- ✅ Пять gates CODING_STANDARDS на tested revision; ревью `claude-opus-5-5` без Critical/Important

## Не делать

- ❌ Не менять права владельца
