# Task 30.4.4: Root Admin: склейка дублей пользователей

## Цель

Один человек с входом через Telegram и через email — одна учётная запись.

## Контекст

- Спецификация референса: [R-11 · Склейка дублей пользователей](../design/reference-v3/specs/04-root-admin/R-11-merge-users.md); обновление референса — [отчёт 2026-11-24](../design/2026-11-24-reference-v3-update.md).
- Макет: 4b Root Admin → Пользователи → «Возможные дубли».
- **Как есть (main `69a5595`):** дубли пользователей (Telegram и email) возможны; склейки нет. Связано: 27.3.4 «Привязка Telegram».
- **Дельта до референса:** всё, что в «Что должно быть сделано»; работающее не переписывается.
- Модель: реализация `claude-opus-5-5`, ревью `claude-opus-5-5` (обязательны тесты граничных случаев); маршрутизация — [ORCHESTRATION](../ORCHESTRATION.md).

## Что должно быть сделано

**Объём** (по спецификации)

- Подсказки пар по имени, телефону, email в Telegram-профиле
- «Объединить» переносит записи, членства, абонементы, оплаты; оба способа входа остаются
- «Разные люди» скрывает пару
- Отмена склейки 7 дней

## Критерии приёмки

- ✅ Перенос идёт одной транзакцией
- ✅ Склейка пишется в журнал
- ✅ IDOR- и ролевые тесты на каждый новый эндпоинт
- ✅ Пять gates CODING_STANDARDS на tested revision; ревью `claude-opus-5-5` (обязательны тесты граничных случаев) без Critical/Important
