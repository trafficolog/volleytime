# Task 20.5.8: Колонка «Оплаты» и меню строки в списке событий кабинета (`W-03`)

## Цель

Организатор видит по каждому событию сколько оплачено и ждёт оплаты, цену места при делёже суммы, и выполняет действия над событием из строки списка.

## Контекст

- Решение владельца 2026-10-14 (ревью PR #124, 20.5.4): колонка «Оплаты» и меню строки вынесены из [20.5.4](20-5-4-events.md) отдельной задачей v0.2.0.
- Спецификация референса: [W-03 · События](../design/reference-v3/specs/03-organizer-web/W-03-events.md); макет: `4-cabinet/02-screen.png`, исходник — таблица событий в `handoff/screens-web.jsx` (колонка «Оплаты», `ActionMore` строки).
- **Как есть (main `16b0cb8`):** `GET /api/organizations/{orgId}/events` отдаёт события без денежных агрегатов; `POST .../events/{eventId}/cancel` и `GET .../events/{eventId}/price` есть; дублирования и публикации в чат нет.
- **Дельта до референса:** по каждому событию — оплачено и ожидает оплаты (`paid` и `+pending` в макете), для делёжа суммы — «≈ N за место» (для прошедших и закрытых — без «≈»), чип «делёж суммы»; меню строки ⋯: «Открыть событие», «Дублировать», «В чат группы», разделитель, «Отменить событие» (подтверждение; баланс возвращается по D-09/D-13 из [20.2.1](20-2-1-event-balance.md)).
- Модель: реализация `claude-sonnet-5-5`, ревью `claude-opus-5-5` (деньги и доступ: ревью Opus); маршрутизация — [ORCHESTRATION](../ORCHESTRATION.md).

## Что должно быть сделано

1. Агрегаты оплат в `GET /api/organizations/{orgId}/events`: по каждому событию сумма оплаченного (`succeeded`) и сумма ожидающего оплаты (`pending`) одним запросом на страницу списка, без N+1; суммы в копейках по правилам денег проекта.
2. «≈ N за место» для событий с делёжем суммы считается расчётом цены [20.1.1](20-1-1-pricing.md) (тот же quote, что `GET .../events/{eventId}/price`), а не отдельной формулой в списке; для прошедших и закрытых — зафиксированная доля без «≈».
3. Колонка «Оплаты» в списке (не в календаре): оплачено, ожидание, «≈ N за место».
4. Меню строки ⋯ (`popover`, выравнивание вправо, клик по меню не открывает карточку):
   - «Открыть событие» — переход в карточку;
   - «Дублировать» — создание события через существующий контракт создания [20.5.5](20-5-5-event-create.md) с копией полей (название, зал, время, места, цена, режим записи); дата — по макету следующая; копия создаётся черновиком, баланс не списывается (D-04);
   - «В чат группы» — публикация анонса события в Telegram-чат группы через бота и привязку чата из [20.3.4](20-3-4-group-chat-link.md) (зависимость: без 20.3.4 пункт не реализуется; решение владельца 2026-10-19); если у группы нет привязанного чата, пункт недоступен с пояснением. Контракт 20.3.4: `POST /api/organizations/{orgId}/events/{eventId}/telegram-announce` (manager; тело не нужно), статус привязки — `GET /api/organizations/{orgId}/telegram-chat` (`link`: `null` или `status` `active`/`invalid`, `invalidReason` `no_rights`/`migrated`, `botCanPost`; `released` — почему чат снят: `organizer`/`bot_removed`); коды ошибок `telegram_chat.not_linked|bot_removed|no_rights|migrated|event_not_announceable|rate_limited|delivery_failed`;
   - «Отменить событие» — подтверждение и существующий `POST .../events/{eventId}/cancel` (возврат баланса и оплат по D-09, D-13, D-14).
5. Доступность: меню — кнопка с `aria-haspopup`, пункты по клавиатуре, `Esc` закрывает, фокус возвращается на кнопку; опасное действие отделено и подтверждается.
6. Сверить экраны с референсом через харнесс [19.0.2](19-0-2-visual-reference-harness.md) и приложить отчёт к PR.

## Решения по реализации (координатор, 2026-10-25)

- **«Дублировать»** (решение владельца 2026-10-26, [журнал](../operations/decisions/2026-10-12-reference-v3-decisions.md)): то же местное время в часовом поясе группы, к дате прибавляются недели, пока начало копии не окажется в будущем (минимум +7 дней; копия старого события не создаётся в прошлом), статус `draft`; валюта события передаётся в `POST` (схема создания принимает `currency`); запрос — существующий `POST …/events` (нового маршрута нет), копируются тип, название, описание, зал, место текстом, места, режим и цена (цель делёжа), уровень, режим записи (`joinMode`), срок закрытия записи; время открытия записи не переносится. Баланс не списывается (черновик, D-04).
- **«≈ N за место»** в списке организатора — цена на участника при **текущем составе**: `quoteEventPrice` для одного места (`splitShareQuote` в `GET …/events`, только manager), то есть то же, что `GET …/price` для игрока с одним местом. Это не прогноз «если запишетесь» из 20.4.6. До закрытия записи — «≈ N» (`perSeat.max`), после фиксации и для прошедших — доля без «≈»; у отменённого события цены места нет.
- **Агрегаты оплат** (`paymentTotals`) считает `readEventListMoney` одним сгруппированным запросом на страницу; правила те же, что у `readPricingFinancials` (касса и карточка события). Игроку поля не отдаются.
- **Меню:** `VtPopover` расширен (`separator`, `hint`, `fixed`: меню поверх окна, чтобы таблица с прокруткой его не обрезала; закрывается при прокрутке страницы). «В чат группы» недоступен с пояснением, если чат не привязан, недействителен (`no_rights`/`migrated`), состояние не удалось прочитать, либо событие не опубликовано или уже началось (правило `announceEvent`). «Отменить событие» скрыт у уже отменённого. Недоступный пункт остаётся в порядке фокуса (`aria-disabled`), подсказка читается с клавиатуры и скринридером, выбрать его нельзя; «сейчас» для правила анонса берётся при открытии меню. В подтверждении отмены — общие последствия без счёта по местам (состав в списке не загружен; текст принят владельцем 2026-10-26); возврат баланса и оплат — на сервере (D-09, D-13, D-14).
- После действия из меню список перезагружается с первой страницы, фокус переходит на заголовок страницы.

## Критерии приёмки

- ✅ Суммы в колонке совпадают с кассой и карточкой события; ожидающие платежи не входят в «оплачено»
- ✅ «≈ N за место» совпадает с `GET .../events/{eventId}/price` для того же события
- ✅ Tenant safety: агрегаты и действия меню доступны только организатору этой группы; IDOR-тесты на список с агрегатами, дублирование, анонс в чат и отмену (чужая группа, чужое событие, роль без прав)
- ✅ Дублирование не списывает баланс; отмена возвращает баланс строго по D-09/D-13 и не возвращает его повторно
- ✅ Тесты: интеграционные на агрегаты (оплачено, ожидание, отмена платежа, делёж суммы, пустое событие), на каждое действие меню, граничные случаи денег; компонентные на меню и колонку
- ✅ Отчёт визуальной сверки по экранам из `reference.screens` без открытых расхождений Critical/Important
- ✅ Пять gates CODING_STANDARDS на tested revision; ревью `claude-opus-5-5` без Critical/Important
