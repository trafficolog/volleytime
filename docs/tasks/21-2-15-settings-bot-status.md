# Task 21.2.15: Статус бота, тестовое сообщение и переподключение (`W-11`)

## Цель

Организатор видит, подключён ли бот к чату группы, проверяет доставку тестовым сообщением и переподключает бота.

## Контекст

- Решение владельца 2026-10-15 (ревью PR #138, 20.5.7): часть макета W-11, которой нужна новая серверная работа, выделена из [20.5.7](20-5-7-settings.md) отдельной задачей v0.3.0; в v0.2.0 она не входит.
- Спецификация референса: [W-11 · Настройки](../design/reference-v3/specs/03-organizer-web/W-11-settings.md); макет: 4 Кабинет организатора → Настройки → Telegram-бот, `4-cabinet/23-screen.png`; исходник — `WebSettings` в `handoff/screens-web.jsx`.
- **Как есть (main `35a43fd`):** Бот v3 — [20.3.3](20-3-3-telegram-bot.md); в кабинете нет страницы состояния бота, invite-ссылка группы есть в API приглашений.
- **Дельта до референса:** Блок «Telegram-бот»: бот, статус подключения, чат группы и число участников, ссылка Mini App, invite-ссылка с копированием, «Тест-сообщение», «Переподключить».
- Модель: реализация `claude-sonnet-5-5`, ревью `claude-opus-5-5` (ревью Opus: действия бота от имени группы, IDOR и злоупотребление отправкой); маршрутизация — [ORCHESTRATION](../ORCHESTRATION.md).

## Что должно быть сделано

1. API состояния бота группы (подключён ли, привязанный чат, число участников) — только чтение из существующих данных бота [20.3.3](20-3-3-telegram-bot.md); если для статуса нужен новый контракт бота — остановиться и вернуть задачу оркестратору.
2. Тестовое сообщение в чат этой группы: только owner/organizer, ограничение частоты, понятная ошибка при недоступном чате.
3. Переподключение: повторная привязка чата группы существующим способом бота; результат и ошибка видны в UI.
4. Блок «Telegram-бот» в кабинете: статус-индикатор, invite-ссылка с копированием, две кнопки.
5. Сверить экраны с референсом через харнесс [19.0.2](19-0-2-visual-reference-harness.md) и приложить отчёт к PR.

## Критерии приёмки

- ✅ Статус отражает реальное состояние привязки; недоступный чат показан как ошибка, а не «подключён»
- ✅ Тестовое сообщение уходит только в чат своей группы; IDOR-тесты (чужая группа, роль игрока) и проверка ограничения частоты
- ✅ Переподключение не создаёт второй чат группы и не затрагивает другие группы
- ✅ Тесты: статус в разных состояниях, тест-сообщение, переподключение, компонентные на блок
- ✅ Отчёт визуальной сверки по экранам из `reference.screens` без открытых расхождений Critical/Important
- ✅ Пять gates CODING_STANDARDS на tested revision; ревью `claude-opus-5-5` без Critical/Important
