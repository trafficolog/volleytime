# Task 22.1.8: Тариф организации и стартовый баланс в ручном создании организации Root Admin

## Цель

В форме ручного создания организации в Root Admin выбирать план организации (beta, demo и т. п.) и стартовый баланс событий, как в макете.

## Контекст

- Решение владельца 2026-11-19 ([D-17](../operations/decisions/2026-10-12-reference-v3-decisions.md#d-17)): поля выделены из [22.1.3](22-1-3-organizations.md) в отдельную карточку бэклога; релиз не назначен.
- Макеты: [4b-root-admin/03-screen.png](../design/reference-v3/screenshots/4b-root-admin/03-screen.png), [4b-root-admin/04-screen.png](../design/reference-v3/screenshots/4b-root-admin/04-screen.png); спецификация [R-01](../design/reference-v3/specs/04-root-admin/R-01-organizations.md).
- **Терминология:** в интерфейсе «баланс событий», единица — «событие» ([D-10](../operations/decisions/2026-10-12-reference-v3-decisions.md#d-10)); слово «кредиты» из макета заменяется. Стартовый баланс существующих пилотных групп — [D-12](../operations/decisions/2026-10-12-reference-v3-decisions.md#d-12).
- **Как есть:** ручное создание организации ([22.1.3](22-1-3-organizations.md)) не задаёт план и стартовый баланс; пакеты и тарифы платформы — [22.2.1](22-2-1-balance-tariffs.md).
- Задача меняет схему БД и начисляет баланс (деньги): схему и контракт задаёт `claude-opus-5-5` (ADR, правило 3 [ORCHESTRATION](../ORCHESTRATION.md)); ревью `claude-opus-5-5` с тестами граничных случаев (правило 1).

## Что должно быть сделано

1. **ADR до кода:** где хранится план организации (колонка или связь с тарифами 22.2.1), допустимые значения, значение по умолчанию для существующих организаций, как стартовый баланс записывается в журнал баланса событий (одна операция, источник «создание организации root»), максимум стартового значения. Вынести ADR на принятие владельцем.
2. Миграция с откатом и запись в [deploy runbook](../operations/runbooks/deploy.md).
3. Серверная часть создания: план и стартовый баланс принимаются на сервере с проверкой диапазона; организация, начисление баланса и запись аудита платформы создаются в одной транзакции.
4. Форма создания: выбор плана и поле стартового баланса по макету, пояснение единицы «событие».
5. Тесты: создание с планом и без, нулевой и граничные значения баланса, отрицательное и нецелое значение, откат при ошибке транзакции, запись аудита, доступ (401, 403).
6. Сверить экраны с референсом вручную (десктоп 1440x900 и мобильный 375x812, отчёт в теле PR) по [D-16](../operations/decisions/2026-10-12-reference-v3-decisions.md#d-16).

## Критерии приёмки

- ✅ ADR принят владельцем до кода; миграция обратима и описана в runbook
- ✅ Стартовый баланс создаётся одной операцией баланса событий вместе с организацией; при ошибке не остаётся ни организации, ни начисления
- ✅ Существующие организации и их баланс не изменены
- ✅ Отчёт визуальной сверки по экранам из `reference.screens` без открытых расхождений Critical/Important
- ✅ Пять gates CODING_STANDARDS на tested revision; ревью `claude-opus-5-5` без Critical/Important
