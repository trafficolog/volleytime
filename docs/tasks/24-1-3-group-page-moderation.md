# Task 24.1.3: Модерация страниц групп (`R-06`)

## Цель

Контроль публичных страниц.

## Контекст

- Спецификация референса: [R-06 · Модерация страниц групп](../design/reference-v3/specs/04-root-admin/R-06-group-page-moderation.md); макет: прототип владельца 2026-11-23 — [`handoff/screens-moderation.jsx`](../design/reference-v3/handoff/screens-moderation.jsx) (4b Root Admin → «Страницы групп»: маршруты `pages` → `ModCities`, `page-complaints` → `ModComplaints`; 5 Public Pages → «Пожаловаться» `ModGroupPublic`; 4 Кабинет → баннер `ModSeoBanner`). Прототип не импортируется: пересобирается на Vue с токенами проекта.
- **Как есть (main `32e6eb45`):** публичная страница, каталог города, sitemap и короткая ссылка 24.1.2; индексация — `seoIndex` владельца (24.1.1). Модерации нет.
- **Дельта до референса:** каталог городов со страницами групп и их состояниями, «Скрыть» / «Принудительный noindex» / «Вернуть» с причиной, история, жалобы с публичной страницы, баннер решения в кабинете, сообщение в бот.
- Решения владельца: [D-08](../operations/decisions/2026-10-12-reference-v3-decisions.md#d-08) выполнено макетом 2026-11-23 (запись журнала решений 2026-11-23 «Макет модерации страниц групп»); визуальная сверка экранов Root Admin — вручную, [D-16](../operations/decisions/2026-10-12-reference-v3-decisions.md#d-16); переключатель индексации владельца — [D-24](../operations/decisions/2026-10-12-reference-v3-decisions.md#d-24).
- Модель: контракт `claude-opus-5-5`, UI `claude-sonnet-5-5`; ревью обоих шагов `claude-opus-5-5`; маршрутизация — [ORCHESTRATION](../ORCHESTRATION.md).

**Общий функционал с другими интерфейсами:**

- **Страница группы** — Конструктор организатора, рендер и модерация root. С этим связаны: [W-13 → 24.1.1](24-1-1-group-page-builder.md), [W-14 → 24.1.2](24-1-2-group-page-render.md), [P-02 → 19.2.2](19-2-2-group-settings.md). [Подробнее](../design/reference-v3/specs/links.md#seo)

## Что должно быть сделано

**Шаги (правило 3 [ORCHESTRATION](../ORCHESTRATION.md#маршрутизация-моделей)):** контракт данных — `claude-opus-5-5` (схема, миграция, общие типы, сервис, API, применение решений в 24.1.2, уведомления), затем UI — `claude-sonnet-5-5`. Отдельные PR; UI начинается после merge контракта.

**Контракт**

1. Миграция `0046` (аддитивная, откат отказывает, пока есть решения или жалобы): решение root по странице (`group_page_moderation`: состояние `hidden`/`noindex`, причина, заметка, автор, время), жалобы (`group_page_complaints`: страница, причина, подробности, пользователь — только если вошёл, HMAC устройства для лимита, статус `new`/`rejected`/`resolved` и итог), счётчик отсечённых лимитом по суткам. История решений — `audit_log` без `organization_id`.
2. Применение решения в 24.1.2: `hidden` — страница, `GET /api/public/groups/{slug}`, короткая ссылка, каталог и sitemap отвечают как для неопубликованной страницы (тот же 404); `noindex` — страница открывается, `noindex` в meta и `X-Robots-Tag`, нет в sitemap и каталоге, поверх `seoIndex` владельца. Кеш — прежний `s-maxage`.
3. Пока решение действует, `PATCH …/settings { seoIndex }` с другим значением — 409 `group_page.moderation_locked`; `GET …/group-page` отдаёт решение (`moderation`: причина, заметка, время; без автора) владельцу и организаторам.
4. Root API (`/api/platform/**`): города справочника (все районные центры и Минск) со счётчиками; страницы города или страны с фильтром и поиском; `moderation` (hidden/noindex, причина обязательна, заметка «Что исправить»), `restore` (без причины); история; жалобы (новые или закрытые; KPI: открытые, самая старая, закрыто и среднее время за 30 дней, отсечено лимитом); «Отклонить» и решение по странице из жалобы.
5. Публичная жалоба `POST /api/public/groups/{slug}/complaints` без входа: причина из пяти, подробности до 500; не больше 3 в сутки с устройства плюс общий публичный лимит; скрытая и неизвестная страница — 404; автор не раскрывается организатору.
6. Уведомление владельцу и организаторам о скрытии, noindex и возврате — лента и бот через журнал `scheduled_jobs` (тип ленты `organizer_action_required`, вид — шаблон `group_page_hidden` / `group_page_noindex` / `group_page_restored`), кнопка «Открыть кабинет».
7. OpenAPI маршрутов, [permissions-v3](../architecture/permissions-v3.md), строка миграции в [ADR-v3-domain](../architecture/ADR-v3-domain.md).

**UI** (по макету `screens-moderation.jsx`)

8. Root Admin «Страницы групп»: вкладки «Каталог городов» и «Жалобы»; навигатор городов по областям с поиском и фильтрами «Со страницами / Внимание / Все»; таблица страниц с состояниями «в поиске», «noindex · владелец», «noindex · root», «скрыта · 404»; диалоги «Скрыть» и «Принудительный noindex» (причина, «Что исправить», «Что произойдёт», превью сообщения бота), подтверждение «Вернуть», история. Старая очередь AdminPages в меню не возвращается.
9. «Жалобы»: KPI, вкладки «Новые / Решённые / Все», «Отклонить», «Noindex», «Скрыть»; подпись о том, что жалобы на организатора и оплату принимаются отдельно (ссылки нет: раздела «Жалобы» в Root Admin пока нет).
10. Публичная страница `/g/<slug>`: «Пожаловаться на страницу» с причинами и подробностями, «Не больше 3 жалоб в сутки», подтверждение «Модератор посмотрит в течение суток…».
11. Кабинет «Страница группы»: баннер решения (причина, заметка, время) вместо статуса индексации; переключатель индексации недоступен с подсказкой «Пока действует решение администрации, переключатель не работает».
