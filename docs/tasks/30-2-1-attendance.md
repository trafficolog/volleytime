# Task 30.2.1: Посещаемость: опоздал, пришёл без записи, окно отметки

## Цель

Отметка «пришёл / опоздал / не пришёл» по каждой записи. На ней считаются no-show, серии, MVP, прогресс и итоги сезона.

## Контекст

- Спецификация референса: [P-19 · Посещаемость](../design/reference-v3/specs/01-platform/P-19-attendance.md); обновление референса — [отчёт 2026-11-24](../design/2026-11-24-reference-v3-update.md).
- Макет: 3 Mini App → Организатор → «Сегодня · Отметить пришедших»; 3 Mini App → Тренер → Состав.
- **Как есть (main `69a5595`):** статусы записи `attended` и `no_show` есть (`booking_status`); «опоздал», «пришёл без записи» и окна отметки нет; отметка — в карточке события.
- **Дельта до референса:** всё, что в «Что должно быть сделано»; работающее не переписывается.
- Модель: реализация `claude-opus-5-5`, ревью `claude-opus-5-5` (обязательны тесты граничных случаев); маршрутизация — [ORCHESTRATION](../ORCHESTRATION.md).

## Что должно быть сделано

**Шаги (правило 3 [ORCHESTRATION](../ORCHESTRATION.md#маршрутизация-моделей)):** контракт — `claude-opus-5-5`: статус «опоздал», запись «пришёл без записи», окно отметки и автоматический no-show через планировщик, событие `attendance.saved`.

**Объём** (по спецификации)

- Статус посещения у записи и у каждого места в записи
- «Пришёл без записи» — создаёт запись задним числом
- Отметка открыта с начала события до +24 ч, потом только у организатора
- Автоматический no-show, если записи не отмечены через 24 ч — выключается в настройках группы

**Данные и API** (по спецификации; точные маршруты и имена — в контракте)

- PATCH /events/{id}/attendance — пакетно
- Событие `attendance.saved` для P-09 и гипотез

## Критерии приёмки

- ✅ Повторная отметка перезаписывает статус и пишет автора
- ✅ Счётчик no-show в профиле игрока совпадает с отметками
- ✅ IDOR- и ролевые тесты на каждый новый эндпоинт
- ✅ Пять gates CODING_STANDARDS на tested revision; ревью `claude-opus-5-5` (обязательны тесты граничных случаев) без Critical/Important
