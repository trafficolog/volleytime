# Task 27.2.3: Проверка истории Git публичного репозитория на секреты и личные данные

## Цель

В истории Git публичного репозитория нет действующих секретов, личных данных и боевых идентификаторов.

## Контекст

- Замечание `PD-03` [аудита 2026-11-10](../operations/reviews/2026-11-10-project-audit.md); фаза [27](../phases/27-audit-hardening.md).
- Решение AQ-1 (2026-11-10): репозиторий остаётся публичным — проект в разработке и используется только для тестирования; описания замечаний аудита публикуются.
- Правило проекта: в документах нет имён и Telegram-ников; это нужно проверить и по истории.
- Приоритет поднят с P2 (PD-03 в аудите) до P1: проверка нужна до публикации новых документов безопасности в публичный репозиторий.
- `docs/PLATFORM_VISION.md` («Решения», п. 4) ещё говорит «repo приватный до Phase 10» — правится в [27.9.2](27-9-2-vision-update.md).
- Модель: реализация `claude-sonnet-5-5`, ревью `claude-opus-5-5` (итог принимает владелец); маршрутизация — [ORCHESTRATION](../ORCHESTRATION.md).

## Что должно быть сделано

1. Прогнать gitleaks (или аналог) по всей истории локально; отчёт без значений секретов — только файл, коммит, тип.
2. Поиск по истории: Telegram ID, имена, телефоны, домены и IP вне публичных, токены ботов; список мест.
3. Для каждой находки: отзыв или ротация (секреты — владелец), решение о переписывании истории (только с владельцем).
4. Добавить gitleaks в CI как проверку новых коммитов (если не покрыто 27.2.2).

## Критерии приёмки

- ✅ Отчёт проверки истории передан владельцу без значений секретов
- ✅ Найденные секреты отозваны или ротированы владельцем
- ✅ Новые коммиты проверяются на секреты
- ✅ Пять gates CODING_STANDARDS на tested revision; ревью `claude-opus-5-5` без Critical/Important; итог принят владельцем

## Не делать

- ❌ Не переписывать историю и не делать force push без решения владельца
- ❌ Не печатать найденные значения
