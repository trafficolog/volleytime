# Task 10.5.1: Onboarding-чеклист (runbook)

## Цель

Пошаговый повторяемый чеклист подключения нового бета-организатора: от first contact до первого проведённого события.

## Контекст

Решение 6: формализация onboarding. PRIVATE_BETA_PLAN.md описывает процесс — превращаем в исполнимый чеклист. На основе опыта Трека B.

## Что должно быть сделано

1. **Runbook `docs/operations/runbooks/beta-onboarding.md`:**

   ```markdown
   # Onboarding бета-организатора

   ## Предусловия

   - Организатор подходит по критериям (PRIVATE_BETA_PLAN: активный, Telegram, 8+ человек, готов месяц)

   ## Чеклист

   ### 1. First contact

   - [ ] Личный разговор/демо (10-15 мин)
   - [ ] Объяснить: закрытая бета, бесплатно, нужна обратная связь
   - [ ] Получить согласие + контакт для оперативной связи

   ### 2. Добавить в allowlist

   - [ ] Узнать telegram_id (организатор пишет боту → super-admin показывает, или username-резолв)
   - [ ] Добавить в allowlist (super-admin 10.3.2, note = имя/группа)

   ### 3. Создание организации (вместе)

   - [ ] Организатор открывает volleytime.by / t.me/bot
   - [ ] Авто-логин через Telegram
   - [ ] Создаёт организацию (название, город)
   - [ ] Создаёт первый план абонемента (или бесплатный)
   - [ ] Создаёт первое событие

   ### 4. Приглашение игроков

   - [ ] Организатор генерирует invite-ссылку
   - [ ] Отправляет в чат своей группы
   - [ ] Проверить: игроки присоединяются, записываются

   ### 5. Первое событие

   - [ ] Сопроводить первую реальную тренировку (онлайн на связи)
   - [ ] Проверить: записи, оплаты, attendance, уведомления работают
   - [ ] Собрать первые впечатления

   ### 6. Передать материалы

   - [ ] Ссылка на FAQ (10.4)
   - [ ] Добавить в чат беты (поддержка)
   - [ ] Договориться о еженедельной feedback-сессии

   ## После онбординга

   - Отметить в super-admin обзоре (10.3)
   - Начать трекинг активности (гейт-метрики)
   ```

2. **Как узнать telegram_id** — конкретизировать (из 10.1.2): организатор пишет боту /start → в логах/super-admin виден telegram_id; либо по @username.

3. **Время онбординга** — оценить (по Треку B опыт): сколько занимает, чтобы планировать (2-5 организаторов).

## Критерии приёмки

- ✅ Runbook beta-onboarding.md (пошаговый чеклист)
- ✅ Покрывает: contact → allowlist → создание org → приглашение → первое событие → материалы
- ✅ Конкретика получения telegram_id
- ✅ Повторяемость (любой подключит организатора по чеклисту)
- ✅ Опирается на PRIVATE_BETA_PLAN + опыт Трека B

## Подсказки

- **Сопроводить первое событие** — критично. Первый реальный прогон с поддержкой на связи ловит проблемы и создаёт доверие. По Треку B знаешь где спотыкаются.
- **telegram_id bootstrap** — самая частая загвоздка онбординга. Чёткий способ узнать обязателен.
- **Чеклист, не эссе** — checkbox-формат, чтобы реально следовать по шагам.

- ❌ Не пропускать сопровождение первого события
- ❌ Не дублировать PRIVATE_BETA_PLAN (конкретизировать в чеклист)
