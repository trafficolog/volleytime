# Task 20.3.4: Привязка Telegram-чата к группе и анонс в чат

## Цель

Организатор привязывает групповой чат Telegram к группе Volley Time, и бот публикует в нём анонс события с кнопками, которые работают в групповых чатах.

## Контекст

- Решение владельца 2026-10-19 (закрытие [20.3.3](20-3-3-telegram-bot.md), [журнал решений](../operations/decisions/2026-10-12-reference-v3-decisions.md)): привязка группового чата к группе — отдельная задача v0.2.0. Кнопка «В чат группы» в [20.5.8](20-5-8-events-payments-row-menu.md) ждёт эту задачу.
- Спецификация референса: [P-16 · Telegram-бот](../design/reference-v3/specs/01-platform/P-16-telegram-bot.md); макет: 2 Telegram Bot, экран BotDeeplink «анонс „Записаться“» (сообщение с датой, местом, «Свободно N из M» и кнопками «Записаться», «Открыть»).
- **Как есть (после 20.3.3):** в схеме нет привязки Telegram-чата к группе; бот принимает `my_chat_member` только в личном чате (снятие `users.bot_blocked_at`); `/internal/notify` умеет слать сообщение по любому `telegramId` (в том числе id чата), но кнопки `web_app` в групповых чатах не работают — нужны `url`-ссылки `t.me/<бот>?startapp=…`.
- **Дельта:** связь «группа ↔ чат», обработка `my_chat_member` в группах, проверка прав бота в чате, привязка одноразовым кодом организатора с проверкой администратора чата (решение владельца 2026-10-20), анонс события в чат с url-диплинками.
- Модель: реализация `claude-sonnet-5-5`, ревью `claude-opus-5-5` (миграция, права и tenant safety: ревью Opus); маршрутизация — [ORCHESTRATION](../ORCHESTRATION.md).

## Что должно быть сделано

1. Миграция: связь группы с Telegram-чатом (id чата, тип, название, кто и когда подтвердил, статус привязки). Один чат — одна группа, одна группа — не более одного активного чата; уникальность на уровне БД; откат миграции описан.
2. Бот принимает `my_chat_member` в групповых и супергрупповых чатах (добавление, удаление, смена прав); `allowed_updates` уже включает `my_chat_member`. При удалении бота из чата или потере права писать привязка помечается недействительной, а не удаляется молча.
3. Права бота: для публикации анонса бот должен быть участником чата с правом отправлять сообщения (по `getChatMember` бота); состояние прав сохраняется в привязке и показывается организатору.
4. Привязка кодом (решение владельца 2026-10-20, [журнал решений](../operations/decisions/2026-10-12-reference-v3-decisions.md)): код привязки выдаёт действующий organizer/owner группы в кабинете — одноразовый, с истекающим сроком, привязанный к группе; в Telegram-чате бот принимает код только от администратора этого чата (`getChatMember` отправителя: creator/administrator); отдельного подтверждения владельцем группы нет; чужой, просроченный или повторный код привязку не создаёт. Владелец видит привязку в кабинете и может отвязать; отвязка — действие organizer/owner группы с записью в аудит. Исключение бота из чата освобождает чат (привязка снимается с причиной, возвращение бота её не оживляет, нужен новый код); потеря права писать — привязка `invalid`, оживает с возвращением права; код, прозвучавший в чате, сгорает при любом исходе, кроме привязки, а бот пытается удалить сообщение с ним (решение владельца 2026-10-20, дополнение).
5. Внутренний API web для бота и авторизованный API для организатора: статус привязки, начало и подтверждение, отвязка. Роли — [19.3.1](19-3-1-auth-roles.md); сравнение секрета бота константное, проверка секрета раньше разбора тела.
6. Анонс события в чат: сообщение по макету (дата, место, «Свободно N из M»); в групповом чате вместо `web_app` — кнопки `url` с `t.me/<бот>?startapp=event_<id>` («Записаться», «Открыть»). Контракт вызова (id события) — для [20.5.8](20-5-8-events-payments-row-menu.md); анонс строится из данных события на стороне web, не из тела запроса.
7. Ошибки Bot API (бот исключён, нет прав, чат перенесён в супергруппу) возвращаются организатору понятным кодом и не раскрывают токен или внутренние данные.

## Критерии приёмки

- ✅ Миграция применяется и откатывается на копии данных; ограничения уникальности проверены интеграционным тестом
- ✅ `my_chat_member` в группе создаёт или обновляет состояние привязки; удаление бота и потеря прав помечают привязку недействительной; личные чаты ведут себя как в 20.3.3
- ✅ Привязку нельзя создать для чужой группы, по чужому, просроченному или использованному коду, от не администратора чата, без роли organizer/owner; IDOR-тесты на все новые маршруты
- ✅ Анонс отправляется только в привязанный и действующий чат группы события; в групповом чате нет кнопок `web_app`, только `url`-диплинки; диплинк открывает нужное событие
- ✅ Токены и секреты не попадают в ответы и логи; проверка внутреннего секрета раньше разбора тела
- ✅ Тесты: интеграционные на миграцию, права и привязку, юнит-тесты обработчика `my_chat_member` и клавиатуры анонса
- ✅ Отчёт визуальной сверки по экранам из `reference.screens` (анонс) без открытых расхождений Critical/Important
- ✅ Пять gates CODING_STANDARDS на tested revision; ревью `claude-opus-5-5` без Critical/Important

## Примечания реализации

- **Миграция `0031_telegram_chat_link`** (аддитивная; откат `packages/db/rollback/0031_telegram_chat_link.sql` отказывает, пока есть не отвязанные чаты): `organization_telegram_chats` (частичные уникальные индексы `WHERE status <> 'unlinked'`: один чат — одна группа, у группы один не отвязанный чат) и `telegram_chat_link_codes` (SHA-256 кода, TTL 15 минут, `consumed_at`). Описание — [ADR v3](../architecture/ADR-v3-domain.md#привязка-telegram-чата-к-группе-2034), права — [матрица](../architecture/permissions-v3.md). Флага включения нет (прежний runtime новых таблиц не знает; решение координатора в журнале 2026-10-20); проведение в production — [20.7.1](20-7-1-release-v0-2-0-qa.md), п. 11.
- **Кабинет (manager):** `GET /api/organizations/{orgId}/telegram-chat` (статус, причина недействительности, право бота, срок кода; без Telegram id и кода), `POST …/telegram-chat/link-code` (код показывается один раз; новый код отзывает прежний), `DELETE …/telegram-chat` (отвязка, журнал; повтор безопасен), `POST …/events/{eventId}/telegram-announce` (контракт для [20.5.8](20-5-8-events-payments-row-menu.md); только опубликованное, не начавшееся событие этой группы; текст и кнопки строит web).
- **Бот:** `/link <код>` в группе или супергруппе — проверка `getChatMember` отправителя (creator/administrator; анонимный администратор отклоняется) и бота (право писать; для `restricted` — `is_member` и `can_send_messages`; общие запреты чата, которых `getChatMember` не показывает, обнаруживаются при первой отправке анонса как `telegram_chat.no_rights`), затем `POST /api/internal/bot/chat-link`. Если отправитель не администратор, анонимен или проверить его не удалось, бот отправляет `verdict: rejected`: код сгорает без привязки; сообщение с кодом удаляется в каждой ветке, если у бота есть право. `my_chat_member` в группах → `POST /api/internal/bot/chat-member`: исключение бота (`left`/`kicked`, в том числе `restricted` без членства) снимает привязку и освобождает чат (`unlinked`, `unlink_reason = bot_removed`, возвращение бота не оживляет), потеря права писать делает её `invalid` (`no_rights`), возвращение права оживляет; новый чат так не привязывается. Секрет проверяется раньше разбора тела; подбор кода ограничен (10 за 10 минут на администратора, 20 на чат). Команды личного чата (`/start`, `/games`, `/my`, `/menu`, `/help`) в группах не выполняются: одна строка-подсказка без кнопок и данных; `setMyCommands` — область `all_private_chats` для них и `all_chat_administrators` для `/link`, общий список снят.
- **Ошибки Bot API при анонсе:** бот отвечает 410 с заголовком `x-failure-reason` (`bot_removed`, `no_rights`, `migrated`), web помечает привязку недействительной (`no_rights`, `migrated`) или снимает её (`bot_removed`) и возвращает организатору `telegram_chat.bot_removed|no_rights|migrated` (409), `rate_limited` (429), `delivery_failed` (502); токены и тексты Bot API наружу не попадают; в логи и Sentry бота при сбое отправки идут только код и описание ошибки Bot API (без `chat_id` и текста). Код и `chat_id` в логи не пишутся; Telegram id пользователя виден только в стандартной строке `[bot] message from <id>` middleware логирования. В групповом чате бот принимает только `url`-кнопки с `https`.
- **Не вошло:** интерфейс кабинета (статус бота и переподключение — [21.2.15](21-2-15-settings-bot-status.md), v0.3.0; кнопка «В чат группы» — [20.5.8](20-5-8-events-payments-row-menu.md)); обработка служебного сообщения `migrate_to_chat_id` (перенос в супергруппу замечается при первой неудачной отправке: `telegram_chat.migrated`, привязку нужно выдать заново после отвязки); повторная проверка прав бота по расписанию.
- **Визуальная сверка:** [QA-заметка](../operations/qa/2026-10-20-20-3-4-chat-announce-visual.md); харнесс 19.0.2 для сообщений Telegram неприменим (нет HTML-страниц), как и в 20.3.3.
