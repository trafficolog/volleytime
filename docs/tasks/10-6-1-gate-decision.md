# Task 10.6.1: Гейт-метрики измерение + decision framework (runbook)

## Цель

Runbook гейт-ревью: как измерить каждый критерий, decision framework (A/B/C сценарии с порогами), чеклист ревью, шаблон документа решения.

## Контекст

Решения 2, 8: объективное измерение гейта, переход в Phase 7 при успехе. Решение о монетизации должно быть на данных, не на ощущениях.

## Что должно быть сделано

1. **Runbook `docs/operations/runbooks/beta-gate-review.md`:**

   ```markdown
   # Гейт-ревью Phase 10 → Phase 7

   ## Когда проводить

   - После ≥1 месяца беты с ≥2 организаторами
   - Когда метрики стабилизировались (не всплеск первой недели)

   ## Гейт-критерии и измерение

   | Критерий              | Цель                    | Откуда данные             | Метод                    |
   | --------------------- | ----------------------- | ------------------------- | ------------------------ |
   | Активные организаторы | ≥2                      | super-admin (10.3)        | org с активностью ≥1 мес |
   | Ретеншн               | ≥1 орг ≥4 недели подряд | gate-metrics (10.3.2)     | события неделя-к-неделе  |
   | Событий создано       | ≥50                     | super-admin агрегат       | сумма по бете            |
   | Бронирований          | ≥200                    | super-admin агрегат       | сумма по бете            |
   | Готовность платить    | ≥1 организатор          | прямой вопрос + поведение | опрос (см. ниже)         |
   | % через Mini App      | ≥80%                    | оценка                    | наблюдение/трекинг       |
   | Критические жалобы    | ≤5                      | feedback-трекинг (10.5.3) | P0/P1 bugs count         |

   ## Измерение «готовности платить» (не автоматизируется)

   - Прямой вопрос организаторам: «Если за проведение событий будет платная
     комиссия/credits (X), продолжите пользоваться?»
   - Сигналы поведения: активность, зависимость от платформы, отказ от старых инструментов
   - Зафиксировать ответы каждого организатора

   ## Decision framework

   ### A — Гейт ПРОЙДЕН

   Условие: ВСЕ критерии достигнуты (или близко + сильный ретеншн + ≥1 готов платить)
   → Phase 7 (Event Credits): технически проверяем готовность платить
   → затем Phase 11+

   ### B — ЧАСТИЧНО

   Условие: ретеншн есть, но часть метрик недотягивает / UX-проблемы
   → Возврат в Phase 5-8 для доработок по обратной связи (10.5.3)
   → Повтор/продление беты
   → НЕ размывать критерии — доработать и переизмерить

   ### C — НЕ ПРОЙДЕН

   Условие: нет ретеншна / организаторы отваливаются / никто не готов платить
   → Анализ: почему? (не тот сегмент / не та ценность / UX / цена)
   → Возможный pivot: позиционирование, функции, аудитория
   → Не идти в монетизацию пока не ясна ценность

   ## Чеклист ревью

   - [ ] Собрать все метрики (super-admin, feedback-трекинг)
   - [ ] Провести опрос готовности платить (все организаторы)
   - [ ] Заполнить таблицу критериев (достигнуто/нет)
   - [ ] Определить сценарий (A/B/C)
   - [ ] Зафиксировать решение + обоснование (документ ниже)
   - [ ] Если A → планировать Phase 7
   - [ ] Если B/C → план доработок/анализа

   ## Шаблон документа решения

   docs/operations/decisions/2026-XX-beta-gate-decision.md

   - Дата, период беты
   - Метрики (факт vs цель)
   - Решение (A/B/C) + обоснование
   - Следующие шаги
   ```

## Подсказки

- **Объективность защищает от самообмана** — соблазн «почти пройдено, идём дальше» силён. Чёткие пороги + честное измерение спасают от преждевременной монетизации.
- **Ретеншн + готовность платить — ключевые.** События/брони можно «накрутить» энтузиазмом первой недели. Ретеншн (возвращаются) и готовность платить (ценят деньгами) — настоящие сигналы.
- **Готовность платить — прямой вопрос.** Не угадывать. Спросить каждого организатора явно. Поведение (зависимость от платформы) подтверждает слова.
- **B лучше преждевременного A** — если недотягивает, доработать честнее, чем монетизировать сырое и потерять доверие.
- **Трек B уже дал сигнал** — продукт работает на своей группе. Phase 10 проверяет переносимость на чужих. Это снижает риск C, но не исключает (свой энтузиазм ≠ чужой).

## Не делать

- ❌ Не размывать критерии чтобы «пройти»

- ❌ Не идти в монетизацию при слабом ретеншне
- ❌ Не решать на ощущениях (данные + framework)
