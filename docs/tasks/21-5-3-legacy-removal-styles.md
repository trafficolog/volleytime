# Task 21.5.3: Удаление наследия, пакет 2: стили без потребителей

## Цель

Удалить из `tokens.css` и `desktop.css` правила `LEG-04` и `LEG-05` принятого отчёта [21.5.1](../operations/reviews/2026-10-28-legacy-inventory.md), которым не соответствует ни один элемент разметки.

## Контекст

- Один пакет = одна ветка, один PR, одна область (стили). Предыдущий пакет: [21.5.2](21-5-2-legacy-removal-batches.md); соседние: [21.5.4](21-5-4-legacy-removal-dev-config-docs.md), [21.5.5](21-5-5-legacy-history-condense.md).
- Старт — после `21.3.1`: задачи 21.2.x правят `desktop.css`, поэтому проверка `LEG-05` повторяется на `main` после релиза v0.3.0.
- Риск пакета низкий: деньги, доступ, данные, деплой и откат не затронуты. Это чистая вёрстка: `claude-haiku-5-5` не трогает логику, API и схему; если понадобятся — остановиться и вернуть оркестратору.
- Модель: реализация `claude-haiku-5-5`, ревью `claude-sonnet-5-5`; маршрутизация — [ORCHESTRATION](../ORCHESTRATION.md).

Состав пакета:

| ID     | Объект                                                                                                                                            | Команда проверки                                                                                                    |
| ------ | ------------------------------------------------------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------- |
| LEG-04 | правило `.vt-legacy-ctl`, `.vt-legacy-ctl *` в `apps/web/app/assets/css/tokens.css`                                                               | `rg -n -F "vt-legacy-ctl" apps packages` → только `tokens.css`                                                      |

## Что должно быть сделано

1. Повторить команды проверки на текущем `main`; класс, у которого появился потребитель в `*.vue`/`*.ts`, исключить из пакета и записать в отчёте. Проверить, что имена не собираются динамически (`` `vt-desktop-event-detail__${…}` ``).
2. Удалить правила `LEG-04` и `LEG-05`. `.vt-desktop-events__controls` стоит в общем списке селекторов с `.vt-desktop-events__filters`: убрать только `__controls`, правило `__filters` сохранить.
3. Проверить, что CSS-тесты (`tokens.test.ts`, `atoms-v3.test.ts`, `desktop-contrast.test.ts`, `shadows.test.ts`, `fields.test.ts`) зелёные; если тест фиксирует удаляемый селектор, обновить его вместе с удалением.
4. Обновить отчёт аудита: статус `LEG-04`, `LEG-05` — удалено + номер PR.
