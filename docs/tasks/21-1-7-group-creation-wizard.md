# Task 21.1.7: Мастер создания группы (3 шага)

## Цель

Организатор создаёт свою группу в Mini App за три шага — «Группа», «Расписание», «Готово» — вместо одношаговой формы.

## Контекст

- Решение владельца 2026-11-05: группа создаётся на переходе 1→2, а не 2→3 — предпросмотр серии требует существующей группы с балансом; шаг 3 создаёт серию и показывает результат из API; «Назад» со шага 2 группу не отменяет. Решение записывает координатор в журнал; здесь оно зафиксировано как входное.
- Решение владельца 2026-10-14: мастер из референса входит в v0.3.0 отдельной карточкой. В списке задач референса его нет, макет — онбординг `OrgOnboarding` (`org-new`) в `handoff/screens-extra.jsx`.
- Макеты: скриншот только шага 1 — [3-miniapp-player/14-screen.png](../design/reference-v3/screenshots/3-miniapp-player/14-screen.png) («Своя группа · Шаг 1 из 3»). Шаги 2 и 3 нарисованы только в исходнике `OrgOnboarding` (`handoff/screens-extra.jsx`, шаги `step === 1` и `step === 2`); скриншотов у них нет, эталон — рендер прототипа.
- Точки входа в мастер (`nav.push('org-new')`): шторка «Мои группы» ([20.4.3](20-4-3-group-switcher.md), «Создать свою группу»), главная игрока и режим организатора (`screens-player.jsx`, `screens-organizer.jsx`).
- **Как есть (main `72de74f`):** `/m/orgs/create` — одна форма «название + город» (`apps/web/app/pages/m/orgs/create.vue`), `POST /api/organizations`; demo-квота 5 событий начисляется сервисом баланса ([20.2.1](20-2-1-event-balance.md), D-12).
- **Дельта до референса:** три шага с индикатором и «Шаг N из 3» в шапке; шаг 2 — дни недели, время, число мест, можно пропустить; шаг 3 — итог, «5 событий в подарок» (D-10: вместо «credits» — «баланс событий», единица — «событие»), ссылка-приглашение с копированием.
- Задача снимает пункт «Создание группы v3» с [21.1.5](21-1-5-org-miniapp-collections-notifications.md).
- Модель: реализация `claude-sonnet-5-5`, ревью `claude-opus-5-5` (ревью Opus: мастер доходит до баланса событий — публикация серии списывает баланс); маршрутизация — [ORCHESTRATION](../ORCHESTRATION.md).

## Что должно быть сделано

1. Шаг 1 «Группа»: название (обязательное, минимум 2 символа, как в текущей форме) и город (по умолчанию «Минск»); «Дальше» недоступна без названия; те же ошибки API, что у текущей формы.
2. Шаг 2 «Расписание»: выбор дней недели, время, число мест; «Пропустить» и «Далее». Расписание создаётся серией событий через существующий контракт [20.2.2](20-2-2-event-series.md) по D-04: серия создаётся атомарно целиком, даты в пределах баланса публикуются и списывают баланс, даты сверх баланса становятся черновиками. До подтверждения шаг показывает предпросмотр из контракта серий: сколько событий будет опубликовано, сколько останется черновиками и баланс после создания. Предпросмотр считается по реальной группе, создание серии — по «Далее» на шаге 2 (переход на шаг 3) с одним ключом идемпотентности на весь запуск мастера (не на тело запроса): если создание прошло, а клиент увидел ошибку, повтор, в том числе с изменённым расписанием, не создаёт вторую серию и не списывает баланс повторно. Ответ 409 `series.idempotency_conflict` значит «расписание уже создано»: сообщение «Расписание уже создано» и переход на шаг 3 (списка серий в API нет, поэтому показывается нейтральная пометка и ссылка на группу). После неоднозначной ошибки «Пропустить» не утверждает «расписание позже», а предлагает проверить события группы; ошибка гаснет при изменении полей. При пропуске серия не создаётся. Нового контракта задача не вводит.

   Инженерные значения шаблона серии (мастер спрашивает только дни, время и число мест; решение координатора 2026-11-05): `title` = название группы, `durationMinutes` = 120, `type` = `training`; правило — `weekly` по выбранным дням, начало — завтрашний день по часовому поясу группы (первая дата не должна быть в прошлом), срок — один месяц (`until`, как период «Месяц» формы события). Умолчания формы: время 20:00, мест 14 (как в макете), день — среда.

3. **Решение владельца 2026-11-05: группа создаётся на переходе со шага 1 на шаг 2.** Предпросмотр серии (`POST /api/organizations/{orgId}/series/preview`) требует существующей группы, членства и баланса событий, который начисляется при создании группы (`grantDemoQuota`), поэтому первое «Дальше» после названия делает один вызов `POST /api/organizations` и запоминает `id` группы в состоянии мастера. Вызов идемпотентен на клиенте: блокировка на время запроса, а повтор после ошибки, «Назад» и снова «Дальше», двойное нажатие используют уже созданную группу и не создают вторую. «Назад» со шага 2 группу не отменяет: она остаётся созданной (пустой), на шаге 1 название и город после создания не редактируются (поля только для чтения, подсказка «Группа уже создана»). Если пользователь выходит из мастера со шага 2, группа остаётся в списке «Мои группы». Если серия не создалась, группа остаётся созданной, пользователь видит сообщение на шаге 2 и может повторить или нажать «Пропустить» и создать расписание позже.
4. Шаг 3 «Готово»: серия создаётся на переходе 2→3 (если расписание не пропущено); карточка группы (название, город, дни), число событий в подарок и итог серии (опубликовано, черновиков, баланс после) берутся из ответов API, а не из констант; ссылка-приглашение в группу из существующего контракта приглашений группы, «Скопировать»; «Готово» ведёт на экран группы в режиме организатора.
5. Шапка «Своя группа» с «Шаг N из 3», кнопка «Назад» между шагами 1–2 (данные шагов сохраняются; на шаге 3 группа и серия уже созданы, «Назад» нет), состояние мастера не теряется при возврате на шаг; выход с шага 1 — на список групп.
6. Маршрут `/m/orgs/create` заменяется мастером; ссылки из [20.4.3](20-4-3-group-switcher.md), главной игрока и режима организатора ведут в него; старая форма удаляется.
7. Доступность: индикатор шагов с `aria-current="step"`, дни недели — группа переключателей с `aria-pressed`, фокус переносится на заголовок шага при переходе.
8. Сверить экраны с референсом через харнесс [19.0.2](19-0-2-visual-reference-harness.md) и приложить отчёт к PR: шаг 1 — по скриншоту 14, шаги 2 и 3 — по рендеру `OrgOnboarding` в прототипе.

## Критерии приёмки

- ✅ Группа создаётся за три шага; без названия «Дальше» недоступна; шаг 2 можно пропустить
- ✅ Созданная группа появляется в шторке «Мои группы» и открывается в режиме организатора; баланс новой группы равен demo-квоте из сервиса баланса, повторное нажатие не создаёт дубль
- ✅ Выбранное расписание создаёт серию по D-04: даты в пределах баланса опубликованы и списаны, остальные — черновики; предпросмотр до подтверждения совпадает с результатом (число опубликованных, черновиков, баланс после); без расписания событий нет
- ✅ Ссылка-приглашение копируется и ведёт в созданную группу
- ✅ Тесты: компонентные — навигация по шагам, валидация, пропуск, защита от двойной отправки, ошибка API, ошибка создания серии, «Назад» и повторное «Дальше» без второй группы; интеграционный — создание группы с расписанием и без
- ✅ Отчёт визуальной сверки по экранам из `reference.screens` (шаг 1) и по рендеру прототипа (шаги 2–3) без открытых расхождений Critical/Important
- ✅ Пять gates CODING_STANDARDS на tested revision; ревью `claude-opus-5-5` без Critical/Important
