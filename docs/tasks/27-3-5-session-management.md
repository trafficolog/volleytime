# Task 27.3.5: Выход со всех устройств и отзыв сессий при блокировке

## Цель

Пользователь может завершить все свои сессии; деактивация пользователя платформой сразу закрывает его сессии.

## Контекст

- Замечание `AUTH-05` [аудита 2026-11-10](../operations/reviews/2026-11-10-project-audit.md); фаза [27](../phases/27-audit-hardening.md).
- **Как есть:** сессия 30 дней, продлевается раз в сутки; проверить наличие «выйти со всех устройств» и отзыва сессий при деактивации (smoke cleanup деактивирует и удаляет сессии — переиспользовать).
- Блокировка в группе не равна блокировке на платформе: сессии отзываются только при деактивации пользователя (будущий Root Admin, фаза 22).
- Модель: реализация `claude-sonnet-5-5`, ревью `claude-opus-5-5` (безопасность, доступ или деньги; обязательны тесты граничных случаев); маршрутизация — [ORCHESTRATION](../ORCHESTRATION.md).

## Что должно быть сделано

1. Функция core «деактивировать пользователя» с удалением сессий; использовать в smoke cleanup и в будущих root-действиях.
2. Кнопка «Выйти со всех устройств» в профиле Mini App и кабинета (тексты по стилю проекта).
3. Тесты: после выхода со всех устройств прежняя cookie → 401; деактивированный пользователь → 401 на любом маршруте.

## Критерии приёмки

- ✅ Выход со всех устройств закрывает все сессии (тест)
- ✅ Деактивация отзывает сессии (тест)
- ✅ Пять gates CODING_STANDARDS на tested revision; ревью `claude-opus-5-5` без Critical/Important

## Не делать

- ❌ Не менять срок сессии без решения владельца
- ❌ Не строить экраны Root Admin
