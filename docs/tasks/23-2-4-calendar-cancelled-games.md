# Task 23.2.4: Отменённые игры в общем календаре (`M-10`)

## Цель

Игрок не теряет из виду отменённую игру, на которую был записан: она видна в общем календаре приглушённой, как в расписании группы.

## Контекст

- **Как есть (main после PR #327, `b9ed7878`):** `GET /api/me/calendar` (`packages/core/src/player-calendar`) исключает отменённые события; страница `apps/web/app/pages/m/orgs/[orgId]/calendar.vue` их не показывает.
- Расписание группы ([21.1.4](21-1-4-group-schedule.md)) показывает отменённые события приглушёнными — образец отображения. Из 21.1.4 переиспользуется приглушённая точка в сетке месяца (`apps/web/app/utils/group-schedule.ts`, ~56). Новое здесь: подпись «Отменена» в списке общего календаря и сам выбор отменённых событий в API.
- **Что значит «игрок был записан».** `eventService.cancel` (`packages/core/src/events/service.ts`, ~714) переводит все активные записи события в `cancelled` (`cancelledAt` = момент отмены), а при отмене игроком запись тоже становится `cancelled` с `cancelledAt`. У записи нет поля причины или источника отмены, у события нет столбца времени отмены (только `updatedAt`, который меняется и после отмены), а журнал аудита хранит одну строку на событие. Без изменения схемы отличить «отменена вместе с событием» от «игрок отменил сам» надёжно нельзя. Поэтому правило: **отменённое событие показывается, если у игрока есть строка записи на него в любом статусе.** Ограничение: игрок, сам отменивший запись до отмены события, тоже увидит такую игру приглушённой; принято как допустимое, схему ради этого не меняем.
- Решение владельца 2026-11-22 в чате, по вопросу ревью PR #327.

## Что должно быть сделано

1. API календаря возвращает отменённые события, на которые у игрока есть строка записи в любом статусе (статус события в ответе); прочие отменённые события по-прежнему не возвращаются. Логика участия и фильтра в `buildMyCalendar` (`apps/web/app/utils/my-calendar.ts`, ~110) не должна отбрасывать такие события: сейчас она оставляет только `going`/`waitlist` и «С местами», поэтому для отменённого события с записью `cancelled` нужна явная ветка.
2. В списке такая игра приглушена и помечена «Отменена» (новое), в месяце — приглушённая точка, как в расписании группы (21.1.4).
3. Пересечения и фильтр «С местами» не меняются и покрываются тестом: `overlapsOf` учитывает только `going`, «С местами» требует статус `published`, поэтому отменённые игры уже исключены.
4. Переход в событие работает, как для остальных игр.

## Критерии приёмки

- Отменённая игра, на которую у игрока есть строка записи (любой статус), видна приглушённой и с подписью «Отменена»; отменённая игра без строки записи не видна; фильтр участия `buildMyCalendar` её не отбрасывает
- Пересечения и «С местами» не учитывают отменённые игры (тест подтверждает, код не меняется)
- Интеграционные тесты core/HTTP и тесты страницы; пять gates CODING_STANDARDS; ревью `claude-opus-5-5` без Critical/Important

## Не делать

- ❌ Не менять расписание группы и другие экраны
- ❌ Не показывать отменённые игры, на которые игрок не записывался
- ❌ Не менять схему ради различения причины отмены записи
