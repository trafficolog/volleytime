# Task 22.1.5: Уровни записей журнала платформы INFO/OK/WARN/ERROR и счётчики

## Цель

Показать на экране «Аудит» Root Admin уровень каждой записи (INFO, OK, WARN, ERROR) и счётчики по уровням, как в макете.

## Контекст

- Решение владельца 2026-11-19 ([D-17](../operations/decisions/2026-10-12-reference-v3-decisions.md#d-17)): уровни выделены из [22.1.2](22-1-2-audit-log.md) в отдельную карточку бэклога; релиз не назначен.
- Спецификация: [R-07 · Журнал действий](../design/reference-v3/specs/04-root-admin/R-07-audit-log.md); макет: [4b-root-admin/11-screen.png](../design/reference-v3/screenshots/4b-root-admin/11-screen.png).
- **Как есть:** `GET /api/platform/audit` и страница `/root/audit` (22.1.2) отдают журнал без уровня; в таблице `audit_log` колонки уровня нет.
- **Дельта до референса:** колонка уровня в записях, фильтр по уровню и счётчики по уровням.
- Задача меняет схему БД: по правилу 3 [ORCHESTRATION](../ORCHESTRATION.md) схему и контракт сначала задаёт `claude-opus-5-5` (ADR), затем интерфейс — `claude-sonnet-5-5`. Доступ root — ревью `claude-opus-5-5`.

## Что должно быть сделано

1. **ADR до кода** (раздел в [ADR-v3-domain](../architecture/ADR-v3-domain.md) или отдельный файл): как определяется уровень (колонка `audit_log.level` или вывод из имени действия), значение по умолчанию для существующих записей, какие действия получают WARN и ERROR, что считают счётчики (по текущему фильтру или по всему журналу). Подготовить ADR и вынести его на принятие владельцем до кода.
2. Миграция с откатом (если ADR вводит колонку): значение по умолчанию для старых записей без перезаписи их `old/new`, индекс под фильтр и счётчики, запись раздела в [deploy runbook](../operations/runbooks/deploy.md).
3. Запись уровня при создании записей аудита платформы; существующие места записи не должны менять поведение.
4. API: поле `level` в записях, параметр фильтра по уровню, счётчики по уровням в ответе `GET /api/platform/audit`; только чтение, `requireRootAdmin`, `no-store`.
5. Экран `/root/audit`: фишки уровней со счётчиками, фильтр по уровню (в URL), метка уровня в строке; тексты — по макету и словарю проекта.
6. Тесты: каждый уровень; счётчики с фильтрами периода, организации и поиска; доступ (401, 403 `forbidden.root_only`); старые записи без уровня.
7. Сверить экран с референсом вручную (десктоп 1440x900 и мобильный 375x812, отчёт в теле PR) по [D-16](../operations/decisions/2026-10-12-reference-v3-decisions.md#d-16).

## Критерии приёмки

- ✅ ADR принят владельцем до кода; миграция обратима и описана в runbook
- ✅ Каждая запись показывает уровень; счётчики совпадают с числом записей выбранных фильтров
- ✅ Журнал остаётся только на чтение; значения `old/new` по-прежнему проходят скрытие секретов
- ✅ Отчёт визуальной сверки по экрану 4b-root-admin/11 без открытых расхождений Critical/Important
- ✅ Пять gates CODING_STANDARDS на tested revision; ревью `claude-opus-5-5` без Critical/Important
