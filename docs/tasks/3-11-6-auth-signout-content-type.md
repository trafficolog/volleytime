# Task 3.11.6: Sign-out после OTP отправляет JSON

## Дефект и причина

В локальном браузерном сеансе с настоящей тестовой PostgreSQL и console email-драйвером вход по OTP привёл аккаунт без организаций к экрану «Нет доступа организатора». Кнопка «Сменить аккаунт» оставила экран и показала ошибку выхода: `POST /api/auth/sign-out` вернул HTTP 415 `UNSUPPORTED_MEDIA_TYPE`, тело ответа: `Content-Type is required. Allowed types: application/json`.

Трассировка: кнопка → `switchEmailAccount()` → `useAuth().logout()` → `$fetch('/api/auth/sign-out', { method: 'POST' })` без тела и `Content-Type`. Контрольный запрос **в той же тестовой сессии** с `Content-Type: application/json` и телом `{}` вернул HTTP 200 `{"success":true}`. Следовательно, ошибка в форме клиентского запроса, а не в OTP, правах или серверной политике отказа.

## Что сделать

1. Добавить RED-тест клиентского контракта logout: запрос без JSON не должен считаться успешным; после успешного sign-out состояние пользователя очищается и открывается форма входа.
2. Передать пустой JSON-объект в POST sign-out, чтобы `$fetch` выставил требуемый Content-Type. Не менять обработку настоящих ошибок выхода и не сбрасывать экран до успешного ответа.
3. Проверить GREEN-тест, полный набор пяти gates и повторить реальный локальный OTP → нет прав → смена аккаунта в браузере. Production/Telegram QA остаётся отдельным gate R0.6.

## Критерии приёмки

- «Сменить аккаунт» после успешной OTP-сессии без роли организатора возвращает к пустой email-форме; сервер принимает запрос sign-out и сессия прекращена.
- При настоящем отказе sign-out остаётся сообщение об ошибке и текущий экран, без ложного очищения формы.
- Regression test, пять gates и browser smoke записаны в журнале.
