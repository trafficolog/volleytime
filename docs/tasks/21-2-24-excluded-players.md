# Task 21.2.24: Исключённые игроки: вкладка и «Исключить и заблокировать»

## Цель

Показать организатору исключённых игроков и дать заблокировать их оттуда, а также исключить и заблокировать за одно действие.

## Контекст

- Решение владельца 2026-11-06 ([журнал](../operations/decisions/2026-10-12-reference-v3-decisions.md), «Исключённые игроки и права исключения»): исключённые игроки видны в кабинете во вкладке «Исключённые» с возможностью заблокировать; подтверждение исключения получает действие «Исключить и заблокировать», чтобы игрок не вернулся по многоразовой ссылке-приглашению группы.
- **Как есть ([21.2.21](21-2-21-player-exclude.md), PR #226):** исключение переводит участника в статус `left` (как и добровольный выход), причина записывается в аудит `member.excluded`; блокировка — отдельное действие модерации.
- Модель: реализация `claude-sonnet-5-5`, ревью `claude-opus-5-5` с тестами; доступ — правило 2 [ORCHESTRATION](../ORCHESTRATION.md).

## Что должно быть сделано

1. Отличить исключение от добровольного выхода: сегодня оба имеют статус `left`, различие есть только в аудите `member.excluded`. Предпочтительно вывести признак из существующих данных (аудит). **Если для надёжного различия нужны новый статус или колонка (миграция) — остановиться и вернуть карточку оркестратору** (ADR и ревью Opus, миграции сериализуются).
2. Вкладка «Исключённые» на экране игроков кабинета: список исключённых с датой и исполнителем; добровольно вышедшие в неё не попадают.
3. Блокировка из статуса `left`: действие «Заблокировать» в строке исключённого; блокировка запрещает возвращение, повторная блокировка идемпотентна.
4. «Исключить и заблокировать» в подтверждении исключения: оба действия в одной транзакции (либо оба, либо ни одного); аудит записывает исполнителя и причину.
5. Права по решению владельца: организаторов и помощников исключает только владелец, организаторы исключают только игроков и гостей ([21.2.21](21-2-21-player-exclude.md)); блокировка из вкладки — по правам модерации группы.
6. Тесты (RED→GREEN): различие исключённого и вышедшего, блокировка из `left`, атомарность «исключить и заблокировать» (откат при сбое второго шага), попытка возвращения по многоразовой ссылке после блокировки, IDOR (управляющий другой группы, обычный игрок, организатор против организатора). Сверка 19.0.2 по `4-cabinet/06`.

## Критерии приёмки

- ✅ Вкладка «Исключённые» показывает только исключённых; добровольный выход в неё не попадает
- ✅ Исключённого можно заблокировать из вкладки; заблокированный не возвращается по многоразовой ссылке
- ✅ «Исключить и заблокировать» атомарно; при сбое ничего не меняется
- ✅ Чужая группа, игрок и организатор без права получают отказ (IDOR-тесты)
- ✅ Схема и миграции не изменены (иначе — эскалация по п. 1)
- ✅ Отчёт визуальной сверки без открытых расхождений Critical/Important
- ✅ Пять gates CODING_STANDARDS на tested revision; ревью `claude-opus-5-5` без Critical/Important; RED→GREEN тесты приложены
