# Task 30.2.3: Mini App: «Состав сегодня»

## Цель

Один экран на зале: кто пришёл, кто нет, приём оплаты. Общий для организатора и тренера.

## Контекст

- Спецификация референса: [M-26 · «Состав сегодня»](../design/reference-v3/specs/02-mini-app/M-26-roster-today.md); обновление референса — [отчёт 2026-11-24](../design/2026-11-24-reference-v3-update.md).
- Макет: 3 Mini App → Организатор → Главная → «Сегодня · Основа в 20:00»; 3 Mini App → Организатор → Событие → ··· → Отметить пришедших; 3 Mini App → Тренер → Состав.
- **Как есть (main `69a5595`):** состав события и отметка есть в карточке события (кабинет и Mini App); отдельного экрана зала нет.
- **Дельта до референса:** всё, что в «Что должно быть сделано»; работающее не переписывается.
- Модель: реализация `claude-sonnet-5-5`, ревью `claude-opus-5-5`; маршрутизация — [ORCHESTRATION](../ORCHESTRATION.md).

## Что должно быть сделано

**Объём** (по спецификации)

- Счётчики: пришли, не пришли, не отмечены; «к оплате» — только с правом на оплату
- Строка игрока: уровень В1–В4+, места, три кнопки 40×40 «пришёл / опоздал / не пришёл»
- С правом на оплату: «не оплачено» или «говорит, что перевёл», кнопка «Принять / Подтвердить» → наличные или перевод
- Без права: сумм и статусов нет, подсказка «попросите включить приём оплаты»
- «Пришёл без записи»
- Сохранение отметок пакетом

**Данные и API** (по спецификации; точные маршруты и имена — в контракте)

- P-19 attendance, P-20 payment-confirm

## Критерии приёмки

- ✅ Тренер без флага не видит ни одной суммы
- ✅ Подтверждение оплаты тренером видно в кассе как «на зале · тренер …»
- ✅ Экраны совпадают с макетом: отчёт харнесса визуальной сверки 19.0.2 или ручной сверки в теле PR
- ✅ Доступ к экрану проверен для каждой роли
- ✅ Пять gates CODING_STANDARDS на tested revision; ревью `claude-opus-5-5` без Critical/Important
