## Методика

- Срез `main`: `git fetch origin && git log --oneline -1 origin/main` → `e6e0e21`. Изменения между проходами: PR #194 (кассa кабинета, 21.2.3), #195 (21.1.8), #196 (карточка 21.2.19, документы); команды LEG-01…LEG-05, LEG-17 повторены на `e6e0e21`, результат прежний. `readEventPricing` ни одним из PR не тронут, см. LEG-17.
- Прежние заметки первого прохода использованы как гипотезы; каждый пункт перепроверен. Расхождения с заметками: утверждение «API подтверждения/отклонения/блокировки участников без потребителя» **неверно** (маршруты вызываются динамически: `act(m, 'approve')` в `apps/web/app/pages/m/orgs/[orgId]/members.vue`), потребителя не имеют только `members/[memberId]/level` и `members/leave`. Утверждение «драйверов Unisender нет» тоже было **неверным** (`packages/auth/src/email/unisender-driver.ts`), см. LEG-07 и LEG-29.
- Поиск: `rg`; строковые шаблоны регистронезависимы (`rg -in`) там, где имя может встречаться в другом регистре (имена сервисов и переменных окружения). В Git Bash на Windows шаблоны, начинающиеся с `/`, подменяются путём; шаблоны даны без ведущего `/` или с `-F "}/…"`. Проверки, не сводимые к одному `rg`, делались временными Node-скриптами вне репозитория (обход `apps/` и `packages/`, поиск по имени, исключение `*.test.ts`); результат воспроизводится ручным `rg` по имени.
- «Нет потребителя» = нет ссылок в нетестовом коде `apps/`, `packages/`, `scripts/`, workflows и в живых документах, включая динамические шаблоны строк (`${…}`/`'approve' | 'reject'`). Трафик и production-логи не использовались.
