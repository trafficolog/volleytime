## Методика

- Срез `main`: `git fetch origin && git log --oneline -1 origin/main` → `c919ee8`. Изменения после первого прохода аудита: [PR #195](https://github.com/trafficolog/volleytime/pull/195), `git diff --stat b4186e3 origin/main` (16 файлов); `readEventPricing` в #195 не тронут, см. LEG-17.
- Прежние заметки первого прохода использованы как гипотезы; каждый пункт перепроверен на `c919ee8`. Расхождения с заметками: утверждение «API подтверждения/отклонения/блокировки участников без потребителя» **неверно** (маршруты вызываются динамически: `act(m, 'approve')` в `apps/web/app/pages/m/orgs/[orgId]/members.vue`), потребителя не имеют только `members/[memberId]/level` и `members/leave`.
- Поиск: `rg` (в Git Bash на Windows шаблоны, начинающиеся с `/`, подменяются путём; шаблоны даны без ведущего `/` или с `-F "}/…"`). Проверки, не сводимые к одному `rg`, делались временными Node-скриптами вне репозитория (обход `apps/` и `packages/`, поиск по имени, исключение `*.test.ts`); алгоритм описан в соответствующем разделе, результат воспроизводится ручным `rg` по имени.
- «Нет потребителя» = нет ссылок в нетестовом коде `apps/`, `packages/`, `scripts/`, workflows и в живых документах, включая динамические шаблоны строк (`${…}`/`'approve' | 'reject'`). Трафик и production-логи не использовались.
