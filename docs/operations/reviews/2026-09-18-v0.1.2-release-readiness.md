# Release-readiness review v0.1.2 → v0.1.3 (2026-09-18)

## Scope

Проверка перед первым каноническим GitHub/production release-gate. Источник реализации — предоставленный Git-архив `main@v0.1.2`; Claude Design export используется только как UI reference. Product scope не расширяется за R0/MVP (phases 3, 4, 5, 6, 8, 9).

## Вердикт

**Repository release-gate теперь воспроизводимо зелёный, но production/R0 approval всё ещё не закрыт.** После публикации canonical GitHub PR #1 прошёл format/lint/typecheck, unit+integration tests и build. SDD reconciliation Task 9.11.2 устранил исторический status drift: 119 non-done → 18 cards на reconciliation, затем 17 после закрытия 4.7.5.

Оставшиеся blockers/gates разделены: repository gap (9.8.3), manual Telegram QA (8.7.2/8.8.11) и external Phase 9 production operations. Поэтому корректный статус — **repository CI green / release candidate; production MVP not yet proven**.

## Находки текущей итерации

### RR-1 — Node runtime drift — исправлено

**Уровень:** P1 release/configuration.

- `.nvmrc` указывал Node 20;
- `package.json` допускал `>=20`;
- CI, deploy workflow и все production Dockerfile фактически используют Node 22.

Это делало локальный documented runtime отличным от release runtime. В `v0.1.3` target унифицирован на Node 22 (`.nvmrc`, package engine, architecture current decision). Исторические task cards не переписываются.

### RR-2 — status/documentation drift — исправлено

**Уровень:** P2 documentation/release control.

`README.md` и нижняя часть `docs/operations/status/current-state.md` одновременно содержали уже актуальный `v0.1.2` статус и дореализационные утверждения: «реализация — следующий шаг», Phase 3 todo, GitHub не создан, монорепо не инициализировано.

В Task 9.11.1 snapshot переписан как единый источник текущего состояния; root README теперь явно различает `code-complete / release candidate` и `production-validated`.

## Security / tenant / money spot-check

Проверены наиболее рискованные границы после предыдущих hardening-релизов:

- organization API защищён tenant middleware (`resolveTenant`) и policy checks;
- ID-based event/payment/booking routes дополнительно сравнивают `organizationId` перед мутацией;
- booking creation проверяет event→organization и активное membership;
- roster/listing queries ограничены organization/event scope;
- payment confirm/reject передаёт `orgId` в сервис и проверяет принадлежность payment;
- event cancel выполняется транзакционно и восстанавливает subscription/payment state;
- auth rate limiter доверяет forwarded chain только при `TRUSTED_PROXY=1`; regression tests существуют;
- webhook в Caddy использует точное совпадение секретного path; Telegram `secret_token` проверяется grammY;
- production secrets не обнаружены в tracked files: `.env.example`/`.env.prod.example` содержат шаблоны, реальные `.env` не отслеживаются;
- smoke проверяет health, auth endpoint, подписанный Telegram initData, forged initData и webhook route; cleanup smoke-account предусмотрен.

В исходниках остаётся TODO в event cancellation для Phase 7 credit refund / Phase 15 scheduled jobs. Это соответствует roadmap и не блокирует R0.

## UI / Claude Design reference

Design export содержит смесь MVP и будущего roadmap: web organizer cabinet, root admin, Credits, Contributions, Reports, online payments и другие Phase 10+ screens. Для R0 сравнивались только MVP flows.

В текущем Nuxt присутствуют R0-маршруты для:

- входа email + Telegram Mini App bootstrap;
- списка/создания организаций и invite redemption;
- dashboard организации;
- events list/create/detail/edit/manage;
- booking/waitlist/cancel/attendance;
- members + pending/rejected/blocked moderation;
- invites;
- subscription plans + user subscriptions;
- pending payments + confirm/reject;

Ключевые состояния из референса также представлены: pending payment, waitlist, confirmed booking, cancellation, empty states, organizer-only sections. Не реализованные Credits/Root Admin/Contributions/Reports/online-payment screens относятся к последующим релизам и не классифицируются как R0 gap.

## Static repository checks

На release branch выполнены без внешних зависимостей:

- `git diff --check` — чисто после исправления whitespace;
- root/package JSON parse — успешно;
- release Node target consistency: `.nvmrc`, package engine, Dockerfiles и workflows согласованы на Node 22;
- tracked-secret pattern scan — production credentials не найдены;
- merge-conflict marker scan — конфликтов нет;
- modified-document local-link check — после создания этого отчёта должен быть 0 broken links.

Свежая проверка `corepack pnpm --version` завершилась `exit=1`: sandbox не может скачать `pnpm-12.4.1.tgz` с `registry.npmjs.org` (network/DNS unavailable) и не содержит `node_modules`. Поэтому `pnpm test/lint/typecheck/build` локально не может считаться свежим evidence. Эти проверки переносятся в GitHub Actions release-candidate PR.
