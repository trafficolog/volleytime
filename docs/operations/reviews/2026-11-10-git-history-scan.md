Дата: 2026-11-10. Задача: [27.2.3](../../tasks/27-2-3-repo-history-scan.md). Отчёт не содержит найденных значений: только короткий SHA коммита, путь, тип находки и оценка.

## Метод

- Охват: `git log --all -p` по всем 986 коммитам и всем ссылкам (добавленные строки, включая бинарные файлы как текст), на состоянии `origin/main` `74ee34a6`.
- Инструменты: встроенный `git` и собственный скрипт (Python, без установки пакетов и без загрузок). gitleaks локально не запускался (установка не разрешена); та же проверка для новых коммитов добавлена в CI ([`secret-scan.yml`](../../../.github/workflows/secret-scan.yml)).
- Шаблоны: токены Telegram-ботов, приватные ключи, ключи AWS, токены GitHub/Slack/Stripe/Google, JWT, `Bearer`, SSH-ключи, присваивания `password|secret|token|api_key|…` с непустым значением, строки подключения и URL с паролем, IPv4 вне приватных и документационных диапазонов, телефоны (РФ), e-mail, Telegram `@`-ники и `t.me`-ссылки, числовые Telegram/chat ID, куки сессий, имена файлов (`.env`, `*.pem`, `*.key`, дампы, `.har`).
- Ограничение: сканирование по шаблонам не находит секреты нестандартного вида, а содержимое растровых изображений (скриншоты) не распознавалось.

## Итог

**Находок уровня «похоже на реальный действующий секрет» нет.** Ротация секретов не требуется. Есть несколько находок о личных и операционных данных, по которым нужно решение владельца (раздел «Решения владельца»).

## Решения владельца

Решения по критерию приёмки «найденные секреты отозваны или ротированы» не нужны: секретов нет. Нужны решения по приватности (задача запрещает переписывать историю без владельца):

1. F-01: достаточно ли удаления из актуальной версии, или переписывать историю (`git filter-repo` и force push; сломает SHA в ссылках PR и карточках, потребует перепривязки). Если ник личный, то он останется в истории и в форках/кэшах GitHub даже после переписывания.
2. F-04: принять публичное имя автора и рабочий e-mail в метаданных или переписать авторство. Для новых коммитов можно включить GitHub-режим «Keep my email addresses private» и `noreply`-адрес (настройки аккаунта, вне кода).
3. F-02: убрать числовой ID технического аккаунта из актуальных документов (не нужен для работы) или принять как есть.
4. F-03: принять как публичный адрес домена.

## Проверка новых коммитов (критерий приёмки)

Добавлен workflow `.github/workflows/secret-scan.yml`: `gitleaks/gitleaks-action` v2.3.9 (закреплён по SHA коммита), `permissions: contents: read`, полная история для вычисления диапазона. Лицензия не нужна: репозиторий принадлежит личному аккаунту (README action: ключ нужен только организациям). Комментарии в PR, summary и артефакты отключены, так как репозиторий публичный: результаты остаются только в журнале job (значения скрываются самим action).

Остаточный риск: правила gitleaks по умолчанию могут срабатывать на тестовые токены-фикстуры в новых коммитах; тогда допускается точечный `.gitleaksignore` по отпечатку находки (не по пути целиком) отдельным PR.
