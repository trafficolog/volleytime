# R0.6 / 8.10.3 — Chrome 200%: авторизация и Mini App игрока

Статус: локальный визуальный проход; не Telegram WebView, не production и не итоговая приёмка R0.6.

## Условия

- Отдельный headed Chrome persistent profile. В `chrome://settings/appearance` выбран штатный **«Масштаб страницы: 200%»** (`#zoomLevel = 2`), без CSS `zoom` или подмены результата viewport resize. Окно Chrome 1440×900 физических пикселей, приложение сообщило `devicePixelRatio = 2`, `innerWidth = 712` CSS px и `innerHeight = 402` CSS px. Проверялся локальный built preview `http://127.0.0.1:3168/` на QA-БД `volleytime_qa_8101_selfcheck`, с тестовой email-сессией игрока; production данные не использовались.
- Chrome `Page.captureScreenshot` снимал видимую область при этом нативном zoom через CDP: стандартный Playwright `page.screenshot` на этой настройке обрезал физическую область, поэтому его кадр **не** использован для визуального вывода. Показанные в текущем QA-прогоне кадры CDP просмотрены вручную. Группа сохранена также в ignored artifact `output/playwright/r06-native-zoom-player-groups.png`; остальные кадры этого прохода выведены в QA-инструмент, но не являются версионированными файлами репозитория.
- Проверялись отсутствие горизонтального переполнения (`documentElement.scrollWidth <= innerWidth`), доступность верхней и нижней частей прокруткой и сохранение фиксированной нижней навигации. Это не pixel-perfect аудит каждого экрана и не повторение всех денежных POST.

Ранее пользователь уже прислал native 200% для лендинга, Home организатора и desktop finance, а также подтвердил экранный диктор для finance. Остальные native 200% экраны не заявляются автоматически. Реальный Telegram-host и двухаккаунтный пилот остаются после controlled deploy полного кандидата.
