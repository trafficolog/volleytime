# QA 20.3.3 — Telegram-бот v3: визуальная сверка с макетом «2 Telegram Bot»

Дата: 2026-10-19. Задача: [20.3.3](../../tasks/20-3-3-telegram-bot.md). Метод: структура сообщений и клавиатур, которые строит код бота (`apps/bot/src/handlers/*`, `packages/core/src/notifier/templates.ts`), сверена с исходником макета `handoff/screens-bot.jsx` и скриншотами `screenshots/2-bot/01..04`. Telegram рисует пузыри, кнопки и тосты сам, поэтому сверяются состав и порядок текста, подписи кнопок, тип кнопок и паттерн отклика, а не пиксели. Харнесс 19.0.2 для бота неприменим (нет HTML-страниц). Проверка на устройстве — отдельный шаг Telegram QA владельца (см. «Осталось владельцу»); репозиторные тесты её не заменяют.

## Ограничения Bot API, которые соблюдены (из шапки макета)

| Правило макета                                        | Реализация                                                                                                                       |
| ----------------------------------------------------- | -------------------------------------------------------------------------------------------------------------------------------- |
| Inline-кнопки только текст, эмодзи допустимы          | Подписи без графики; тест проверяет `callback_data` ≤ 64 байт                                                                    |
| Тело — подмножество HTML (`b`, `i`)                   | Только `<b>`, `<i>`; пользовательские названия экранируются (`esc`), тест на `<b>` в названии события                            |
| Нажатие не создаёт сообщение: toast + правка на месте | `answerCallbackQuery` (тост) + `editMessageText` с сохранением `entities`; повтор «message is not modified» проглатывается, тест |
| Reply-клавиатура над полем ввода, шлёт текст          | `Keyboard` `resized`, `persistent`; кнопки «Расписание», «Мои записи», «Помощь» обрабатываются `bot.hears` только в личном чате  |
| Сообщения статичны, абсолютный дедлайн                | Время событий — абсолютное, в часовом поясе группы; таймеров нет                                                                 |
| Статусы эмодзи-кружками, счёт места словами           | `🟢 / 🟡 (≥ 75 %) / 🔴`, «занято 12 из 14», «мест нет»                                                                           |

## Расхождения с макетом (приняты, не Critical/Important)

1. **«Буду» (2 ч) и «Пропущу» (место)** не реализованы. В домене нет подтверждения присутствия; «Пропущу» (досрочный отказ от предложения) меняет очередь и требует решения по D-03 (сейчас отказ = истечение 30 мин). Это новая доменная логика вне карточки — вынесено владельцу (вопрос 1).
2. **«Мой абонемент», «Сборы», «Кто уже играет», «Не сейчас»** в меню и приветствии нет: данных и сценариев для них в карточке нет, остальной функционал — в Mini App.
3. **«Записаться» кнопкой бота** нет: запись требует выбора способа оплаты, мест и режима приглашения, поэтому ведёт в Mini App (`startapp=event_<id>`).
4. **Подтверждение отмены** (нет в макете) добавлено сознательно: отмена необратима (место уходит очереди), а нажатие по соседней кнопке в чате случайно.
5. «Тост «Вы в группе» и правка сообщения приглашения» относятся к принятию приглашения в Mini App (20.4.7), не к боту.
