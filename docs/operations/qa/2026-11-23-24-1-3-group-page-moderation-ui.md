# 24.1.3 · Модерация страниц групп, шаг UI — ручная сверка (2026-11-23)

- **Харнесс 19.0.2:** не применяется. В карточке `reference.screens: []`, а для Root Admin действует [D-16](../decisions/2026-10-12-reference-v3-decisions.md#d-16): сверка вручную, 1440x900 и 375x812, роль root в харнесс не добавляется. Макет — прототип [`screens-moderation.jsx`](../../design/reference-v3/handoff/screens-moderation.jsx) (данные и вёрстка не копировались).
- **Стенд:** production-сборка (`node .output/server/index.mjs`) на свободном порту, собственная БД PostgreSQL 16 с применёнными миграциями (0046 включительно), демо-сид и несколько групп в разных городах; вход через Telegram-подпись тестового токена, root выдан в БД. Данные и сервер после проверки удалены.
- **Скриншоты в репозиторий не добавляются** (правило D-16 и карточки): результаты ниже.

## Root · «Жалобы на страницы» (`/root/page-complaints`)

- «Новые / Решённые», KPI (новые и самая старая, решено за 30 дней и среднее время, отсечено лимитом), причина, текст или «без текста», источник «вход» (@username) или «посетитель», возраст — на обоих размерах.
- «Отклонить» убирает жалобу из «Новых» и переносит в «Решённые» с итогом; «Noindex» из жалобы открывает окно с причиной по умолчанию (мошенничество → «Оплата в обход записи») и закрывает жалобу решением.
- На телефоне строка жалобы собирается в столбец (исправлено по результатам сверки: колонка № слева, страница справа от неё).

## Публичная страница `/g/<slug>`

- Кнопка «Пожаловаться на страницу» — настоящая `<button>` с `aria-haspopup="dialog"`; окно — `role="dialog"` с заголовком, причины в `fieldset`, фокус на первой причине, Esc закрывает, фон недоступен.
- Отправка без причины невозможна; после отправки — «Спасибо / Модератор посмотрит в течение суток…».
- Четвёртая жалоба за сутки с того же адреса: `429 group_page.complaint_limited` показан в окне как «Не больше 3 жалоб в сутки» (`role="alert"`), форма остаётся.
- Скрытая решением страница отдаёт 404 (проверено запросом).

## Кабинет «Страница группы»

- Баннер решения вместо статуса индексации: причина, «Что исправить», время, четыре факта; для noindex при включённой индексации — пояснение, что её перекрывает решение; для скрытия — «404 по ссылке». Автора решения нет, кнопок «Ответить модератору» и «Исправил — запросить проверку» нет.
- Переключатель индексации заблокирован с подсказкой «Пока действует решение администрации, переключатель не работает»; прямой `PATCH …/settings { seoIndex }` даёт `409 group_page.moderation_locked`.
- На телефоне баннер и факты в две колонки без прокрутки вбок.

## Расхождения с макетом (не дефекты)

- Фильтр «Скрытые и noindex» назван «С решениями» (формулировка задачи).
- В «Жалобах» вкладки «Новые» и «Решённые» без «Все» (формулировка задачи).
- Ссылки «Жалобы на организатора и оплату — в разделе Жалобы» нет: такого раздела в Root Admin пока нет, в подписи оставлен текст без ссылки.
- Причина решения не предвыбирается, пока модератор не выбрал её (у «Другое» в жалобе предвыбора нет); в макете по умолчанию была первая.

## Не проверено

- Реальная доставка сообщения в Telegram-бот (проверяется на контрактном шаге и в боевом QA); здесь проверен текст превью, совпадающий с шаблоном.
