Дата: 2026-09-24. Ветка: `trafficolog/feat/8.10.1-player-miniapp-v2`, первоначальный browser smoke после `af64657`. Стенд: локальная Nuxt production-сборка на `localhost:3100`, отдельная PostgreSQL `volleytime_qa`; не production и не Telegram-host. Данные созданы только для этой проверки: тестовая группа, два опубликованных события, один план, аккаунты владельца и игрока.

## После независимого code review

Ревью обнаружило четыре расхождения, внесённые в SDD-карточку: CTA при ошибке обновления с сохранёнными данными, недостижимое информационное состояние приостановленной группы, пустой статус отменённой записи и слишком маленькая цель раскрытия истории абонемента. Для первых трёх добавлены RED-тесты (3 падения), затем исправлены проекции и их применение в страницах; кнопке истории добавлены высота 44 px и `aria-expanded`. Повторная проверка после правок: `pnpm format:check`, `pnpm lint` (0 ошибок, 18 предупреждений), `pnpm typecheck`, `pnpm test` (91 файл, 497 тестов), `pnpm build` (2 задачи) — все с кодом 0. Независимый повторный code review подтвердил закрытие четырёх замечаний и не нашёл новых подтверждённых регрессий. Повторный браузерный проход по этим четырём состояниям ещё не выполнен.

После новой сборки и повторного email-OTP входа тестового игрока detail платного события снова отобразил реальное `pending_payment` и кнопку отмены. Нажатие открыло системный confirm с ожидаемым вопросом; управление этим диалогом в автоматизированном браузере прервалось. Последующее чтение локальной QA-БД подтвердило, что бронь получила `cancelled`, `cancelled_at` и освободила место (`0/12`). При этом Home ошибочно оставил её в ближайших записях с подписью «Записан», а detail не показывал статус отмены. Дефект синхронизирован с SDD-карточкой до исправления.

## Дополнительный RED → GREEN и повторный браузерный smoke

Для read-model отменённой записи добавлены RED-тесты событий, списка бронирований, API и UI-проекции (4 ожидаемых падения). Исправлено: `myBooking` передаёт отменённую бронь в detail и карточки, не увеличивая занятость; dashboard исключает отмены **до** `limit: 3`, не меняя обычный `/bookings/my`; карточка события показывает нейтральное «Запись отменена». Повторный targeted run прошёл 55 тестов. Затем прошли `pnpm format:check`, `pnpm lint` (0 ошибок, 15 предупреждений), `pnpm typecheck`, `pnpm test` (91 файл, 501 тест), `pnpm build` (2 задачи).

На локальной собранной версии detail отменённого события показал «Запись отменена», `0/12` и доступную повторную запись; Home убрал событие из «Моих ближайших записей», а карточка расписания показала отмену. Через UI игрок повторно записался с методом «перевод»: detail показал `1/12` и «Ждёт оплаты», чтение QA-БД подтвердило ту же бронь в `pending_payment` с методом `transfer` и пустым `cancelled_at`. Это локальный тестовый выбор способа оплаты, не подтверждение реального денежного перевода.

При 320×700 CSS px detail и ещё пять маршрутов (`events`, `bookings`, `subscriptions`, `profile`, `orgs`) загрузились без горизонтального переполнения: `scrollWidth` был 305–320 при `innerWidth=320`; tab bar detail оставался в viewport (`left=12`, `right=293`, `bottom=686`). Это частичный responsive smoke, не сравнение всех экранов с референсом.

После перезапуска локальной сборки тестовый игрок повторно вошёл по email OTP. При 390×844 CSS px семь маршрутов (`Home`, `events`, `event detail`, `bookings`, `subscriptions`, `profile`, `orgs`) показали содержимое из QA-данных; `scrollWidth` составил 375 для экранов группы и 390 для обзора групп при `innerWidth=390`. Горизонтального переполнения на этих маршрутах нет. Сравнение структуры и стилей каждого экрана с референсом этим замером не выполнено.

## Открыто до приёмки 8.10.1

- Сквозная отмена подтверждена переходом локальной QA-БД в `cancelled` после UI-действия и последующим видимым состоянием; однако автоматизированное управление нативным confirm прервалось, поэтому повторяемый browser-проход через OK и Telegram-host проверка ещё нужны.
- Не проверены фактически: реальный перевод/подтверждение платежа, подтверждённый активный абонемент и списание/возврат занятия, лист ожидания/повышение, серверный отказ при устаревшей вместимости или дедлайне, быстрое переключение A→B, прямой URL истории при скрытом пункте меню, потеря сессии, pending/suspended участник.
- Визуальная матрица по всем экранам на 320 и 390 px, Telegram-dark, 200% zoom, reduced motion и safe-area ещё не завершена. Снимки экрана в этом прогоне осмотрены, но не сохранены как артефакты. Responsive smoke без переполнения не подтверждает соответствие v2-референсу.
- Browser smoke по замечаниям review ещё открыт; независимый повторный просмотр кода завершён без новых замечаний.
- Реальная проверка внутри Telegram на двух аккаунтах относится к отдельному gate 8.10.3 и этим локальным прогоном не заменена. `main`, `prod` и VPS не менялись.
