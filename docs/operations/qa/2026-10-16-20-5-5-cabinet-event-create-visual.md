## Ограничения сверки

- Смотрели глазами снимки в обеих темах; pixel-diff только ориентир. Референс — превью 924×540, размеры брались из исходников `screens-web-forms.jsx` и `screens-schedule.jsx` (`RecurrenceBlock`).
- Предпросмотр серии и баланс на снимках — живой ответ `POST …/series/preview` демо-группы (34 события на балансе). Нехватку баланса снимали, временно поставив группе остаток 3 (потом 34 возвращён): «Нужно 14 событий, на балансе событий 3. Опубликуем первые 3, остальные 11 станут черновиками до пополнения», черновики подсвечены янтарным.
- Сохранение (создание серии, повтор с тем же ключом, ошибки сервера) проверено интеракционными тестами формы и контрактными тестами тел запросов против zod-схем API (`PreviewSeriesInput`, `CreateSeriesInput`, `CreateEventInput`); реальный `POST …/series` и идемпотентность покрыты интеграционными тестами 20.2.2. Кликами в живом браузере с записью в БД создание не проверялось.
- MainButton Telegram (`createMainButton`, решение владельца 2026-10-15) относится к Mini App и явно отложен до 21.1.2; кабинет использует обычную кнопку формы.
- Скринридер вручную не прогонялся; доступность проверена ролями и связями label / описание / ошибка в тестах (фокус на первом неверном поле, `role="alert"`, `aria-invalid`, имена у атомов).
- Отдельно нарисованного экрана «серия создана» в референсе нет: итог серии (сколько опубликовано, сколько черновиков, остаток баланса) собран из атомов и токенов.

## Differences

- **Закрыто follow-up'ом 2026-10-16:** селектор «Запись закрывается за 1 / 2 / 6 / 24 ч» (`closeBeforeMinutes`, по умолчанию 2 ч, `VtSegment` в виде чипов в колонке «Состав и запись») добавлен после поля сервера из 20.3.1 (PR #150); повторный прогон харнесса `cabinet-event-new`, `-series`, `-split` (`output/visual/20261016-1552*`, светлая и тёмная темы) расхождений не выявил. Значение уходит при создании всегда (и в шаблон серии), при правке — только если изменено.
- **Принято владельцем 2026-10-16 (все отклонения формы ниже; журнал решений, заметка «2026-10-16 · Форма W-04 (ревью PR #149, 20.5.5)»).**
- **Minor:** тип события — три значения API (`Тренировка`, `Открытая игра`, `Другое`); в макете четыре («Основа», «Открытая игра», «Микст», «Турнир»), «Микст» и «Турнир» в схеме нет.
- **Minor:** «Дата» и «Время» объединены в одно поле `datetime-local` плюс выбор длительности (в макете дата, начало и конец отдельными полями); число мест — числовое поле вместо кнопок «−/+».
- **Minor:** кнопка «Создать N событий» стоит внизу формы, а не в шапке страницы справа (кнопка внутри формы, чтобы Enter и фокус работали одинаково в кабинете и Mini App); «Отмена» — ссылка «К событиям» вверху.
- **Minor:** «Мест на игрока» показано строкой из настроек группы (поле события для него не предусмотрено ADR, лимит принадлежит группе).
- **Minor:** `VtSelect` в серой карточке без фона сливался с карточкой; добавлено правило в `main.css` для `.vt-event-form`.

- **Вне карточки:** отмена и правка серии из кабинета («это и последующие») — интерфейс принадлежит карточке события (W-05, 20.5.6); сообщение `series.from_in_past` уже добавлено в общий словарь ошибок.
