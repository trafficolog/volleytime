## Ключевые решения

### Тарифная сетка (вариант C — изменение пользователя)

Вместо фиксированных пакетов — настраиваемая таблица credit_pricing_tiers (min_quantity → price_per_credit). Flat-tier: для Q берётся tier с наибольшим min ≤ Q, ВСЕ Q по этой цене (Q=35 → 35×3.50, tier min=30). Покупатель вводит любое количество (тест тоже), цена авто. Root-admin редактирует сетку целиком (replaceTiers, валидация: начало с 1, возрастание, положительные). Старые деактивируются (история цен). Дефолт: 1→5.00, 10→4.00, 30→3.50, 100→3.00 BYN.

### Credit account + transaction (append-only)

Баланс денормализован в account + balanceAfter в каждой транзакции (audit + сверка). addTransaction — единая точка изменения баланса (grant/spend/refund/purchase). Защита от минуса (InsufficientCreditsError). balance == SUM(amounts) инвариант.

### Spend/refund логика

Создание Event → spend −1 (атомарно, откат если 0). Отмена до открытия записи (нет броней) → refund +1; после (были брони) → потрачено. Отдельно от player mass refund (6.4.1) — два разных refund в cancel.

### Заявки на покупку

Организатор → заявка (цена фиксируется по сетке на момент) → уведомление root-админу → согласование оплаты (перевод) → root confirm → grant credits + уведомление организатору. Идемпотентно. Цена не пересчитывается при смене сетки (фиксирована).

### Root-admin = расширенный super-admin (10.3)

Не новый слой. Добавлено: grant credits, confirm/reject заявок, управление тарифной сеткой, audit транзакций. requireSuperAdmin (10.3.1).

### Платформенный учёт

Покупка фиксируется в EventCreditTransaction (количество + priceAmount). Без отдельного платформенного ledger (это доход платформы, не org-кассы Phase 6). Полноценный финучёт платформы — отдельно (Трек A, налоги).
