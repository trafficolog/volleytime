## Ключевые решения

### Allowlist (10.1)

Создание организаций — только приглашённые (beta_allowlist по telegram_id). Игроки свободны (org-invite Phase 4). Beta-флаг (BETA_ALLOWLIST_ENABLED) отключает при выходе из беты. Bootstrap: первый организатор через seed/CLI.

### Feedback-кнопка (10.2)

Кнопка в Mini App → служебный Telegram-канал (через bot transport 8.4.1). Контекст (экран, орг) автоматически. Снижает трение репорта.

### Super-admin обзор (10.3)

Вне org-ролей (владелец платформы по telegram_id в env). Read-only обзор бета-организаций + метрики активности + гейт-метрики (value/target) + управление allowlist. Системный доступ не нарушает обычную tenant-изоляцию.

### Ретеншн-метрика (10.3.2, 10.6.1)

Главный сигнал ценности: организаторы с событиями ≥4 недели подряд. «Накрутить» события энтузиазмом первой недели можно, ретеншн — нет.

### Гейт decision framework (10.6.1)

A (пройден → Phase 7) / B (частично → доработки) / C (провал → pivot). Готовность платить — прямой вопрос организаторам (не угадывать). Антипаттерн: размывание критериев чтобы «пройти». Decision-документ фиксируется.

### Операционные runbooks (10.5)

onboarding-чеклист (повторяемое подключение), support-runbook (severity P0/P1/P2, типовые проблемы из Трека B, эскалация), feedback-трекинг (GitHub Issues, частота×влияние, → FAQ для повторов).

## Что даёт пройденный Трек B

- Типовые проблемы (support-runbook) — на основе реального опыта, не гадания
- FAQ — на основе реальных вопросов своей группы
- Onboarding — формализован из реального процесса
- Бета проверяет переносимость (чужие организаторы), а не «работает ли вообще»
