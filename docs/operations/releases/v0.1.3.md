# Volley Time v0.1.3 — verified production baseline

**Release date:** 2026-09-19

**Commit:** `91f6bffbd005876f94ffd1c31cebb4bcd891a752`

`v0.1.3` records the first verified production baseline for `volleytime.by`. The release does not add product scope; it combines the release-readiness work with the production fixes merged through PRs #6-#15.

## Verified live evidence

- GitHub `main`, GitHub `prod`, the local `main` reference and the VPS `prod` checkout resolved to the release commit.
- `https://volleytime.by/api/health` returned HTTP 200 with database and authentication schema checks reported as `ok`.
- `vt_postgres`, `vt_web` and `vt_bot` were `healthy`; `vt_caddy` was running.
- The Docker backend network had IPv6 enabled with subnet `fd3f:fc9a:f0f4::/64`.
- Telegram `getMe` succeeded for `@volleytimeby_bot` through the concrete IPv6 address `2001:67c:4e8:f004::9`.
- The bot started in webhook mode and registered the production HTTPS webhook.
- Pre-release backup `/opt/volleytime/backups/volleytime_20260919_162625.sql.gz` had mode `0600`, size 6857 bytes and passed gzip validation.
- The backup restored into an isolated PostgreSQL 16 container; 15 public tables and the critical MVP tables were readable. The pilot database contained zero users, events and bookings at the time of the snapshot.

## Known release boundaries

- Deployment was performed through the manual local-build path. GitHub Actions production Secrets and automatic deployment were not configured.
- Locally built application containers reported `release: dev`; the running source commit was verified separately.
- Sentry event delivery and external UptimeRobot monitoring were not configured.
- S3 upload, retention and S3-based restore remained deferred for the pilot; release-local database dumps and provider-level server backups were active.
- Telegram Mini App client QA, BotFather menu/deep-link acceptance, real notification delivery and the one-week real-training MVP gate remained open.

These boundaries are addressed or preserved explicitly by the `v0.1.4` production automation plan. They must not be interpreted as completed acceptance criteria for `v0.1.3`.
