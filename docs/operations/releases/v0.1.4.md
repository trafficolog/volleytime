# Volley Time v0.1.4 — production automation

**Release date:** 2026-09-21

**Tested code candidate:** `c8648c25ce2e1955806cb051af5365089945d2ca`

`v0.1.4` automates the already deployed R0/MVP code without adding product scope. The immutable annotated tag is the authority for the final docs-inclusive production SHA; it is created only after this release documentation is merged, promoted through `prod`, deployed and verified on every release-identity surface.

## Included

- production deploy only from GitHub `prod`, after repository tests and source gating;
- a dedicated restricted GitHub Actions SSH credential and fail-closed production Secret materialization;
- exact-SHA Git bundle delivery that does not require the VPS to contact GitHub or GHCR;
- local PostgreSQL backup before checkout advancement and migrations;
- SHA-tagged local web, bot and migrator images with deterministic health identity;
- exact-release smoke checks and same-SHA-safe rollback manifests;
- explicit ancestor rollback, including identity compatibility for the legacy v0.1.3 Compose revision;
- production Telegram polling fallback while outbound IPv6 works and provider IPv4 webhook ingress does not reach the VPS.

## Operational path

The active path is `task branch → main → prod → verified bundle/local build on VPS`. GHCR remains an explicit manual alternative only; its availability is not required for production. Failed backup, bundle identity, ancestry, migration, health or expected-release checks stop the release or enter the documented application rollback path.

## Explicit exclusions

This release does **not** claim full R0/MVP acceptance. The following gates remain open:

- complete Telegram Mini App QA on real clients/accounts, including BotFather menu/domain, deeplinks and initData login;
- direct Telegram webhook ingress; polling is the approved production transport until provider IPv4 routing is repaired;
- a real web-to-bot notification-delivery scenario;
- controlled Sentry web/bot events and external UptimeRobot alerting;
- S3 upload, retention and S3-based restore (release-local dumps and provider-level server backups are active meanwhile);
- the one-week real-training pilot required by the R0 Definition of Done.

No secret values, private keys, webhook paths or bot tokens are part of this release record.
