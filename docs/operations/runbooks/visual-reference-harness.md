# Харнесс визуальной сверки с референсом v3

Задача [19.0.2](../../tasks/19-0-2-visual-reference-harness.md). Локальный инструмент для UI-задач фаз 19–26: снимает экраны приложения и кладёт их рядом со снимками референса. **Не CI-gate**: шрифты и антиалиасинг отличаются между ОС, поэтому pixel-diff — только ориентир.

## Что делает

- Mini App снимается в 390×820, кабинет и экран входа — в 1440×900, в светлой и тёмной теме (класс `dark` на `<html>`, как в приложении).
- Данные — демо-сид 19.2.1 (`VolleyTime Минск`, `МинскВолей · Воскресные`, `СпайкКлуб`).
- Вход без реальных учётных данных: харнесс привязывает тестовый `telegram_user_id` к демо-пользователю в **локальной** БД (игрок `sonya`, организатор `nikita`, владелец `artem`) и входит через `POST /api/auth/sign-in/telegram` с initData, подписанным тестовым токеном бота. Защита от случайного запуска против чужого окружения: `--base` и `DATABASE_URL` должны указывать на localhost/127.0.0.1/[::1]; authority с несколькими `@` или запятой (мульти-хост) отклоняется, после создания клиента БД проверяются все его фактические хосты, при `NODE_ENV=production` харнесс не стартует. Это защита от ошибок, а не граница безопасности: не запускайте харнесс с боевыми переменными окружения. Тестовый telegram id выбирается свободным (от 7000000001 с шагом 10), занятый другим пользователем не перезаписывается.
- Результат: `output/visual/<время>/report.html` и `report.md` (папка в `.gitignore`), рядом `captures/`, `refs/`, `diffs/`, `results.json`.
- В отчёте у каждого экрана: снимок приложения, снимок(и) референса, пустой список «Differences» для ручных заметок и, с `--diff`, процент отличающихся пикселей.

## Подготовка

1. Локальный PostgreSQL 16 с миграциями и демо-сидом. Даты сида считаются от создания группы и «стареют», поэтому для свежих данных базу пересоздают:

   ```bash
   pnpm dev:db:reset
   pnpm db:migrate
   pnpm db:seed:demo
   ```

2. Приложение запущено с **тестовым** токеном бота (одинаковым у сервера и харнесса):

   ```bash
   TELEGRAM_BOT_TOKEN=111111:visual-harness-test pnpm dev:web
   ```

3. Браузер: по умолчанию системный Chrome (`channel: chrome`), отдельная загрузка браузеров не нужна. Другой путь: `VISUAL_BROWSER_PATH=...` или `--browser-path`.

## Запуск

```bash
export TELEGRAM_BOT_TOKEN=111111:visual-harness-test
export DATABASE_URL=postgresql://postgres:postgres@localhost:5432/volleytime_dev

pnpm qa:visual --list                       # экраны карты
pnpm qa:visual --routes player-home,cabinet-overview --diff
pnpm qa:visual --viewport miniapp --themes light
```

| Опция                         | Назначение                                             |
| ----------------------------- | ------------------------------------------------------ |
| `--routes a,b`                | id экранов из карты (без опции — все)                  |
| `--viewport miniapp\|cabinet` | только экраны выбранного размера                       |
| `--themes light,dark`         | темы (по умолчанию обе)                                |
| `--diff`                      | грубый pixel-diff для темы референса (светлой)         |
| `--base URL`                  | адрес приложения, по умолчанию `http://localhost:3000` |
| `--out DIR`                   | куда писать отчёты, по умолчанию `output/visual`       |

## Карта экранов

`scripts/qa/visual-reference-map.json` — единый файл, который расширяют UI-задачи: `id`, `title`, `viewport` (`miniapp` или `cabinet`), `role` (`player`, `organizer`, `owner`, `anonymous`), `path` с `{org}` и `{event}`, `org` (ключ из `orgs`), `event` (название и статус события демо-сида), `references` (пути внутри `docs/design/reference-v3/screenshots/`), необязательные `referenceCrop` (область снимка-превью без рамки устройства), `steps` (`{ "click": "<selector>" }`, например переключение на календарь), `referenceTheme`, `fullPage`. Схема проверяется unit-тестом `scripts/qa/visual-reference-lib.test.ts` (в том числе существование файлов референса).

Чтобы добавить экран, допишите запись в `screens`, запустите `pnpm test:unit` и `pnpm qa:visual --routes <id>`.

## Как читать pixel-diff

Снимки референса — превью 924×540 с рамкой устройства, а не макет в натуральную величину. Харнесс вырезает `referenceCrop`, приводит оба изображения к ширине 400 px и считает долю пикселей, у которых канал отличается больше чем на 32. Значения 10–35 % для верстки, совпадающей по структуре, нормальны. Используйте процент, чтобы найти экран для ручного разбора, а расхождения фиксируйте в списке «Differences»; размеры и токены берите из `docs/design/reference-v3/handoff/`.

## Как прикладывать к PR

Скриншоты не коммитятся. В описание PR UI-задачи добавьте путь запуска, команду, список экранов и выдержку из «Differences» (критичность — Critical, Important, Minor, как в `.claude/agents/vt-visual-qa.md`). HTML-отчёт при необходимости прикладывают как артефакт вручную.

## Известные ограничения

- Редирект (например, на экран входа вместо запрошенной страницы): снимок попадает в отчёт с предупреждением, а процесс завершается с кодом 1.
- В dev-режиме плашка Nuxt DevTools скрывается стилем при съёмке.
- Экраны с рамкой Telegram (шапка, статус-бар) в референсе отсутствуют в приложении вне Telegram: это ожидаемое расхождение.
- Харнесс не создаёт данные: если события демо-сида в прошлом, пересоздайте базу.
