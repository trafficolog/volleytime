# QA-чеклист MVP (R0 / v0.1.0)

> Ручная проверка перед запуском в реальной группе. Автотесты покрывают логику,
> этот чеклист — то, что видно только в живом Telegram.

## Подготовка

- [ ] Postgres запущен, миграции применены (`pnpm db:migrate`)
- [ ] `.env` заполнен: DATABASE_URL, TELEGRAM_BOT_TOKEN, BETTER_AUTH_*, BOT_INTERNAL_SECRET, WEB_URL
- [ ] Бот создан в BotFather, Mini App domain настроен
- [ ] web (`pnpm dev:web`) и bot (`pnpm dev:bot`) запущены

## 1. Вход (организатор)

- [ ] `/start` в боте → приветствие + кнопка «Открыть Volley Time»
- [ ] Кнопка открывает Mini App, происходит авто-вход (без ввода email)
- [ ] `/help` показывает справку

## 2. Организация

- [ ] Создание организации (название, город)
- [ ] Организация появилась в списке «Мои организации»
- [ ] Страница организации открывается, владелец в списке участников

## 3. Приглашение игроков

- [ ] «Пригласить» → создаётся ссылка `t.me/<bot>?start=org_...`
- [ ] Ссылка копируется
- [ ] Переход по ссылке с ДРУГОГО Telegram-аккаунта → бот пишет про приглашение
- [ ] Открытие Mini App → страница приглашения с названием организации
- [ ] «Присоединиться» → игрок в списке участников

## 4. События

- [ ] Создание события (название, время, вместимость, цена)
- [ ] Событие видно игроку в списке «Предстоящие»
- [ ] Фильтр «Прошедшие» работает

## 5. Запись (ключевой сценарий)

- [ ] Бесплатное событие: игрок жмёт «Записаться» → статус «Записан»
- [ ] Организатору видно игрока в записях события
- [ ] Игроку пришло уведомление в Telegram
- [ ] Платное событие: запись «оплата на месте» → статус «Ждёт оплаты»
- [ ] Организатору пришло уведомление о новой заявке на оплату

## 6. Лист ожидания

- [ ] Событие на 1 место: первый записался, второй → «В листе ожидания»
- [ ] Первый отменяет → второй автоматически продвинут
- [ ] Второму пришло уведомление «Освободилось место»

## 7. Абонементы

- [ ] Организатор создаёт план (например, 8 занятий)
- [ ] Игрок видит план и покупает
- [ ] Запись «с абонемента» → остаток уменьшился на 1
- [ ] Отмена записи → остаток вернулся

## 8. Оплаты и касса

- [ ] Организатор видит платёж в «Ожидают оплаты»
- [ ] «Подтвердить» → запись игрока становится «Записан», игроку пришло уведомление
- [ ] Касса: баланс вырос на сумму оплаты
- [ ] «Отклонить» другой платёж → запись отменена, игрок уведомлён
- [ ] Добавление расхода (аренда) → баланс уменьшился
- [ ] История операций отображается корректно

## 9. Посещаемость

- [ ] Организатор отмечает «Был»/«Не был» для участников
- [ ] Статусы сохраняются

## 10. Отмена события

- [ ] Организатор отменяет событие с оплаченными записями
- [ ] Всем участникам пришло уведомление об отмене
- [ ] Касса вернулась к исходному балансу (доход = расход)
- [ ] Занятия абонементов восстановлены

## 11. Telegram UX

- [ ] MainButton появляется на экране бесплатного события
- [ ] Haptic-отклик при успешной записи
- [ ] Тема (светлая/тёмная) подхватывается из Telegram
- [ ] Offline-баннер появляется при отключении сети

## 12. Устройства

- [ ] iOS Telegram — все ключевые экраны
- [ ] Android Telegram — все ключевые экраны
- [ ] Браузер (вне Telegram) — вход по email-коду работает

## Критерий готовности MVP

- [ ] **Неделя реальных тренировок проведена только через бота** — без Excel и чатов
