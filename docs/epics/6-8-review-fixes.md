# Epic 6.8: Исправления по ревью v0.1.0 — Manual Payments + Ledger

**Цель.** Сделать денежные переходы атомарными и корректными: нет двойного дохода, двойного возврата, бесплатных абонементов; отклонение и отмена не оставляют висячих мест и платежей; UI платежей и кассы по дизайну.

## Контекст

Ревью: 10 параллельных подтверждений одного платежа дали 8 записей дохода по 15 BYN; параллельная отмена события — 2 расхода-возврата; абонементный платёж не создавался (закрыто 5.13.1), а подтверждение активировало абонемент без срока; отклонение оплаты не продвигает лист ожидания и может отменить новую бронь; отмена брони оставляет pending-платёж; расход принимает дробные/отрицательные суммы; касса смешивает валюты. UI: «Платёж #123», «0.00 BYN»→«0,00», ошибки не показываются.

## Definition of Done

- `confirm`/`reject` — условный UPDATE `WHERE status='pending'`; уникальный индекс дохода на `payment_id`
- `eventService.cancel` сериализован (`FOR UPDATE` события), повторная отмена — no-op без возвратов
- Подтверждение абонементного платежа активирует абонемент со сроком `validityDays`; бесплатный — сразу (5.13.1)
- Отклонение оплаты брони = отмена брони через `bookingService.cancel` (промоушен листа ожидания); старый платёж не трогает новую бронь
- Отмена брони отменяет её pending-платёж
- Расход валидируется zod (целые минорные > 0, категория, дата, событие своей организации)
- Валюта события = валюте организации; баланс по валютам
- `payments.user_id` — `RESTRICT`; ручной доход
- Тесты гонок confirm/refund/cancel
- UI «Ожидают оплаты» и «Касса» по дизайну (имена, события, суммы `ru-RU`, группировка по дням, ошибки)
