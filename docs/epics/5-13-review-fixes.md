# Epic 5.13: Исправления по ревью v0.1.0 — Events + Bookings + Subscriptions

**Цель.** Закрыть бесплатные абонементы, утечки данных и действия над чужими организациями, потерю сессий и денег в жизненном цикле броней; довести UI игрока и организатора до дизайна.

## Контекст

Ядро распределения мест держит главное (20 параллельных записей на последнее место → ровно одна), но: абонемент выдаётся бесплатно; список броней события у организатора падает на BigInt и не проверяет организацию (после починки утекли бы email/телефон/telegram id); посещаемость и абонементы работают через границы организаций; промоушен из листа ожидания не списывает сессию; параллельные отмены продвигают одного игрока дважды; повторная запись теряет `subscription_id`/`payment_id`; платные события можно занять методом free/online без платежа; отмена отмеченного посещения возвращает сессию. Навигации и админского UI нет.

## Definition of Done

- Абонемент по платному плану создаётся `pending` с платежом; активация только при подтверждении
- Список броней события: только своя организация, whitelist полей пользователя, без BigInt
- Посещаемость и списание абонемента scoped по организации (и сроку)
- Промоушен с абонемента списывает сессию или ждёт оплаты; отмены сериализованы по событию
- Повторная запись обновляет `subscription_id`/`payment_id`; метод допустим для цены события
- Нельзя отменить attended/no_show и после старта; pending не записывается; черновики скрыты от игроков; capacity ≥ занятых; события только в будущем
- Audit для событий, броней, абонементов и планов
- CHECK/FK на уровне БД; `activate` проверяет статус; `listMyBookings` фильтрует в SQL с пагинацией
- Ротация и окно закрытия записи зафиксированы как отложенные (ROADMAP)
- Время во всех экранах — в TZ организации
- UI: список событий с заполненностью и статусом брони, страница события с составом и отменой, UI организатора (создание события, планы, состав/посещаемость), абонементы с планом и сроком
