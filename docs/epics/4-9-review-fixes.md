# Epic 4.9: Исправления по ревью v0.1.0 — Organizations + Members + Invites

**Цель.** Закрыть эскалацию до владельца, нерабочие и небезопасные инвайты, пустой audit log, недостающие сценарии управления участниками и UI расхождения с дизайном.

## Контекст

Ревью подтвердило изоляцию чтения между организациями, но нашло: организатор назначает себе `owner`; инвайт-ссылки без имени бота; гонку по `max_uses`; отзыв чужого инвайта; отсутствие audit-записей; pending-участника с правами активного; отсутствие approve/reject/unblock; невозможность вернуться после выхода; архивные организации в списке. Визуально — состав «Участник #45», инвайт без настроек, экран приглашения без контекста.

## Definition of Done

- Роль меняет только owner; `ChangeMemberRoleInput` валидируется; свою роль сменить нельзя
- Инвайт-ссылка содержит имя бота; при пустом имени API отвечает 500 misconfigured, а не битой ссылкой
- `max_uses` соблюдается при 25 параллельных redeem
- Отзыв/чтение инвайта scoped по организации
- Все мутации org/members/invites пишут audit в транзакции
- Матрица прав зафиксирована в карточке 4.3.1 и совпадает с кодом
- pending: видит только карточку организации; approve/reject/block/unblock — сервис, API, UI
- Вышедший участник возвращается по инвайту; архивные организации не в списке
- Ошибки валидации → 422 без дампа SQL/zod; tenant берёт pathname
- Состав с именами и аватарами; FK `invite_id`, enum для `role_to_assign`/`default_member_status`
- API-тесты безопасности (4.8.2); UI инвайтов, экрана приглашения и empty state по дизайну
