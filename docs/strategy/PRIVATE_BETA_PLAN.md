# 🚀 Private Beta Plan (Phase 10)

> **Last updated:** 2026-05-25
> Подробный план Phase 10 — закрытого тестирования с 2-5 внешними организаторами.

---

## Цель

Проверить **продуктовые гипотезы** на реальных организаторах вне команды разработки.

Главный вопрос: **«Готов ли реальный мир платить за это?»**

---

## Когда начинаем

Когда выполнены **все** условия:

- ✅ Phase 3-9 завершены (Foundation → Production Deploy)
- ✅ Бот доступен 24/7 на `volleytime.by`
- ✅ Mini App работает в Telegram без багов
- ✅ Базовые сценарии (создать организацию → пригласить игроков → создать тренировку → собрать оплаты) прошли smoke-тест на собственной группе
- ✅ Python-прототип дал минимум 1 месяц обкатки в реальной группе
- ✅ Есть документация для пользователей (FAQ, gif-ки или короткие видео)

---

## Кого приглашаем

### Критерии для beta-организаторов

1. **Активный организатор** — проводит регулярные тренировки или открытые игры (1+ в неделю).
2. **Использует Telegram-чат** для координации игроков. Готов попробовать новый инструмент.
3. **Лояльный знакомый** — не случайный человек, готов давать обратную связь даже если что-то не работает.
4. **Группа 8+ человек** — чтобы было что записывать и за чем наблюдать.
5. **Готов хотя бы 1 месяц использовать** — без этого данных мало.

### Где искать

- Знакомые волейболисты Минска через личные связи.
- Чаты «Волейбол Минск», «Любительский волейбол РБ».
- Чаты в Telegram о любительском спорте.
- Рекомендации от первых beta-участников.

**Не ищем через:**

- Рекламу (рано)
- Open call в каналах (фильтр на 80% случайных)
- SEO / поиск (нет страниц для индексации)

### Целевое количество

**2-5 организаторов** на closed beta.

- Меньше 2 — данные не репрезентативны.
- Больше 5 — не справимся с обратной связью и поддержкой соло.

## Onboarding нового организатора

### Шаг 1: First contact

```
1. Личный разговор / звонок / встреча
2. Демо платформы (10-15 минут)
3. Объяснение что это закрытый beta-тест, бесплатно
4. Согласие на участие + обмен контактами для оперативной связи
```

### Шаг 2: Создание организации

```
1. Организатор регистрируется через volleytime.by или t.me/volleytime_bot
2. Вместе создаём первую организацию
3. Настраиваем базовые параметры:
   - Название (например, «Volley Vitebsk Tuesday»)
   - Город
   - Дефолтные настройки (цена тренировки, лимиты слотов)
4. Создаём первый план абонемента
5. Создаём первое событие (на следующую неделю)
```

### Шаг 3: Импорт игроков

```
1. Организатор делится списком игроков (имена + контакты Telegram)
2. Генерируем 1 общий invite_link на организацию (organization_join, ∞ uses)
3. Организатор рассылает ссылку в свой чат
4. Игроки кликают, попадают в Mini App, видят расписание
```

### Шаг 4: Первое событие

```
1. Игроки записываются через Mini App
2. Организатор видит состав
3. На тренировке — собирает оплаты обычным способом
4. После тренировки — подтверждает оплаты в Mini App
5. Отмечает посещаемость
```

### Шаг 5: Feedback session (через неделю)

```
- 30-минутный разговор
- Что понравилось / не понравилось
- Что сломалось / что непонятно
- Какие фичи не хватают
- Готов ли продолжать
```

## Метрики Private Beta

### Метрики использования

| Метрика                          | Цель               | Как считаем                         |
| -------------------------------- | ------------------ | ----------------------------------- |
| Активные организаторы (DAU)      | ≥ 2 после 1 месяца | организация с ≥1 событием за неделю |
| События / организация / месяц    | ≥ 4                | count(events) where status=finished |
| Бронирования / событие           | ≥ 6                | avg количество confirmed bookings   |
| % операций через Mini App        | ≥ 80%              | events vs web для admin-операций    |
| Время от первой записи до оплаты | ≤ 1 день в среднем | average gap                         |

### Метрики качества

| Метрика                | Цель                               |
| ---------------------- | ---------------------------------- |
| Критические баги       | 0 в production                     |
| Жалобы на UX           | ≤ 5 / месяц на одного организатора |
| Время ответа на жалобу | ≤ 24 часа                          |
| Uptime                 | ≥ 99%                              |

### Метрики монетизации

| Метрика                                | Цель                                       |
| -------------------------------------- | ------------------------------------------ |
| Demo credits использовано              | ≥ 50% организаций исчерпали бесплатные 5   |
| Готовность платить (по интервью)       | ≥ 1 организатор готов купить пакет credits |
| Реальная покупка credits (если успели) | ≥ 1 купил                                  |

## Гейт-критерии для Phase 11+

После минимум **2 месяцев** Private Beta принимаем решение:

### Сценарий A: Гейт пройден — продолжаем

Все критерии:

- ✓ ≥ 2 активных организаторов через месяц
- ✓ ≥ 50 событий создано
- ✓ ≥ 200 бронирований
- ✓ ≥ 1 организатор сказал «я бы платил» в интервью
- ✓ ≥ 80% операций через Mini App
- ✓ ≤ 5 критических жалоб

→ **Запускаем Phase 11** (Contributions). Дальше Phase 12-15.

### Сценарий B: Гейт частично пройден — итерация

Несколько критериев не выполнены, но базовая ценность подтверждена.

→ Возвращаемся в Phase 5-8 для устранения. Не идём в Phase 11 до выполнения всех критериев.

### Сценарий C: Гейт не пройден — pivot

Организаторы не возвращаются, Mini App не используют, ручные процессы (Excel + чат) для них удобнее.

→ Стоп. Анализ причин. Возможный pivot:

- Может быть, фокус не на боте, а на простой админ-странице?
- Может быть, проблема в нише (волейбол слишком мал)?
- Может быть, нужно идти в другой сегмент (детские школы, корпоративные клубы)?

## План коммуникации

### Канал

- **Telegram-чат «Volley Time Beta»** — закрытый, только beta-организаторы + команда.
- Личные сообщения для срочных багов.
- Регулярная (раз в неделю) рассылка апдейтов: что починили, что добавили, что планируем.

### Расписание событий

- **Понедельник:** еженедельный апдейт от команды.
- **Среда:** mid-week check-in — спросить каждого, как дела.
- **Пятница:** review накопленных фидбеков.

### Канал feedback

- Telegram-бот `/feedback` команда (опционально).
- Простой Google Form для длинных отзывов.
- Личные звонки 1 раз / месяц.

## Поддержка во время Private Beta

### Что обещаем

- **24-часовой SLA** на ответ.
- **48-часовой SLA** на исправление критических багов.
- **Полная компенсация** при потере данных (откатим из бэкапа).
- **Бесплатное использование** на всё время beta.

### Что не обещаем

- Кастомные доработки под одного beta-участника.
- Гарантии feature-roadmap (priorities могут меняться).
- 100% uptime (но стараемся).

## Risk management

### Риск 1: Никто не приглашается

**Mitigation:**

- Заранее (Phase 7-8) подготовить 5-7 потенциальных кандидатов.
- Параллельные приглашения, не последовательные.
- Личные встречи / звонки, не сообщения в чате.

### Риск 2: Beta-участники не возвращаются

**Mitigation:**

- Постоянный контакт первые 2 недели (ежедневно).
- Очень короткий onboarding (≤ 30 мин).
- Прозрачные метрики «что работает / что нет».

### Риск 3: Серьёзные баги в проде

**Mitigation:**

- Smoke-тесты перед каждым deploy.
- Ежедневный backup БД.
- Telegram-канал с alerts (Sentry).
- Hotfix-процесс: критический баг → fix в течение 48 часов.

### Риск 4: Перегрузка одного человека

**Mitigation:**

- Поддерживаем не более 5 организаций.
- Чёткие границы рабочего времени (не реагируем на сообщения в 2 ночи).
- Если перегрузка — паузим новые beta-участники, фокусируемся на текущих.

### Риск 5: Юридические вопросы

**Mitigation:**

- Beta — без денег. Никаких реальных платежей через платформу до Phase 12-13.
- Простая оферта для beta-участников: «закрытое тестирование, использование на свой риск, данные могут быть удалены».

## После Private Beta

### Если гейт пройден

1. **Soft launch:** открываем регистрацию для широкого круга, но без рекламы.
2. **Phase 11+** активно разрабатывается.
3. **Первые платные клиенты** — конвертируем beta-участников.
4. **Расширение beta:** ещё 5-10 организаторов второй волной.

### Если гейт не пройден

1. Анализ. Не спешим закрывать проект.
2. Возможный pivot (см. сценарий C выше).
3. Если pivot невозможен — закрываем красиво, благодарим beta-участников, экспортируем им данные.
