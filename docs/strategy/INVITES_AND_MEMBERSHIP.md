# 🔗 Invites & Membership

> **Last updated:** 2026-05-25
> Как пользователи попадают в организацию, как становятся участниками событий, какие роли получают.

---

## Главный принцип

**Invite-first, не self-registration.**

Игрок не может «найти и присоединиться к группе» через поиск. Только через приглашение организатора. Это:

- Защищает от спама и случайных людей.
- Создаёт ощущение «закрытого клуба».
- Упрощает доверие (организатор приглашает только тех, кого знает).

---

## Сущности

См. полные определения в [../DOMAIN.md](../DOMAIN.md).

- `User` — глобальный аккаунт (email и/или Telegram).
- `Organization` — клуб / команда / группа.
- `OrganizationMember` — связь User ↔ Organization с ролью и статусом.
- `InviteLink` — пригласительная ссылка с типом и параметрами.

---

## Типы InviteLink

| Тип                   | Что делает                               | Где используется                                     |
| --------------------- | ---------------------------------------- | ---------------------------------------------------- |
| `organization_join`   | Вступление в организацию                 | Owner приглашает игроков в клуб                      |
| `event_join`          | Запись на конкретное событие             | Owner приглашает на тренировку (включая «не-членов») |
| `subscription_invite` | Получение абонемента после подтверждения | Phase 11+, для акций / подарков                      |
| `staff_invite`        | Приглашение помощника / админа           | Owner приглашает второго организатора                |

**MVP (Phase 4-5):** только `organization_join` и `event_join`.

## Жизненный цикл invite

```
СОЗДАНИЕ
   │
   │ Owner / Organizer создаёт invite через UI
   │ → token генерируется (nanoid 10 символов)
   │ → создаётся InviteLink с параметрами
   │
   ▼
ИСПОЛЬЗОВАНИЕ
   │
   │ Получатель открывает ссылку
   │ → t.me/volleytime_bot?start=org_<token>
   │ → bot встречает с экраном подтверждения
   │ → или Mini App открывается с welcome flow
   │
   ▼
ПРИНЯТИЕ / ОТКЛОНЕНИЕ
   │
   ├─ Принял:
   │   - User создаётся или находится по telegram_user_id
   │   - OrganizationMember создаётся со статусом (active или pending)
   │   - uses_count += 1
   │   - Уведомление организатору
   │
   └─ Отклонил:
       - InviteLink остаётся в системе
       - В аналитике учитывается «отклонено»
   │
   ▼
ИСТЕЧЕНИЕ / REVOKE
   │
   ├─ expires_at пройден → is_expired
   ├─ uses_count >= max_uses → is_full
   └─ Owner отозвал → is_revoked
```

## Сценарии

### Сценарий 1: Owner приглашает игрока в клуб

```
1. Owner открывает Mini App → «Моя организация» → «Игроки» → «Пригласить»
2. Выбирает:
   - Type: organization_join
   - Role to assign: player
   - Default status: active (моментально активный) или pending (требуется подтверждение)
   - Max uses: ∞ или конкретное число
   - Expires at: через 7 дней
3. Bot генерирует ссылку: t.me/volleytime_bot?start=org_aBc123XyZ9
4. Owner копирует ссылку и отправляет игроку в личку Telegram
```

**Что видит игрок при открытии:**

```
🏐 Вас приглашают в:
Volley Minsk Evening

Организатор: Иван Петров
Город: Минск
Sport: Волейбол

15 участников · 3 события в неделю

[Присоединиться]
[Не интересно]
```

После «Присоединиться»:

- User создаётся (если ещё не было — по telegram_user_id)
- OrganizationMember создаётся (role=player, status=active или pending)
- Bot уведомляет owner: «🎉 Алексей присоединился к Volley Minsk Evening»
- Mini App открывается с меню организации

---

### Сценарий 2: Owner приглашает на конкретное событие

```
1. Owner создаёт событие
2. В карточке события — кнопка «Пригласить»
3. Тип: event_join (автоматически с event_id)
4. Default member status: guest (только для этого события)
5. Owner share-ит ссылку: t.me/volleytime_bot?start=event_xyz999
```

**Что видит игрок:**

```
🏐 Волейбол · открытая игра
📍 Минск, спортшкола №1
🕘 30 мая, пятница, 19:00–21:00
💰 15 BYN

👥 Свободно: 4 из 14 (main)
Записаны: 8 main + 2 rotation

[Записаться]
[Подробности]
```

После «Записаться»:

- Если пользователь ещё не в организации:
  - User создаётся (если нужно)
  - OrganizationMember создаётся со статусом `guest`
- Booking создаётся (логика slot distribution из Phase 5)
- Player видит карточку события с инструкциями по оплате

### Сценарий 3: Приглашение помощника (Phase 11+)

```
Owner → «Моя организация» → «Сотрудники» → «Пригласить»
Тип: staff_invite
Role: organizer
```

Получатель видит:

```

Volley Minsk Evening

В роли «organizer» вы сможете:
- Создавать события

- Видеть кассу
```

### Сценарий 4: Один игрок в нескольких организациях

Сценарий нормальный и поддерживается:

- Игрок состоит в «Volley Minsk Evening» (player).
- Также состоит в «Office League» (player, status=guest для конкретных матчей).
- Также организует свою группу «Friday Pickup» (owner).

Mini App при старте показывает переключатель организаций (если их больше одной):

```
Ваши организации:

🏐 Volley Minsk Evening (player)
🏐 Office League (player)
👑 Friday Pickup (owner)

Платформа:
⚙️ Настройки аккаунта
```

## Статусы OrganizationMember

| Статус     | Описание                                | Что может делать                                    |
| ---------- | --------------------------------------- | --------------------------------------------------- |
| `pending`  | Заявка ждёт подтверждения owner         | Видеть карточку организации                         |
| `active`   | Полноценный участник                    | Записываться, использовать абонементы               |
| `guest`    | Участник одного события (не постоянный) | Записаться только на тот event, через который вошёл |
| `blocked`  | Заблокирован owner                      | Только видит «вы заблокированы»                     |
| `left`     | Добровольно вышел                       | Не видит организацию, история сохранена             |
| `rejected` | Заявка отклонена                        | Может подать снова, если invite разрешает           |

### Переходы статусов

```
NEW USER
   │
   ▼
(invite-based)
   │
   ├─► pending ──(owner accepts)──► active
   │       │
   │       └──(owner rejects)──► rejected
   │
   └─► active (если default_member_status=active)
       │
       ├──(owner blocks)──► blocked ──(unblocks)──► active
       │
       ├──(user leaves)──► left
       │
       └──(promoted from guest)──► active

GUEST (для event_join)
   │
   ├─► guest ──(owner promotes)──► active
   │
   └─► guest ──(event ends)──► остаётся guest, но без активных bookings
```

## Роли OrganizationMember

| Роль        | Описание                         | Кто назначает      |
| ----------- | -------------------------------- | ------------------ |
| `owner`     | Создатель организации            | Авто при создании  |

## Регистрация и связывание identity

### Сценарий: новый пользователь через invite (Telegram)

```
1. Кликает на t.me/volleytime_bot?start=org_<token>
2. Bot создаёт User:
   - telegram_user_id (из Telegram)
   - telegram_username
   - first_name (из Telegram profile)
   - email = null
3. Открывает Mini App с auth через initData
4. better-auth создаёт session
5. OrganizationMember создаётся
```

### Сценарий: уже зарегистрированный пользователь

```
1. User уже есть (по telegram_user_id)
2. Открывает invite link
3. Mini App открывается, session уже есть
4. Если уже в этой организации:
   - «Вы уже состоите в этой организации»
5. Если нет:
   - OrganizationMember создаётся
   - Уведомление owner
```

### Сценарий: добавление email к Telegram-аккаунту

```
1. Mini App → «Настройки» → «Привязать email»
2. Ввод email
3. Запрос better-auth: send-code
4. Получение кода на email
5. Ввод кода
6. Email добавляется к User (тот же user_id)
```

### Сценарий: связывание двух accounts (Phase 11+)

Если у пользователя случайно создалось два User (один через email, другой через Telegram) — поддержка может объединить через специальный workflow (Phase 11+). На MVP — не делаем.

## Безопасность invites

### Защита токена

- Token — 10 символов из nanoid (URL-safe).
- Энтропия: ~60 bit. Не угадывается перебором.
- Hash в БД? Нет, токены хранятся plaintext (они и так одноразового использования или короткоживущие).

### Rate limiting

- На auth endpoints: 1 код / 60 сек, 5 попыток на код (наследие Level Volley).
- На создание invite: 10 invites / час на пользователя.
- На принятие invite: 5 принятий / час на IP.

### Что делать при подозрении

- Owner видит historiю invites и кто их использовал.
- Owner может revoke invite вручную (`is_revoked = true`).
- Owner может заблокировать конкретного игрока (status=blocked).

## Edge cases

### «Я случайно отклонил invite, как принять снова?»

- InviteLink не сгорел при отклонении (только при принятии или истечении).
- Открой ссылку ещё раз → «Присоединиться».

### «Я хочу выйти из организации»

- Mini App → «Моя организация» → «Выйти».
- Status → `left`.
- История сохраняется (bookings, payments).
- Может присоединиться снова, если получит новый invite.

### «Организация была удалена, что с моими данными?»

- В первые 30 дней после удаления — soft-delete, можно восстановить.
- После 30 дней — анонимизация PII, агрегаты сохраняются для статистики платформы.

### «Я меняю Telegram аккаунт, как перенести?»

- Сложный сценарий. Требует поддержки.
- Phase 11+: workflow «связать новый telegram_user_id с существующим email».
