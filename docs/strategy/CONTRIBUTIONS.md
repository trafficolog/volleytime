# 💵 Contributions (сборы)

> **Last updated:** 2026-05-25
> Модуль «Сборы» — как игроки собирают деньги на общие цели через платформу. Phase 11+.

---

## Что это и зачем

Сбор — это **прозрачный учёт** общих расходов клуба. Не оплата конкретной услуги, а вклад в общую цель.

**Типичные сценарии:**

- Собираем 250 BYN на новый мяч
- Собираем 400 BYN на турнирный взнос
- Собираем 150 BYN на форму для команды
- Собираем 800 BYN на аренду зала на месяц
- Собираем 50 BYN на судью турнира
- Общий «клубный фонд»

**Главная ценность платформы — прозрачность**, а не приём денег. Игроки видят:

- Сколько собрано
- Сколько осталось
- Кто внёс
- Кто обещал, но не внёс
- На что потрачено (через связь с Ledger)

---

## Почему это критичная фича

В реальных группах **проблема денежного учёта** — главная причина конфликтов:

- «Ты не сдал на мяч».
- «А я уже сдал, ты забыл записать».
- «Куда делись деньги с прошлого сбора?»
- «Почему мяч новый, а аренда не оплачена?»

Прозрачный учёт убирает эти конфликты.

**Это не про принятие денег платформой.** Платформа не становится посредником. Игроки платят организатору **тем же способом, что и сейчас** (наличными, переводом). Платформа только **записывает факт**.

## Модель данных

См. полные определения в [../DOMAIN.md](../DOMAIN.md#contributions-phase-11).

- `ContributionCampaign` — кампания сбора (цель, описание, видимость).
- `Contribution` — конкретный вклад одного игрока в кампанию.

```typescript
ContributionCampaign {
  id, organization_id, title, description,
  target_amount, currency,
  status: draft | active | completed | cancelled,
  visibility: members_only | public_link,
  public_token (если visibility=public_link)
}

Contribution {
  id, campaign_id, organization_id,
  user_id | offline_name,
  amount,
  method: cash | transfer | online | other,
  status: pledged | received_cash | received_transfer | received_online | cancelled | refunded,
  confirmed_by_user_id,
  comment
}
```

## Жизненный цикл кампании

```
DRAFT
  │ owner создаёт черновик, ещё не виден игрокам
  │
  ▼
ACTIVE (опубликована)
  │ игроки видят кампанию, могут обещать вклад
  │
  ├─ Игрок жмёт «Я внесу 20 BYN»
  │  → Contribution создаётся в status=pledged
  │
  ├─ Игрок передаёт деньги организатору
  │  Owner отмечает «получил наличными»
  │  → Contribution.status=received_cash
  │  → progress_bar обновляется
  │
  └─ Можно отменить pledge (status=cancelled)
  │
  ▼
COMPLETED (цель достигнута или owner вручную завершил)
  │ кампания закрыта, новые pledges невозможны
  │
  ▼
архив — остаётся в истории
```

## Состояния Contribution

| Статус              | Что значит                           | Считается в собранной сумме?          |
| ------------------- | ------------------------------------ | ------------------------------------- |
| `pledged`           | Игрок обещал внести                  | Нет (только promised_amount)          |
| `received_cash`     | Owner подтвердил получение наличными | Да                                    |
| `received_transfer` | Подтверждение перевода               | Да                                    |
| `received_online`   | Online-оплата прошла (Phase 12+)     | Да                                    |
| `cancelled`         | Игрок отменил pledge или owner снял  | Нет                                   |
| `refunded`          | Возвращено (если кампания отменена)  | Нет (отрицательное движение в ledger) |

### Создание кампании (FSM)

```
1. Название
   > Например: "Новый мяч"

2. Описание (опционально)
   > Например: "Старый порвался, нужен Mikasa V200W"

3. Целевая сумма
   > Например: 250 BYN

4. Видимость
   ○ Только для членов организации
   ● Публичная (доступна по ссылке без авторизации)

5. Подтверждение
   "Создать кампанию «Новый мяч» с целью 250 BYN?"
   [Да, создать] [Отмена]
```

## Связь с Ledger

При подтверждении вклада создаётся **LedgerEntry**:

```
Contribution.status: pledged → received_cash
  ↓
LedgerEntry создаётся:
  type: income
  category: contribution
  amount: 20.00
  description: "Иван — Новый мяч"
  related_contribution_id: <Contribution.id>
```

После завершения кампании и закупки — owner создаёт expense:

```
LedgerEntry:
  type: expense
  category: equipment
  amount: 248.50
  description: "Mikasa V200W, мяч"
  evidence_file_id: <фото чека>
```

Это позволяет видеть в кассе **движение по кампании** (income и matching expense) — полная прозрачность.

## Что НЕ делаем в Phase 11

### Не принимаем платежи онлайн

Только через статусы `pledged → received_cash/transfer`. Owner отмечает руками.

Phase 12-13+ — после интеграции bePaid игроки смогут оплачивать прямо в Mini App, статус сразу `received_online`.

### Не делаем сложные правила

- Без deadline'ов на pledges (просто можно отменить).
- Без обязательных взносов («сбор по 20 BYN с каждого»). Только добровольно.
- Без иерархии кампаний (sub-кампании в кампании).

### Не делаем социальный layer

- Без лайков/комментариев под кампаниями.
- Без шеринга в соцсети (только public_link в Telegram).
- Без gamification («top contributors»).

---

## Что добавляем в Phase 12+ (online payments для сборов)

После интеграции bePaid:

- Кнопка «Оплатить картой / ЕРИП» в карточке вклада.
- Игрок жмёт → bePaid checkout → возврат в Mini App.
- Contribution.status сразу `received_online`.
- Никакого ручного подтверждения owner.

Это особенно ценно для:

- Турнирных взносов (большие суммы, удобнее картой).
- Аренды зала (регулярные платежи).
- Сборов с участников вне постоянной группы (гости).

- Аналитика по категориям сборов (на что чаще собираем).

## Public link сценарий

Если кампания `visibility: public_link`:

- Генерируется `public_token` (UUID).
- URL: `https://volleytime.by/c/<public_token>`
- Доступ без авторизации.
- Видно: название, описание, прогресс, список участников (по именам без контактов).
- Можно нажать «Внести» (откроет deeplink в bot или Mini App).

**Use case:**

- Делиться в соцсетях / Telegram-чатах вне организации.
- Прозрачность для бухгалтерии (тренер показывает родителям/спонсорам).
- Привлечение новых игроков (через визит на public page).

## Edge cases

### Сбор перевыполнен (170 → 280 при цели 250)

- Прогресс показывает «280 / 250 (112%)».
- Owner решает: оставить излишек в общий фонд (новая кампания) или вернуть.
- При завершении кампании в комментарии указывает решение.

### Игрок обещал, но не внёс

- Owner видит `pledged` дольше N дней.
- Может отметить как `cancelled`.
- Может напомнить через bot (Phase 15 — auto-reminders).

### Игрок внёс больше, чем обещал

- Owner подтверждает фактическую сумму.
- Contribution.status=received_cash, amount=фактическая.

### Кампания отменяется владельцем

- Все `received_*` записи требуют возврата (refund).
- Owner отмечает каждую `refunded`.
- В ledger создаются compensating expense.

## Прозрачность для участников

В карточке кампании каждый член организации видит:

- Кто внёс, сколько, когда, каким способом
- Свои вклады отдельно
- Свой остаток обещанного (`pledged`)

Это критично: **доверие через видимость**.

**Кто НЕ видит:**

- Игрок, не являющийся членом организации (для `members_only`).
- На `public_link` — имена видны, но не сумма каждого (агрегаты только).
