# 💼 Organizer Monetization

> **Last updated:** 2026-05-25
> Как организатор зарабатывает на платформе Volley Time и как сама платформа зарабатывает на организаторе.

---

## Два уровня монетизации

```
┌─────────────────────────────────────────────────────────────────┐
│ Уровень 1: организатор → платформа (Volley Time → деньги)       │
│                                                                 │
│ - Event credits (покупка права создавать события)               │
│ - Месячные подписки (Regular / Club / Tournament tier)          │
│ - Add-ons (Online Payments, CRM Pro)                            │
└─────────────────────────────────────────────────────────────────┘

┌─────────────────────────────────────────────────────────────────┐
│ Уровень 2: игрок → организатор (Volley Time только учитывает)   │
│                                                                 │
│ - Наличные на тренировке                                        │
│ - Перевод на карту организатора                                 │
│ - Эквайринг организатора (Phase 13+)                            │
│ - bePaid / ЮKassa организатора (Phase 13+)                      │
└─────────────────────────────────────────────────────────────────┘
```

**Ключевое:** уровень 2 — это **не доход платформы**. Платформа на старте **не принимает деньги** за организаторов. Это сознательное решение для упрощения юридической модели.

---

## Принципы

### Принцип 1: Прозрачная стоимость для организатора

Организатор всегда знает, сколько он заплатит платформе и за что. Никаких процентов с оборота на старте (Phase 11+ — возможно, как опция).

### Принцип 2: Платформа не посредник в финансах между игроком и организатором

Игрок платит организатору напрямую. Это критично для:

- Юридической простоты (не нужны marketplace-лицензии)
- Налоговой простоты (платформа не агент по НДФЛ/НДС/УСН)
- Доверия игроков (нет «зависших» денег у посредника)

### Принцип 3: Бесплатный старт

Каждая новая организация получает 5 demo event credits — пять бесплатных событий, чтобы попробовать платформу. Без credit card на регистрации.

### Принцип 4: Никаких lock-in уловок

- Данные организации экспортируются в CSV в любой момент.
- Удаление организации — 1 клик (с 30-дневным soft-delete для отката).
- Никаких автопродлений без явного согласия.

## Уровень 1: монетизация платформы

### Модель A: Event Credits (Phase 7+)

**Кому подходит:** разовые / нерегулярные организаторы.

**Как работает:**

- Платит за каждое созданное событие отдельно.
- Покупает пакет credits заранее (1 / 10 / 30 / 100).
- 1 credit = 1 событие.

**Цены (предварительные):**

| Пакет       | Цена    | Скидка |
| ----------- | ------- | ------ |
| 1 credit    | 5 BYN   | —      |
| 10 credits  | 40 BYN  | 20%    |
| 30 credits  | 105 BYN | 30%    |
| 100 credits | 300 BYN | 40%    |

**Особенности:**

- Demo квота 5 credits при регистрации.
- Отмена события до открытия записи — credit возвращается.
- Credits не сгорают со временем.
- Credits scoped к organization (нельзя перенести между организациями).

**Когда подходит:**

- Организатор проводит 1-4 события в месяц.
- 1-4 события × 5 BYN = ~20 BYN/мес.

### Модель B: Месячная подписка (Phase 14+)

**Кому подходит:** регулярные организаторы.

**Tiers:**

| Tier       | Цена        | Включено                                                 |
| ---------- | ----------- | -------------------------------------------------------- |
| Regular    | ~15 BYN/мес | core + reports + reminders                               |
| Club       | ~40 BYN/мес | Regular + contributions + public page + multi-assistants |
| Tournament | ~80 BYN/мес | tournaments + live scoreboard + всё из Club              |

**Когда подходит:**

- Regular: 4+ событий в месяц.
- Club: клуб с регулярной активностью, инвентарными расходами.
- Tournament: организатор турниров.

### Модель C: Add-ons (Phase 13+)

Дополнения к любому tier:

| Add-on          | Цена        | Что даёт                                   |
| --------------- | ----------- | ------------------------------------------ |
| Online Payments | +20 BYN/мес | bePaid интеграция, авто-оплата картой/ЕРИП |
| CRM Pro         | +30 BYN/мес | заметки, теги, сегменты, рассылки          |
| Public Page     | +10 BYN/мес | публичная страница организации             |

### Модель D: Custom (Phase 14+)

Для федераций, сетей залов, корпоративных клиентов.

- Индивидуальное ценообразование.
- White-label (опционально).
- SLA-договор.
- Выделенный support.

## Уровень 2: как игроки платят организаторам

Платформа поддерживает **несколько способов**. Организатор выбирает, какие активны.

### Способ 1: Cash (Phase 6+) — основной для MVP

**Как работает:**

1. Игрок выбирает «Оплатить наличными» при записи.
2. Booking → `pending_payment`, Payment → `pending`.
3. Игрок оплачивает на тренировке.
4. Организатор подтверждает оплату в админ-меню.
5. Payment → `succeeded`, Booking → `confirmed`, LedgerEntry → income.

**Преимущества:**

- Не требует онлайн-эквайринга.
- Простая юридическая модель.
- Понятно всем.

**Недостатки:**

- Требует ручного подтверждения админом.
- Касса может расходиться с реальностью.

### Способ 2: Transfer (Phase 6+)

Перевод на карту/счёт организатора (вне платформы).

**Как работает:**

- То же что cash, но игрок указывает «Оплачу переводом».
- Организатор после получения перевода подтверждает в админ-меню.

### Способ 3: Subscription (Phase 5+)

Оплата с заранее купленного абонемента.

**Как работает:**

- Игрок при записи выбирает «С абонемента».
- Атомарное списание сессии.
- Booking сразу `confirmed`, без pending.

### Способ 4: Online Payments — own org (Phase 12)

Только для **своей** организации (Volley Time) — proof of concept.

bePaid интеграция:

- Игрок выбирает «Картой» / «ЕРИП».
- Deeplink на bePaid checkout.
- Webhook подтверждает.
- Booking → `confirmed` автоматически.

### Способ 5: Online Payments — organizer add-on (Phase 13)

Любой организатор может подключить **свой** bePaid аккаунт через add-on.

**Как работает:**

- Организатор покупает add-on (+20 BYN/мес).
- Подключает свои credentials через UI.
- Платежи идут на счёт организатора, минуя платформу.

**Важно:** платформа **никогда не видит** содержимое транзакций (PAN, имя, и т.п.). Только `bepaid_uid` и `status`.

### Способ 6 (будущее, Phase 13+): российские провайдеры

Для российских организаторов — ЮKassa, Сбер, Тинькофф. Интегрируем по запросу.

### Способ 7 (будущее, Phase 13+): Marketplace-сценарий (опционально)

**Только если будет явный запрос.**

- Платформа становится агентом организатора по приёму платежей.
- Деньги поступают на счёт платформы, потом перечисляются организатору.
- Платформа берёт % с оборота (например, 2%) или фиксированную плату.
- Требует marketplace-лицензии и сложной юридической модели.
- **Анти-цель на ближайшие 12+ месяцев.**

## Прозрачность для игрока

Что игрок видит **всегда**:

- Кому он платит (имя организатора)
- Каким способом
- Сколько именно
- За что (конкретное событие или абонемент)
- Когда (дата платежа)
- Статус (pending / paid / cancelled)

Что игрок видит при **онлайн-оплате**:

- bePaid checkout page (стандартный UI bePaid)
- В чеке/квитанции — имя организатора, не платформы

Это критично для **доверия** игроков.

---

## Что НЕ строим

- ❌ Reverse-auction («организатор предлагает цену, игроки голосуют»)
- ❌ Subscriptions для игроков (только для организаторов)
- ❌ Buy-now-pay-later
- ❌ Кредитование организаторов
- ❌ Криптовалюты
- ❌ NFT и геймификация
- ❌ Тренерские контракты в платформе

## Метрики дохода (north star)

### Phase 7-10

- Total revenue from event credits (BYN / месяц)
- Average revenue per organization (ARPO)

### Phase 14+

- MRR (Monthly Recurring Revenue)
- ARPU (Average Revenue Per User — но в нашем случае Per Organization)
- LTV (Lifetime Value)
- CAC (Customer Acquisition Cost) — будет известен только после рекламных кампаний (если они появятся)

### Что НЕ оптимизируем (анти-метрики)

- ❌ Number of registrations (легко завысить, не важно)
- ❌ Page views, sessions
- ❌ Cohort retention для случайных регистраций (важна только для активных organizations)
