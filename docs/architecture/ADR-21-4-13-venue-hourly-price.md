# ADR 21.4.13 · Цена за час зала (DEF-23)

- **Статус:** принято исполнителем карточки [21.4.13](../tasks/21-4-13-venue-hourly-price.md), 2026-11-16; подлежит независимому ревью (`review_gate: opus+tests`).
- **Решения владельца:** «Мастер группы, амплуа, залы» (2026-11-05) — цена за час в «Настройки → Залы»; 2026-11-16 — задача в `v0.3.2` первой ([журнал](../operations/decisions/2026-10-12-reference-v3-decisions.md)).
- **Область:** хранение цены за час зала, миграция `0040`, контракт API залов, ввод и показ «N BYN/ч».
- **Не область:** расчёт цены события, касса, отчёты, бот (карточка: «не трогать расчёт цены события»).

## Контекст

Макет W-11 показывает у зала «15 Br/ч», в БД `venues` такого поля нет ([отчёт 21.2.13](../operations/qa/2026-11-05-21-2-13-settings-venues-visual.md), DEF-23). На production работает код `98b60193` (v0.3.1); предыдущая цель отката `aa8d8f9a`. Оба читают и пишут `venues` через Drizzle с явным списком колонок.

## Решение

### Хранение

- Новая колонка `venues.hourly_price integer NULL` — цена одного часа аренды в **минимальных единицах** (копейки: `1550` = 15,50) по принципу 2 [ADR v3](./ADR-v3-domain.md) («Принципы»). `numeric` и дробные значения не используются.
- `NULL` — цена не указана (все существующие залы и пустое поле формы). `0` — допустимое значение «бесплатно» (свой зал), отличается от «не указана».
- CHECK `venues_hourly_price_range`: `hourly_price IS NULL OR hourly_price BETWEEN 0 AND 10000000` (верхняя граница как у сумм кассы `parseDesktopLedgerAmount`, 100 000,00 в мажорных единицах).
- **Валюта** — валюта группы `organizations.default_currency`, отдельной колонки валюты у зала нет (карточка, п. 1). Смена валюты группы не пересчитывает цену: число остаётся, подпись меняет валюту. Это допустимо, пока цена зала только справочная (ни во что не пересчитывается); если цена зала начнёт участвовать в деньгах, нужна колонка валюты — отдельный ADR.

### Миграция (expand-only, forward-compatible)

`0040_venue_hourly_price.sql`: `ALTER TABLE venues ADD COLUMN hourly_price integer` + `ADD CONSTRAINT … CHECK`. Без `DEFAULT` и `NOT NULL`, без переписывания строк и бэкфилла: в PostgreSQL 16 это изменение только каталога, блокировка `ACCESS EXCLUSIVE` кратковременна, CHECK проверяет существующие строки (все `NULL`) мгновенно на таблице такого размера.

Совместимость со старым кодом (`aa8d8f9a`, `98b60193`) на новой схеме:

- чтение — Drizzle перечисляет колонки, новая не выбирается;
- вставка — колонку не передают, получается `NULL` (нет `NOT NULL` и CHECK пропускает `NULL`);
- правка — `UPDATE … SET` перечисленных полей не трогает `hourly_price`, сохранённая цена переживает правку старым кодом.

Поэтому миграция применяется до переключения образа, а откат приложения на `98b60193`/`aa8d8f9a` после неё разрешён без флага и без расширения rollback guard (как 0034).

### Откат схемы

`packages/db/rollback/0040_venue_hourly_price.sql` по образцу 0034: отказывает (`RAISE EXCEPTION`), пока есть хотя бы один зал с `hourly_price IS NOT NULL` — цену вводит организатор вручную, восстановить её нельзя. Иначе снимает CHECK и колонку. Принудительный откат с данными — только решение владельца после `pg_dump -t venues` (или выгрузки `SELECT id, hourly_price FROM venues WHERE hourly_price IS NOT NULL`) и `UPDATE venues SET hourly_price = NULL`. Обычный путь при проблеме — откат приложения без отката схемы (см. выше) или roll-forward.

### Контракт API

- `POST /api/organizations/{orgId}/venues`: `hourlyPrice?: integer 0…10 000 000 | null` (минорные единицы). Отсутствует или `null` — не указана.
- `PATCH …/venues/{venueId}`: `hourlyPrice?: integer | null`; `null` сбрасывает, отсутствие поля не меняет.
- `GET …/venues`: строка зала содержит `hourlyPrice: number | null`.
- Дробное, отрицательное, больше максимума, строка — 422 (Zod). Права не меняются: создание и правка — manager, список — member; зал чужой группы — 404 (IDOR, 21.2.13). Аудит `venue.updated` пишет `hourlyPrice` в `newValue`, как другие поля.

### Расчёт и показ

- Ввод в форме — мажорные единицы строкой, `,` или `.`, не больше двух знаков после разделителя: `^\d+([.,]\d{1,2})?$`. Перевод — `toMinor` (`Math.round(major * 100)`), что устраняет ошибку двоичной дроби (`0.29 * 100 = 28.999…` → `29`). Три и более знака, минус, буквы — ошибка формы без запроса; пустое поле — `null`.
- Показ — `formatHourlyPrice(minor, currency)`: целые без копеек («15 BYN/ч»), с копейками — два знака через запятую ru-RU («15,50 BYN/ч»), `0` — «0 BYN/ч» (не «Бесплатно», чтобы не путать с бесплатным событием), `null` — подписи нет. Разделитель тысяч ru-RU.
- Стоимость аренды за длительность (дробные часы) **не вычисляется** в этой карточке: по «Не делать» цена события не трогается. Когда понадобится (подсказка суммы сбора), правило фиксируется здесь заранее: `round_half_up(hourly_price * minutes / 60)` в копейках целочисленной арифметикой, отдельной картой с тестами.

### Влияние

- **Существующие события:** без изменений. Цена события (`events.price`, `target_amount`) зал не читает; у события нет снимка цены зала.
- **Касса и отчёты:** без изменений. `ledger_entries`, баланс событий, экспорт и отчёты не читают `hourly_price`; расход «Аренда» по-прежнему вводится вручную.
- **Бот и игроки:** не показывают цену зала (не область).

## Последствия

- `+` Одна nullable-колонка, откат приложения свободен, откат схемы безопасен при отсутствии данных.
- `−` Цена привязана к валюте группы без снимка; принято до первого денежного использования.
