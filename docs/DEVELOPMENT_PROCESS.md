# Процесс разработки

> Как ведётся реализация Volley Time. Обязателен для всех (человек + AI-агенты).

## Методология: SDD + TDD

**SDD (Spec-Driven Development).** Спецификация — карточка задачи `docs/tasks/N-M-K-*.md`.
Она источник истины: «Что должно быть сделано» + «Критерии приёмки» + «Не делать».
Код не пишется без карточки. Отклонения от карточки фиксируются в карточке до кода.

**TDD (Test-Driven Development).** Цикл red → green → refactor:

1. **Red** — пишем тест по «Критериям приёмки», он падает.
2. **Green** — минимальный код, чтобы тест прошёл.
3. **Refactor** — чистим, тесты остаются зелёными.

Для инфраструктурных задач (setup монорепо, Docker) TDD заменяется **проверяемыми критериями** (команда отрабатывает, файл существует, сборка проходит) — фиксируются как smoke-проверки.

## Принципы: DRY · KISS · YAGNI

- **DRY** — не дублируй. Общее → в `packages/shared` (или профильный пакет). Но не абстрагируй раньше 3-го повторения (см. YAGNI).
- **KISS** — простейшее решение, работающее по критериям. Без «на будущее».
- **YAGNI** — не строй того, чего не требует текущая карточка. Карточки уже разделены по фазам — не тащи Phase 7 в Phase 3.

Конфликт DRY↔YAGNI решается в пользу YAGNI: дублирование дешевле неверной абстракции.

## Git-flow: ветка на задачу

Каждая задача = отдельная ветка от `main`:

```
feat/<phase>.<epic>.<task>-<slug>       напр. feat/3.1.1-pnpm-workspaces
```

Типы веток: `feat/` (функциональность), `chore/` (инфра/конфиг), `fix/`, `test/`, `docs/`.

**Коммиты** (Conventional Commits) со ссылкой на задачу и релиз:

```
<type>(<scope>): <summary>

Task: <id>          # напр. 3.1.1
Release: <version>  # напр. v0.1.0 (R0/MVP) — из docs/RELEASES.md
```

Пример: `chore(repo): init pnpm workspaces` / `Task: 3.1.1` / `Release: v0.1.0`.

**PR** закрывает issue задачи (`Closes #<issue>`), merge в `main` после зелёных тестов/критериев.

## Workflow одной задачи

1. Прочитать карточку `docs/tasks/N-M-K-*.md` целиком (все 6 секций).
2. Проверить depends_on закрыты (иначе не начинать).
3. Создать ветку `feat/N.M.K-slug` от `main`.
4. **TDD:** тест по критериям (red) → код (green) → refactor.
5. Прогнать `pnpm test`, `pnpm lint`, `pnpm typecheck` — зелёные.
6. Сверить с «Критериями приёмки» и «Не делать».
7. Коммит(ы) с Task/Release тегами.
8. PR → merge в main → закрыть issue.

## Связь с релиз-планом

- Задача → релиз: [docs/RELEASES.md](./RELEASES.md) (фаза → milestone).
- MVP (`v0.1.0`) = фазы 3,4,5,6,8,9.
- Порядок: 3 → 4 → 5 → 6 → 8 → 9 (внутри — по depends_on).

## Статусы карточек

| `status`      | Значение                                                               |
| ------------- | ---------------------------------------------------------------------- |
| `todo`        | не начато или не реализовано                                           |
| `in_progress` | реализовано частично / есть открытые находки ревью (см. `status_note`) |
| `done`        | все критерии приёмки выполнены, находок нет                            |

`sync_state: synced` — карточка сверена с кодом на дату `last_reviewed`. Фикс-задачи по ревью несут `review_ref` (номер находки) и `priority` (P0/P1/P2).

## Definition of Done (задача)

- [ ] Реализовано по «Что должно быть сделано»
- [ ] Все «Критерии приёмки» выполнены
- [ ] Соблюдено «Не делать»
- [ ] Тесты/smoke-проверки зелёные
- [ ] lint + typecheck чисто
- [ ] Коммит с Task/Release, PR смёржен
