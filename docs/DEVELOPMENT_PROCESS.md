# Процесс разработки

> Как ведётся реализация Volley Time. Обязателен для всех (человек + AI-агенты).

## Методология: SDD + TDD

**SDD (Spec-Driven Development).** Спецификация — карточка задачи `docs/tasks/N-M-K-*.md`.
Она источник истины: «Что должно быть сделано» + «Критерии приёмки» + «Не делать».
Код не пишется без карточки. Отклонения от карточки фиксируются в карточке до кода.

**TDD (Test-Driven Development).** Цикл red → green → refactor:

1. **Red** — пишем тест по «Критериям приёмки», он падает.
2. **Green** — минимальный код, чтобы тест прошёл.
3. **Refactor** — чистим, тесты остаются зелёными.

Для инфраструктурных задач (setup монорепо, Docker) TDD заменяется **проверяемыми критериями** (команда отрабатывает, файл существует, сборка проходит) — фиксируются как smoke-проверки.

## Инженерные правила

Перед реализацией или review прочитать [CODING_STANDARDS](../CODING_STANDARDS.md): границы реализации, Git conventions и обязательные проверки. Здесь описана последовательность работы, а не вторая копия стандартов.

## Workflow одной задачи

1. Прочитать карточку `docs/tasks/N-M-K-*.md` целиком (все 6 секций).
2. Проверить depends_on закрыты (иначе не начинать).
3. Создать task branch по CODING_STANDARDS.
4. **TDD:** тест по критериям (red) → код (green) → refactor.
5. Выполнить применимые verification gates из CODING_STANDARDS и сохранить результаты с tested revision.
6. Сверить с «Критериями приёмки» и «Не делать».
7. Оформить коммит и PR по CODING_STANDARDS; проверить acceptance и review/CI перед merge.
8. После merge закрыть связанную issue и синхронизировать статус карточки. Task acceptance не заменяет release/production acceptance.

## Связь с релиз-планом

- До выбора scope прочитать целевой релиз в [RELEASES](./RELEASES.md): состав задач, ограничения и release DoD. Исторический MVP scope не определяет автоматически состав следующего релиза.
- Порядок реализации определяется `depends_on` карточек и утверждённым планом релиза.

## Статусы карточек

| `status`      | Значение                                                               |
| ------------- | ---------------------------------------------------------------------- |
| `todo`        | не начато или не реализовано                                           |
| `in_progress` | реализовано частично / есть открытые находки ревью (см. `status_note`) |
| `done`        | все критерии приёмки выполнены, находок нет                            |

`sync_state: synced` — карточка сверена с кодом на дату `last_reviewed`. Фикс-задачи по ревью несут `review_ref` (номер находки) и `priority` (P0/P1/P2).

## Definition of Done (задача)

- [ ] Реализовано по «Что должно быть сделано»
- [ ] Все «Критерии приёмки» выполнены
- [ ] Соблюдено «Не делать»
- [ ] Применимые verification и Git/review критерии CODING_STANDARDS выполнены, evidence сохранено
- [ ] PR смёржен, карточка синхронизирована
