# Phase 10: Private Beta — ГЕЙТ перед монетизацией

**Цель.** Запустить платформу для 2-5 внешних организаторов (вне команды). Собрать структурированную обратную связь, измерить гейт-метрики, принять решение о монетизации (Phase 7).

**Природа фазы:** смешанная. Полевая работа (onboarding, поддержка, feedback) + лёгкий dev-инструментарий беты (allowlist, feedback-кнопка, super-admin обзор) + операционные артефакты (чеклисты, runbooks).

## Контекст

Трек B пройден — продукт уже обкатан на собственной группе (MVP-критерий Phase 8). Phase 10 — НЕ первая проверка гипотезы, а структурированный закрытый запуск на ВНЕШНИХ организаторах: проверяем переносимость (работает ли не только у автора), готовность платить, ретеншн.

Трек A готов — монетизация разблокирована. Поэтому гейт Phase 10 ведёт прямо в Phase 7 (event credits): успешная бета → технически проверяем готовность платить.

## Предусловия

- ✅ Phase 3-9 завершены (Foundation → Production Deploy), продукт в production 24/7
- ✅ Трек B пройден: MVP обкатан на собственной группе (Phase 8 критерий)
- ✅ Трек A готов: юридическая основа для приёма платежей (для Phase 7 после беты)
- ✅ PRIVATE_BETA_PLAN.md: стратегия onboarding/критериев

## Definition of Done

### Dev-инструментарий беты

1. ✅ Allowlist: новые организации создают только приглашённые (контролируемый рост)
2. ✅ Feedback-кнопка в Mini App → служебный канал (быстрый репорт из контекста)
3. ✅ Super-admin обзор: список бета-организаций + метрики активности (для ведения беты)

### Операционка

4. ✅ Onboarding-чеклист (повторяемый процесс подключения организатора)
5. ✅ Support-runbook (реакция на проблемы, эскалация)
6. ✅ Feedback-трекинг (фиксация, приоритизация обратной связи)
7. ✅ User-facing документация (FAQ организатора + игрока)
8. ✅ Гейт-метрики: способ измерения + decision framework

### Полевая работа (не оценивается в часах)

9. ⏸ Onboarding 2-5 внешних организаторов
10. ⏸ Еженедельные feedback-сессии
11. ⏸ Hotfix критических багов, мини-доработки UX

## Гейт-критерии (для перехода в Phase 7 / 11+)

- ≥ 2 внешних организатора активно используют ≥ 1 месяц
- **≥ 1 организатор провёл ≥ 4 недели подряд (ретеншн — главный сигнал ценности)**
- ≥ 50 событий создано
- ≥ 200 бронирований
- ≥ 1 организатор явно готов платить за event credits
- ≥ 80% операций через Mini App
- ≤ 5 критических жалоб

## Сценарии решений после фазы

- **A (гейт пройден):** → Phase 7 (Event Credits, Трек A готов) — технически проверяем готовность платить → затем Phase 11+
- **B (частично):** возврат в Phase 5-8 для доработок по обратной связи, повтор беты
- **C (не пройден):** анализ почему, возможный pivot позиционирования/функций

## Технические заметки

### Утверждённые решения

1. Phase 10 расписана карточками (dev + ops), не только полевой план
2. Гейт-критерии обновлены: + ретеншн (≥4 недели подряд)
3. Allowlist на создание организации (приглашённые), игроки свободно по org-invite
4. Feedback: Telegram-чат беты + кнопка в Mini App → служебный канал
5. Super-admin обзор бета-организаций (лёгкий, вне обычных ролей)
6. Формализация onboarding/support/feedback в runbooks
7. User-facing FAQ (организатор + игрок)
8. Успех → Phase 7 (монетизация, Трек A готов)
9. Вся фаза за раз

### Что НЕ делаем в Phase 10

- ❌ Открытая регистрация (allowlist — контролируемый рост)
- ❌ Полноценная аналитика использования (для 2-5 орг живой связи достаточно)
- ❌ Реклама/маркетинг/open call (рано, фильтр на случайных)
- ❌ Платная монетизация (Phase 7 после гейта)
- ❌ Полноценная админ-панель (только лёгкий обзор; полная — позже)
- ❌ Многоязычность, расширенные интеграции — после product-market fit

### Что даёт пройденный Трек B

- Продукт уже работает на реальной группе → бета не про «работает ли вообще», а про переносимость и готовность платить
- Известные UX-проблемы уже всплыли → бета ловит то, что специфично для ДРУГИХ организаторов
- Onboarding-процесс можно формализовать на основе реального опыта
