# Phase 27: Укрепление по аудиту 2026-11-10

**Цель.** Закрыть замечания аудита проекта 2026-11-10: безопасность по слоям, права ролей, эксплуатация, персональные данные, качество интерфейса и продуктовые пробелы — до приглашения внешних организаторов.

## Контекст

Источник — [аудит 2026-11-10](../operations/reviews/2026-11-10-project-audit.md); каждая карточка ссылается на замечание полем `review_ref` и несёт `priority` по шкале аудита (не P0–P2 из DEVELOPMENT_PROCESS): P1 — до внешних организаторов, P2 — ближайшие релизы, P3 — по возможности.

Номер фазы — ID, а не порядок ([RELEASES](../RELEASES.md)): фазы 22–26 не перенумерованы. Карточки фазы не входят в релизы, пока владелец их не назначит; назначены 27.2.1–27.2.3 (`v0.3.1`), остальные с пустым `release`.

Объединены замечания-дубли: PROD-11 → PD-01 ([27.6.1](../tasks/27-6-1-legal-docs-consent.md)), PROD-17 → UI-04 ([27.8.4](../tasks/27-8-4-device-matrix.md)), PROD-02 и PROD-15 → [27.9.2](../tasks/27-9-2-vision-update.md). Пересечения с открытыми карточками не дублируются: [27.5.1](../tasks/27-5-1-phase-9-ops-debt.md) доводит до `done` 9.5.1, 9.6.1, 9.6.2, 9.7.1, 9.7.2; [27.10.2](../tasks/27-10-2-organizer-first-run.md) и [27.10.3](../tasks/27-10-3-feedback-support.md) предлагают поглотить 10.5.1, 10.2.1, 10.2.2 (AQ-16; `superseded_by` ставится после решения); [27.9.7](../tasks/27-9-7-status-docs-rule.md) продолжает 21.5.5.

> **Публичный репозиторий.** Решение владельца AQ-1 (2026-11-10): проект в разработке и используется только для тестирования, поэтому аудит и карточки фазы публикуются в `main` до исправлений. Перед приглашением внешних пользователей задачи P1 эпиков 27.1–27.4 и 27.7 должны быть закрыты.

## Definition of Done

1. Все задачи P1 `done` или явно отложены решением владельца.
2. Решения AQ-2…AQ-20 записаны в [журнал решений](../operations/decisions/2026-10-12-reference-v3-decisions.md).
3. Повторный аудит безопасности (P1 эпиков 27.1–27.4, 27.7) без открытых замечаний.
