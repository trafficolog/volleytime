# Task 3.11.3 — MVP-авторизация по очищенному референсу v2

Дата: 2026-09-24. Основание: [карта референсов](../../design/2026-09-23-reference-v2.md), [SDD-карточка](../../tasks/3-11-3-auth-reference-v2.md), решения пользователя от 2026-09-24.

## Цель и границы

Показать реальные состояния входа из `6 Авторизация.html` в существующем Nuxt MVP без изменения способа подтверждения личности. Веб-вход использует только email OTP. Telegram-кнопка ведёт к действующему боту, где уже есть рабочая кнопка открытия Mini App; она не утверждает, что авторизует веб-сайт. Mini App по-прежнему создаёт сессию только после серверной проверки подписанного `initData`. Визуальный JSX — референс, не источник аккаунтов, организаций, сроков, кодов ошибок или прав.

Выбран вариант расширить текущие страницы и их представление состояний поверх действующих API. Отдельный Telegram Login для сайта потребовал бы нового протокола аутентификации; имитация семи экранов на моках не дала бы рабочего MVP. Оба варианта исключены из задачи.

## Источники данных и переходы Web

Точка входа — `/auth/login`. Email OTP остаётся на существующих better-auth endpoint; срок кода в интерфейсе — фактические 5 минут. Безопасный локальный `redirect` на `/m/...` сохраняет текущий сценарий игроков и приглашений. Для входа без такого redirect после успешной проверки кода запрашивается `/api/organizations` и определяется состояние кабинета организатора. Никакой клиентский выбор роли не заменяет серверные проверки API.

| Состояние референса  | Реальный триггер и действие                                                                                                                                                              |
| -------------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Старт / способ входа | Email-форма; отдельная ссылка «Открыть бота в Telegram» строится из `runtimeConfig.public.telegramBotUsername` и скрыта, если username не задан. Бот предлагает рабочую кнопку Mini App. |
| Ввод кода            | Успешная отправка OTP; один настоящий input на 6 цифр, доступный клавиатуре и автозаполнению.                                                                                            |
| Ошибка кода          | Отказ endpoint проверки (неверный либо просроченный код); без выдуманного числа оставшихся попыток. Можно исправить код, повторно отправить после таймера или сменить email.             |
| Проверка входа       | Во время проверки OTP, получения сессии и списка организаций; повторная отправка заблокирована.                                                                                          |
| Выбор организации    | Две или более организации владельца/организатора со статусом `active` или `suspended`; активные открываются, приостановленные ведут к объяснению ограничения.                            |
| Нет доступа          | После входа нет ни одной организации с ролью `owner`/`organizer`; игроку и помощнику не показывается desktop-кабинет. Действия: открыть бота с Mini App или сменить аккаунт.             |
| Доступ приостановлен | Доступная пользователю организация имеет серверный статус `suspended`; показываются её реальное имя и состояние, без фиктивных даты, тикета и ссылки поддержки.                          |

Если доступна ровно одна активная организация и других организаций организатора нет, она открывается сразу. Если единственная организация организатора приостановлена, сразу показывается состояние ограничения. До задачи 5.15.1 действующая цель — `/m/orgs/{id}`; задача 5.15.1 заменит цель на desktop-маршрут, не меняя критерии выбора и авторизации. Если API организаций недоступно, показывается ошибка с повтором запроса, а не состояние «нет доступа». URL Telegram берётся из конфигурации, не из устаревшего имени бота в JSX.

## Состояния Mini App

| Состояние         | Источник и рабочее действие                                                                                                                                                                                                                 |
| ----------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Splash            | `/m/` ждёт Telegram-auth и маршрутизацию; есть текстовый статус, доступный assistive technology.                                                                                                                                            |
| Ошибка `initData` | Сервер отвергает подписанные данные или их не передал Telegram-host; повторная попытка запускает проверку заново. Обычный браузер без `initData` остаётся в email-сценарии.                                                                 |
| Нет групп         | `/m/orgs` получил пустой список для действующей сессии; доступны существующие действия приглашения и создания группы. Ошибка загрузки списка не маскируется под пустой список.                                                              |
| Доступ закрыт     | Прямой переход к группе получает серверный отказ в доступе; текст не раскрывает недоступные данные группы, действие ведёт к списку доступных групп. `suspended` показывается отдельно по фактическому статусу, если данные группы доступны. |

Заблокированное членство сейчас исключается из `/api/organizations`, поэтому UI не должен выводить имя такой группы из старого client state. Ошибка сети/сервера, 401 и 403 различаются; обобщённое «доступ закрыт» допустимо только для подтверждённого отказа.

## Компоненты и визуальное соответствие

Использовать существующие Bento Bold токены и атомы из задач 3.11.1–3.11.2, без нового UI-kit. Общие элементы: бренд, заголовок, пояснение, форма, status/banner, список организаций, пустое/error/loading-состояние. Не копировать JSX и не дробить ввод OTP на шесть недоступных полей: один input сохраняет `autocomplete=one-time-code`, а декоративная разбивка допустима только при сохранении его семантики. На мобильном и desktop адаптируется ширина и вертикальные отступы; кнопки не теряют 44 px hit area. Ошибки объявляются через `role=alert`, ход процесса — через `role=status`; фокус видим и возвращается к релевантному контролу после смены шага.

## Проверки и критерии

TDD: сначала тесты чистого определения web-состояния на наборах организаций и отказах API, переходов OTP, а также разграничения Telegram-host и обычного браузера; затем UI и минимальная интеграция. Наборы включают неверный/просроченный код, одну и несколько активных организаций, смешанный active/suspended, только player/assistant, 403 на группу, ошибку сети и пустой список. Проверить защиту локального redirect и сохранение серверной валидации `initData`. Затем браузерный smoke клавиатуры, ошибок и responsive на локальном окружении, пять обязательных gates и GitHub CI. Реальную Telegram QA и пилотную группу не объявлять выполненными по локальным тестам — это 8.10.3.
