Выбор группы в шапке главной открывает `VtSheet` со списком из `/api/organizations`: активные группы доступны для перехода, pending и suspended видны с причиной/статусом и ведут только на существующий информационный экран. Выбор вызывает `selectOrg(id)` и переход в `/m/orgs/{id}`; вступление по ссылке ведёт к существующему экрану `/m/orgs`. Запоздавшие ответы старой группы не могут заменить данные новой: route-keyed fetch, очистка зависимого отображения и проверка `organization.id === route.orgId`. Ошибка загрузки группы или разрешения не открывает запись/покупку.

## Навигация и структура

Для игрока плавающая панель следует MVP, а не неизданной вкладке «Сборы» из JSX: «Главная», «Записи», условные «Абонементы», «Профиль». Список всех событий доступен заметным действием с главной; прямые маршруты и event deeplink сохраняются. При отключённых абонементах пункт остаётся только с действующим остатком по правилу 5.13.21; без него панель содержит три пункта. Организаторский tab bar не меняется в этой задаче (8.10.2).

Использовать действующие Bento Bold токены 3.11.1 и компоненты 3.11.2. На мобильном: 16 px поля, 12 px между соседними карточками, не менее 24 px между секциями, один главный hero на экран; содержимое и действия учитывают safe-area и плавающий tab bar. Карточки различать тоном и пространством, структурные разделители оставлять лишь где они помогают чтению. Не добавлять другой UI-kit или параллельную тему.

## Состояния и ошибки

- На каждом маршруте различать loading, empty, HTTP/auth error и success; ошибка отображается `ErrorState` с повтором, не пустым экраном. `pending_payment`, `confirmed`, `waitlisted`, `cancelled`, `attended/no_show` показывать словами, а не только цветом.
- Запись, отказ сервера в записи, отмена и покупка сохраняют существующие серверные проверки и сообщения. При неуспешной мутации оставлять исходное состояние и явно показывать ошибку; после успеха обновлять detail/dashboard/баланс.
- `subscriptionsEnabled` и остаток считывать только из выбранной организации. В неопределённом состоянии не показывать покупку или способ `subscription`. Выключение не скрывает уже купленное и не изменяет историю.
- Профиль без имени/почты показывает только доступные поля; не создавать фиктивные персональные данные. При потере сессии действует существующий auth redirect; при закрытом доступе к группе — существующие denied/suspended состояния.

## Доступность и проверка

Навигация — ссылки, мутации — кнопки; icon-only controls получают имя, `VtSheet` возвращает фокус, ошибки доступны через `role=alert` или связанный текст. Touch-цели — не менее 44×44 px; видимый `focus-visible`, читаемый статус и 200% zoom обязательны. Движение не должно быть единственным сигналом и учитывает `prefers-reduced-motion`.

TDD покрывает проекции hero/расписания и booking status, переходы и выбор оплаты, waitlist, отмену, профиль без необеспеченных API, выбор группы и смену доступности абонементов; проверка API и UI должна обнаруживать старые ответы другой группы. Затем обязательные `format:check`, `lint`, `typecheck`, `test`, `build`; браузерный smoke на 320/390 CSS px в светлой и Telegram-тёмной теме, клавиатура и 200% zoom. Реальный Telegram-host QA и сквозная сверка всех MVP-экранов остаются отдельным gate задачи 8.10.3; локальные тесты их не подтверждают.

## Решение о реализации

Меняем существующие страницы и небольшие чистые функции проекции UI-состояний, не вводя второй источник данных или общий новый shell. Такой путь сохраняет поведение продового MVP и позволяет проверять каждый экран и переход отдельно. Полная замена Mini App дала бы визуальную скорость ценой повторной реализации auth/доменной логики; одна CSS-обновка не закрыла бы новую структуру v2.
