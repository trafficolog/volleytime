# MVP Auth v2 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Bring the existing web OTP and Mini App entry flows to the eleven real MVP states in the cleaned Bento Bold auth reference without weakening identity or access checks.

**Architecture:** Keep better-auth email OTP and signed Telegram `initData` endpoints unchanged. Put deterministic organization/redirect decisions in a small pure UI policy module; let existing Nuxt pages render those decisions using live `/api/organizations` and tenant responses. The future desktop route is a separate task; this plan targets the existing group route.

**Tech Stack:** Nuxt 4, Vue 3, TypeScript, Vitest, Tailwind/CSS Bento Bold tokens, better-auth, PostgreSQL-backed organization API.

**Spec:** `docs/superpowers/specs/2026-09-24-auth-mvp-v2-design.md`; SDD card `docs/tasks/3-11-3-auth-reference-v2.md`.

## Global Constraints

- Web sign-in remains email OTP only; code lifetime is **5 minutes** in `packages/auth/src/config.ts`.
- Telegram link opens the configured bot, which offers its existing Mini App button; it does not sign the user into the website.
- Mini App session creation remains server-side validation of signed `initData`; never trust `initDataUnsafe` for identity.
- Use existing Bento Bold tokens/components; no new UI kit, fake organizations, tickets, support links, password sign-in, Root Admin, credits or future phases.
- Preserve valid local redirect for player/invite routes; eligible organizer destination remains `/m/orgs/{id}` until task 5.15.1.
- Do not infer Telegram QA or real-group validation from local tests; those remain in task 8.10.3.

## Review Focus

1. Malicious `redirect` (`//evil`, `/%2f/evil`, backslash and non-Mini-App routes) must never leave the site or bypass organization choice: pin with Task 1 tests.
2. Pending owner/organizer membership must not grant organizer access: pin with Task 1 tests.
3. Organization-list network failure must not render the same screen as an authorized user with no organizer role: pin with Task 2 tests.
4. A stale last-organization ID or blocked membership must not reveal group name or content: pin with Task 4 tests.
5. Duplicate OTP submit/resend and network failure after OTP success must not create contradictory state or a second sign-in: pin with Task 2 tests.

```ts
export function safeAuthRedirect(value: unknown): string | null {
  if (typeof value !== 'string' || !value.startsWith('/m/')) return null
  try {
    const decoded = decodeURIComponent(value)
    if (!decoded.startsWith('/m/') || decoded.includes('\\') || decoded.includes('//')) return null
    return value
  } catch {
    return null
  }
}
```
